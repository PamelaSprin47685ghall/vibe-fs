# abbreviation-anxiety — Main 中文版

## 现在该做什么
把私有缩写替换为领域本来就使用的完整词。不要做“全仓库禁止缩写”的命名运动；只消除那些要求读者额外解码、且不属于公开 vocabulary 的 token。

## 为什么这很重要
命名是检索接口，也是讨论接口。私有缩写会让 grep 漏掉同义概念、让 review 多一次脑内翻译、让新人建立一份仓库专属词典。字符少了，认知总成本反而上升。

## 常见假修复
- 建一份缩写表；这只是正式承认第二套语言。
- 把所有 `URL/HTTP/SQL` 强行展开，制造反常命名。
- 名字变长却仍然错误；准确比长度重要。
- 用 IDE hover 作为长期解码机制。

## 验证
搜索同一 domain concept 的命名。应能使用公开领域词稳定命中，而不是记住多套局部 token。

## 完成条件
名字被读到时就能进入领域推理，不需要先完成一次私有码表翻译。
