把一个已经完成抽象的判断钉成当前工作假设，然后继续执行。

先抽象，再调用 `assume`。先在思考中分清本质结构：哪些部分独立、哪些有真实依赖、哪些是领域判断、哪些只是机械执行。等你已经形成一个要据以行动的结论，再把它写进 `assumption`。它可以短到一句话。

`assume` 不是求证，不替你做领域判断，也不让一个猜测自动变真。它做的是承诺：你已经用当前信息完成抽象，现在停止无信息增量的反复改判，沿这个判断执行并验证。

调用之后，没有新证据就不要重新讨论同一个选择。你在抽象时掌握的信息不会因为犹豫而增加；犹豫不产生新知识，只产生新分支、新错误和更少的时间。抽象后立刻无依据地动摇，等于否定自己的抽象，却没有任何新增事实支撑这种否定。

经验丰富的参与者把第一份经过充分抽象的决策当作默认执行对象；第二念只有携带新事实才有资格推翻它。否则你进入的不是“更谨慎”，而是多米诺链：抽象 → 犹豫 → 改答案 → 再犹豫 → 再改 → 更错 → 更慌 → 更错。它的终点通常不是更好的答案，而是更差的答案和更少的时间。

只有执行结果、验证结果或外部输入带来足以改变原有结构的新信息，才重开判断并修正假设。不要为了安抚不确定感而重复调用 `assume`。

成功返回建立的不是“假设已被证明”，而是“当前假设已被显式提交”。下一步是执行，然后验证：抽象 → 笃定 → 执行 → 验证。
