deliver(reportMapping) — end this program by handing over a report mapping. The program does not continue past the call: the delivery unwinds the stack, records the mapping into the session's delivery cell, and the handoff the caller receives is rendered from it. The host reads the mapping as `{ prefixUntil: 0, thenMap: reportMapping }`: a summary replaces that anchor, `null` keeps it as written, and an unlisted anchor is not passed to the caller. Handing over a `{ prefixUntil, thenMap }` wrapper yourself is revoked: it is refused with `VIEW_DECLARATION_INVALID`. Subagent programs must deliver explicitly; a plain `return` leaves the delivery cell empty and writes no completion — while that child can still deliver it stays a live obligation and the join stays open; once delivery becomes impossible (aborted, cancelled, or settled at restart load) the child is voided, which is not a completion: the join reports it once as `voided`. In `dag`, a non-completed record parks as `node-<status>` (`node-failed`, `node-abandoned`, `node-voided`).

Before the call, write the work's prose in the assistant text: what was done, the evidence, what remains open, and what a successor needs. The report mapping must point at all the material this work owes the caller — including that prose and the context it rests on. Do not copy the prose into the deliver argument and do not leave it for after the call: there is no after. `deliver(undefined)` is not a delivery: a missing reportMapping, or one of an illegal shape, is refused — the call returns `{ ok: false, code: "VIEW_DECLARATION_INVALID", reason }`, that refusal is not a delivery, and the program keeps running; an empty mapping `{}` is legal and passes nothing.

Catching the internal delivery sentinel keeps the program alive — the later return value then wins — so a holder that catches it is knowingly cancelling the delivery.
The report mapping has type `Record<string, null|string>`.
