deliver(reportMapping) — end this program by handing over a report mapping. The program does not continue past the call: the delivery unwinds the stack, records the mapping into the session's delivery cell, and the handoff the caller receives is rendered from it. The host reads the mapping as `{ prefixUntil: 0, thenMap: reportMapping }`: a `Record<string, null|string>` that maps an anchor number to a summary string or `null` (keep). Handing over a `{ prefixUntil, thenMap }` wrapper yourself is revoked: it is refused with `VIEW_DECLARATION_INVALID`. Subagent programs must deliver explicitly; a plain `return` leaves the delivery cell empty and settles the child as `undelivered` (`node-undelivered` in `dag`).

Before the call, write the work's prose in the assistant text: what was done, the evidence, what remains open, and what a successor needs. The report mapping must point at all the material this work owes the caller — including that prose and the context it rests on. Do not copy the prose into the deliver argument and do not leave it for after the call: there is no after. `deliver(undefined)` is not a delivery: a missing reportMapping, or one of an illegal shape, is refused — the call returns `{ ok: false, code: "VIEW_DECLARATION_INVALID", reason }`, that refusal is not a delivery, and the program keeps running; an empty mapping `{}` is legal and applies no replacement projection.

Catching the internal delivery sentinel keeps the program alive — the later return value then wins — so a holder that catches it is knowingly cancelling the delivery.
