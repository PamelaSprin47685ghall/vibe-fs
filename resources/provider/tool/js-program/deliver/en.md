deliver(reportMapping) — end this program by handing over a report mapping. The program does not continue past the call: the delivery unwinds the stack, records the mapping into the session's delivery cell, and the handoff the caller receives is rendered from it. The host reads the mapping as `{ prefixUntil: 0, thenMap: reportMapping }`: a `Record<string, null|string>` that maps an anchor number to a summary string or `null` (keep). A `{ prefixUntil, thenMap }` wrapper is not accepted here. Subagent programs must deliver explicitly; a plain `return` leaves the delivery cell empty and settles the child as `undelivered` (`node-undelivered` in `dag`).

Before the call, write the work's prose in the assistant text: what was done, the evidence, what remains open, and what a successor needs. The report mapping must point at all the material this work owes the caller — including that prose and the context it rests on. Do not copy the prose into the deliver argument and do not leave it for after the call: there is no after. `deliver(undefined)` is not a delivery and fails as `INVALID_RETURN_VALUE`; a report mapping that selects no material renders no handoff.

Catching the internal delivery sentinel keeps the program alive — the later return value then wins — so a holder that catches it is knowingly cancelling the delivery.
