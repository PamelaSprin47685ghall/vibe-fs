# Tool · review

Submit this incumbency's stage review, deciding the gap to promotion to the next milestone (so the next stage can begin, or delivery authority is granted). Shares the tool name and the three-question semantics with the Manager's review; the Plan backend's review target is derived from the current stage: `S1` targets being ready for promotion to `S2` (`S1`'s formalized target, facts, root causes, and trade-offs account is complete so `S2` can start — never requiring `S2` paths to be written already), `S2` targets being ready for promotion to `S3` (`S2`'s understanding, candidate path comparison, main path, and counterfactual checks are complete so `S3` can start — never requiring `S3` pseudocode to be written already), `S3` targets becoming the last runner (`S3`'s pseudocode and decision points are complete, granting delivery authority).

## Contract and Usage

1. **Three Questions**: formalize the target state; state the current gap to it; decide whether the gap set is empty.
2. **findings Pairs**: `findings` is an array of `acceptance_criteria` and `work_plan` pairs. Each non-empty gap yields one acceptance criterion (the formalized target state) and one work plan (how to close the gap). An empty array means the gap set is empty.
3. **Consequences**: an empty set promotes — `S1` to `S2`, `S2` to `S3` (the tool result immediately includes the next stage's method requirements so this incumbency begins writing the new stage right away), and `S3` grants delivery authority (this incumbency calls `deliver` directly to permanently disable nudges, enter the `post-S3` state, and interrupt the conversation to wait for the user). A non-empty set keeps the incumbency in place; the gaps return as repair obligations for the current stage, to be followed by `deliver` to relay once repaired.
4. **Once Per Incumbency**: after this incumbency has been reviewed, further calls are rejected with a typed error. Repair quality is reviewed independently by the next runner; you do not self-certify.
5. **Object of Review**: the gap between the current stage and the entry bar for the next stage (or at `S3`, readiness for execution delivery), not whether the next stage itself is already finished and not a self-assessed completion score. The first runner and every successor face the same standard.
