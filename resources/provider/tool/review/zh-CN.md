# 工具 · review

提交本任的阶段评审，判定离晋级下一里程碑（下一阶段能开始，或获得交付授权）的差距。与 Manager 的 review 共用同一工具名与三问语义；Plan 后端的评审目标由当前阶段推出：`S1` 的目标是能晋级 `S2`（`S1` 的目标形式化、事实、根因与取舍底账已完备，`S2` 能开始，不要求已写出 `S2` 的路径），`S2` 的目标是能晋级 `S3`（`S2` 的理解、候选路径对比、主路径与反事实检验已完备，`S3` 能开始，不要求已写出 `S3` 的伪代码），`S3` 的目标是成为最后一任（`S3` 的伪代码与裁决点已完备，获得交付授权）。

## 契约与使用

1. **三问**：先形式化目标状态；指出当前与目标的差距；判断差距是否为空集。
2. **findings 对**：`findings` 是 `acceptance_criteria` 与 `work_plan` 组成的对数组。每个非空差距对应一条验收标准（目标状态的形式化）与一条工作计划（弥合差距的做法）。空数组表示差距为空集。
3. **后果**：空集晋级——`S1` 晋级 `S2`、`S2` 晋级 `S3`（工具返回值当场附带下一阶段的方法要求，本任立即开始新阶段写作），`S3` 获得交付授权（本任直接调用 `deliver` 进入 `post-S3` 态并中断对话等待用户；旧运行退休后不再被催促，继续规划的新输入重开新任期并照常受 nudge）。非空留任：差距作为修复义务返回，本任留在原阶段补齐差距，补完后调用 `deliver` 接力。
4. **每任一次**：本任已评后再次调用被强类型拒绝。修复质量由下一任独立评审，不由你自证。
5. **评审对象**：是当前阶段离下一阶段准入（或在 `S3` 离可交付执行）的差距，不是下一阶段本身是否已完成，也不是完成度自评。第一任与后任同一标准。
