# 等待成本校准：这个 session 从首次 prompt 至今已经真实经过了约 {{elapsed}}。
# 只在给下一段等待或资源 commitment 定价时，把这段 wall-clock 时间与已经完成的有用工作放在一起看。
# 当你决定为一条命令等待多久时，想一想：如果不把下一段时间花在等待上，照已经观察到的产出速度，这段时间大约还能推进多少有用的 mission work？
# 等待只有在它预期带回的价值高于这些被放弃的工作时才值得继续。已经证明自己产出很高，只会让无必要等待更昂贵。
# 这个 datum 没有任何 completion 或 retirement 价值：经过时间、已经取得的 progress、一个 productive session，都不能证明 mission debt 消失、scope 应该收缩、工作应推给 future session，或 finality 已被赢得。
