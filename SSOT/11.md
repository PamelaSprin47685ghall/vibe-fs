# SSOT/11 — Journal 与持久化合同

条款 ID 前缀：`PERSIST-`

## PERSIST-001：Envelope 结构

每个 journal envelope 必须包含：schema version、event ID、stream ID。

## PERSIST-002：Append 原子性

Append 只有两种结果：Committed 或 CommitUnknown。没有"部分写入"。

## PERSIST-003：CommitUnknown

CommitUnknown 后 runtime 进入 fail-closed reconcile，需要显式恢复。

## PERSIST-004：尾部损坏

尾部截断只允许恢复最后一条不完整 envelope。中间损坏直接拒绝启动。

## PERSIST-005：旧 Schema

Pre-0.5.0 journal 不猜测迁移。启动发现旧 schema 时直接失败。

## PERSIST-006：文件权限

Runtime directory：0700。Journal 文件：0600。

## PERSIST-007：Blob 存储

大内容（超过阈值）存为 blob，NDJSON 只保存 digest/reference。Blob 先写入后 append event。

## PERSIST-008：Projection 查询

Projection 查询不得扫描完整历史。必须使用 O(1) 积分状态。

## PERSIST-009：Durable Effect 协议

对于 worktree 创建、Session 创建、Prompt 发送、Git publish 等外部副作用：

```text
DurableEffectRequested
-> 执行幂等副作用
-> DurableEffectAccepted
```

崩溃后：已 Requested 但未 Accepted 的效果视为未发生，可重试。已 Accepted 的效果确保已物理完成。

Prompt 发送的副作用不走本条通用协议，以 PROMPT-011 为专门恢复合同（at-most-one effect，不自动重发）。

## PERSIST-010：上下文恢复事实的 fold 规则

SSOT/12 引入五个持久事实。Fold 必须按下列规则验证，不满足任一条则拒绝该 envelope，fail closed。

```text
OpeningPromptCaptured
  对每个 lifecycle identity 幂等、不可覆盖
  text = 被 Host 接受的第一条任务 prompt 原文（不 Trim、不重排、不摘要、不 TOML round-trip）

XTracePartAppended
  严格顺序、append-only；BlobRef 存正文，journal line 存 digest/cursor/provenance
  Cursor 单调递增；同 cursor 重复 append 拒绝

BlogEntryCommitted
  PreviousIngestCursor = 当前 IngestCursor
  NextIngestCursor > PreviousIngestCursor
  NextCoverableTurnCutoffExclusive ≥ PreviousCoverableTurnCutoffExclusive
  TextDigest = digest(blob content)
  attempt outcome = Completed 且 terminal valid

TerminalOutputCaptured
  对每个 lifecycle identity 幂等、不可覆盖
  text = 已 reconcile 的 terminal 输出原文

BlogSquashCommitted
  PreviousFrameEpochId = 当前 FrameEpochId
  NextFrameEpochId = PreviousFrameEpochId + 1
  1 ≤ CoveredFrameCount ≤ 当前 frame count
  TextDigest = digest(blob content)
  attempt outcome = Completed 且 terminal valid

PrefixRebaseCommitted
  PreviousEpochId = 当前 EpochId
  NextEpochId = PreviousEpochId + 1
  attempt profile 中存在完全相同的 PrefixProbe（按 ProbeId 验证候选一致性）
  attempt outcome = Completed 且 terminal valid
  candidate cutoff digest 重新验证通过

ContextReanchored
  PreviousEpochId = 当前 EpochId
  NextEpochId = PreviousEpochId + 1
  同一 ObservedCompactionMessageId 只接受一次（幂等）
  提交后 Snapshot → None，coverage 三元组归零，Frames 全部保留
```

`ContextReanchored` 是 HOST-006 收容层的持久事实：观察到 Host compaction pseudo-run 后，退役 `ActivePrefixEpoch` 并归零 Companion coverage。

它必须是一个事实而非两次独立写入，因为两处投影必须原子改变：只退役 epoch 不归零 coverage，会留下一个声称覆盖了不存在编号的 B。

```fsharp
type ContextReanchored =
    { SessionId: SessionId
      PreviousEpochId: int64
      NextEpochId: int64
      /// 哪条消息证明它发生了。这是物理世界的事实，
      /// 不是「它为什么发生」——后者是 CTX-005 禁止的分类。
      ObservedCompactionMessageId: ProviderRunIdentity }
```

单一写入口是观察 compaction 的那一个 reconcile 路径。该事实不携带来源、原因或分类字段：用户手动 `/compact` 与 Host 意外触发走完全相同的处置。

`BlogEntryCommitted` 是 frame append 与 coverage 推进的同一个原子提交。禁止出现「entry 已进入 Frames 但 coverage 未推进」或其反面。

`BlogSquashCommitted` 只改变 B 的表示，不改变 B 覆盖的 X 范围：`IngestCursor`、`CoverableTurnCutoff`、`CoveredPrefixDigest` 与 `RecordCoverage.IngestedThrough` 均不变（COMPANION-006）。

失败的 X prefix probe 不产生任何事实（CTX-010）。不得引入 `PrefixProbeRolledBack`、`PrefixProbeCleared`、`PrefixProbeRejected`、`RestoreOldEpoch` 这类回滚事实——未提交的候选从未成为领域事实，没有可回滚的对象。

同理不得引入 `OverflowDetected`、`ContextNearLimit`、`SquashReason`、`CompressionThresholdReached`：失败不分类（CTX-005），容量不观察（CTX-001）。

正文均走 PERSIST-007 blob（OpeningPrompt、XTrace part、BlogEntry、BlogSquash、FrozenRecordPrefix snapshot、过大的 prompt projection descriptor），NDJSON 只保存 digest/reference。

Projection 按 PERSIST-008 以 O(1) 积分状态回答「当前 PrefixEpoch」「当前 FrameEpoch」「Y 有效 Frames」「RecordCoverage」「XTrace」「Opening/Terminal anchor」。Y 的有效 Frames 只由 Journal fold 派生，不读取物理 Y transcript 作为历史来源——那里可能残留已被 squash 覆盖的 entry、崩溃窗口的孤儿 response、delta 消息、squash instruction 与 repair continuation。

崩溃后上下文恢复事实按同一模式幂等补提交：从 PromptClaim 取 `ProviderRunIdentity`，reconcile 出完整 snapshot，验证 outcome 与正文有效性，再提交。无法证明 response 属于该 request 时不提交。journal append 返回 CommitUnknown 时 runtime fail closed（PERSIST-003），不得重新请求模型来「保证写入」。

Prompt 发送的副作用不走 PERSIST-009 通用协议，以 PROMPT-011 为专门恢复合同（at-most-one effect，不自动重发）。X main、Y main、Y squash 三类请求全部必须经统一 PromptDispatcher（PROMPT-005）。
