# SSOT/03 — Prompt Authority 与 Dispatcher

条款 ID 前缀：`PROMPT-`

## PROMPT-001：顶层不变量

```text
PhysicalUserMessage ≠ AuthorityTurn
```

Host `role=user` 只是运输格式。零宽字符、空白、固定模板、时间与文本长度都不是身份证据。

## PROMPT-002：只有 Authority Root 可以

1. 创建新的 Logical Run
2. 选择或改变 SelectedAgent（并由此确定 PeerAgent/CanonicalRole/SelectedTier）
3. 成为新的 Fallback root
4. 重置 Interaction Repair 预算
5. 成为后续缺省 SelectedAgent 的延续来源

Companion 关联是 Session 结构事实，Authority Root 无权改变（COMPANION-002）。

Authority Root 禁止选择或覆盖 model ID。发送 Prompt 时始终 `Model = None`。

## PROMPT-003：Continuation 不得执行以上操作

以下都是 Continuation：`InteractionRepair`、`ManagerGuard`、`ReviewerGuard`、`ReviewConfirmation`、`BusyAgentNudge`、`ProviderRetryAttempt`。

Continuation 只延续已有 Logical Run：不建新 RunId/completion；不改 SelectedAgent/PeerAgent/CanonicalRole/SelectedTier；不更新 LastAuthorityProfile；不重置 Fallback/repair。物理请求使用当前 fallback cursor 对应的 EffectiveAgent。

## PROMPT-004：来源类型

```fsharp
type PromptOrigin =
    | AuthorityRoot of RootAuthorityKind
    | Continuation of ContinuationKind
    | HostInternal
    | UnknownOrigin

type RootAuthorityKind = HumanRoot | AgentOwnerRoot
```

HumanRoot：必须显式 `fast-*` 或 `deep-*`。省略 → fail-closed。
AgentOwnerRoot：Manager fork(new)/Idle 新任务、经授权的 one-shot Agent。必须显式准确 Agent。
UnknownOrigin：fail-closed。不更新 profile、不启动 Fallback、不发 continuation。

## PROMPT-005：PromptDispatcher 四阶段协议

所有插件产生的 user-shaped message（包括 Guard、repair、ReviewConfirmation、busy nudge、provider failure continuation、Orchestrator 冲突提示）必须经过同一个 Dispatcher。

```text
Claimed
→ Submitted
→ PhysicalAccepted

Claimed
→ Abandoned            （发送前/发送中确定失败）

Claimed → Submitted
→ Abandoned            （已提交但恢复期无法证明物理落地，见 PROMPT-011）
```

恰好四个持久事实。`Abandoned` 携带 reason，不引入第五个事实名：

```fsharp
type PromptAbandonReason =
    | SendFailed of error: string
    | UnresolvedAfterRecovery      // PROMPT-011 恢复边界耗尽
```

Claimed：发送前持久化，确定 PromptKey、Origin、LogicalRunId、AuthorityRoot、EffectiveAgent、payload digest。

Submitted：Host 调用已成功返回，但返回值可能只是 `accepted-*` transport receipt。`accepted-*` 不是物理 MessageId，不是 Authority Root，不能进入 continuation 集合，不能用于 Review 确认。

PhysicalAccepted：只能由真实 `chat.message` 或 Host 明确返回的真实 `msg_*` 身份产生。只有此时 Authority Root 才正式生效。

Abandoned：终局失败。不得改变 Active Logical Run。`Abandoned` 之后同一 PromptKey 不再重发。

禁止：模块绕过 Dispatcher 直接 `prompt_async`。`accepted-*` 升级为 `PhysicalAccepted`。从 `Submitted` 直接推断 Authority 生效。

## PROMPT-006：发送格式

每次发送：

```fsharp
{ Agent = Some effectiveAgent
  Model = None
  Directory = directory
  Metadata = metadata }
```

禁止设置 `Model`。Host 按 `config.agent[effectiveAgent].model` 解析。

## PROMPT-007：Fire-and-forget 的定义

Fire-and-forget 只表示调用方不等待 PhysicalAccepted 结果。不得绕过 claim、authority、持久化、幂等和错误记录。

删除独立 `postPromptFireAndForget(sessionId, prompt)`。改为：

```fsharp
dispatcher.Dispatch(request, AwaitMode.Detached)
```

## PROMPT-008：原子 AttemptExecutionProfile

一次 provider request 的以下内容必须全部来自同一个不可变 profile：

```fsharp
type AttemptExecutionProfile =
    { SessionId
      LogicalRunId
      AuthorityRootUserMessageId
      PhysicalUserMessageId
      ProviderRunIdentity
      Origin
      SelectedAgent
      PeerAgent
      EffectiveAgent
      CanonicalRole
      SelectedTier
      SystemPromptId
      ToolCapabilitySet
      RequestKind: ProviderRequestKind
      ProjectionChoice: XProjectionChoice option }
```

`RequestKind` 是真实物理请求语义，不是流程 Stage：

```fsharp
type ProviderRequestKind =
    | WorkMain
    | BloggerMain
    | BloggerSquash
    | InteractionRepair
```

`ProjectionChoice` 为 `Some` 时表示本次 attempt 使用候选前缀 probe（CTX-010）。它只对该 attempt 有效，不构成领域事实。

包括：Host Agent、CanonicalRole、system prompt、provider-visible tools、runtime execution gate、fallback identity、diagnostics。

禁止：分别从 mutable session cache、最后一条 user message、Role map 和 fallback projection 中临时拼装。也禁止从本 profile 派生任何 Companion 资格判断——Companion 由 Session 种类决定（COMPANION-002）。

## PROMPT-009：来源解析优先级

```text
accepted HostMessageId
→ claimed PromptKey
→ Host compaction/synthetic
→ registered AgentOwnerRoot
→ proven external prompt acceptance (HumanRoot)
→ UnknownOrigin
```

## PROMPT-010：禁止自激励

禁止：零宽 continuation → HumanRoot；repair continuation → 新 repair 预算；Review confirmation → 改 Reviewer SelectedAgent；synthetic → 重置 Offset；B retry → 下一真人 root 默认 Agent；向 Host Prompt 覆盖 Model。

## PROMPT-011：未决发送恢复

Host 已接受 prompt，但插件在写 `Submitted` 或 `PhysicalAccepted` 前崩溃时的恢复协议。

### PromptKey 定义

```fsharp
PromptKey = digest(
    SessionId, LogicalRunId, AuthorityRootUserMessageId,
    Origin, EffectiveAgent, PayloadDigest, ClaimSequence)
```

`ClaimSequence` 是同一 `(SessionId, LogicalRunId, Origin, PayloadDigest)` 下的单调序号，从 journal fold 派生。它存在的唯一原因是让"同一个 Guard 对同一棵 tree 连续发两次"成为两个不同的 key，而不是被当成重复。

PromptKey 必须写入 Host prompt metadata（PROMPT-006 的 `Metadata`）。这是 Host 侧唯一的幂等锚点。

### 恢复步骤

启动 Fold 后，对每个处于 `Claimed` 或 `Submitted` 的 PromptKey：

1. 从目标 Session 读取尾部 最近 50 条消息（`RecoveryTailWindow = 50`）。
2. 在其中查找 metadata 含同一 PromptKey 的 `role=user` 消息。
3. 找到 → 补写 `PhysicalAccepted`，携带该消息真实 `msg_*` ID。
4. 未找到但存在 `Submitted` 的 receipt → 保持 Pending，不自动重发。
5. 未找到且无 receipt（仅 `Claimed`）→ 保持 Pending，不自动重发。

### 恢复边界

```text
RecoveryAttemptBudget = 3    // 跨越 3 次插件启动
```

同一个未决 PromptKey 在第 3 次启动仍无法证明物理落地时，写：

```fsharp
Abandoned(UnresolvedAfterRecovery)
```

由上层明确失败。不得在任何一次恢复中重发。

### 为什么不重发

Host 可能已经物理接受但消息落在 tail window 之外，或 Host 已开始 provider run。重发会产生第二次逻辑效果。合同是：

```text
at-most-one logical effect + fail-closed unknown outcome
```

禁止：假装 exactly-once。用时间窗口代替 PromptKey 匹配。把 `accepted-*` receipt 当作物理落地证明。为了"清理挂起状态"而重发。
