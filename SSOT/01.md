# SSOT/01 — 第一原理

条款 ID 前缀：`ARCH-`

## ARCH-001：结构化程序替代状态机

语言运行时（F# Task、C# async、JavaScript Promise）已经提供了 continuation、局部变量、调用栈和 CancellationToken。在业务层再抄一套 Stage/Phase/Lease/Owner/Generation 等于重做编译器的工作。

必须：用 computation expression 直接写流程。

```fsharp
agent {
    let! inspector = fork "fast-inspector" "调查"
    let! coder = fork "fast-coder" "修复"
    let! first = joinAny ()
    do! react first
    let! review = reviewUntilConfirmedPerfect ()
    return review
}
```

禁止：CurrentStage、NextAction、JoinOwner、ReviewPhase、FallbackPhase、NudgeLease、CompactionGeneration、SquadWaveState。

判断标准：问自己——这个字段是物理世界真实存在的事物（进程、Session、Git tree、文件、模型输出），还是程序接下来去哪的信息？如果是后者，删除它。

## ARCH-002：事件是信号，不是数据

OpenCode 在流式传输中产生大量碎片事件。从碎片中拼装业务事实是 CPU 密集、不确定且随宿主版本改变的。

必须：碎片事件在最早边界丢弃。唯一允许进入业务层的信号：`session.status=idle/retry`、`session.deleted`。

```text
碎片事件（message.updated / part.delta / session.updated）
    ↓ 丢弃
粗粒度信号（idle / retry / deleted）
    ↓ single-flight
Reconciler 从 SDK 读取完整消息
    ↓
纯策略（completion / ReviewGuard / continuation / abort）
```

禁止：
- 在业务层处理 `message.updated`、`message.part.updated`、`part.delta`、`session.updated`、`session.diff`
- 从 idle 事件内容推断 terminal、完成或失败
- 依赖事件先后顺序或 payload 结构推导业务因果

## ARCH-003：不修改 OpenCode 本体

每次 fork 增加维护负担；上游可能拒绝 patch；用户升级 OpenCode 时丢失功能。

仅允许使用以下现有边界：
- `chat.message` — 确认新 turn 被接受
- `experimental.chat.messages.transform` — Companion 唯一输入
- `tool.definition` / `tool.execute.before` / `tool.execute.after` — 权限与结果
- `experimental.session.compacting` / `experimental.compaction.autocontinue` — 控制 compaction
- `event` — 接收 idle/retry/deleted 三信号
- SDK `client.session.*` / `prompt_async` / `session.messages`

禁止：
- 要求 Host 增加新 Hook
- 修改 OpenCode 本体
- 监听到期或实验性非公开 API

## ARCH-004：LLM 前缀缓存保护

KV-cache 延迟优化依赖字节精确前缀匹配。

必须：
- Y frames 增长与 `ActivePrefixEpoch.FrozenRecordPrefix` 严格分离。平常回合 frames 增长，X 前缀不变
- Epoch 只在三种事实提交时切换，每次切换产生一次可预期的冷边界：
  - 成功的 X prefix probe 被提升（CTX-012）
  - 有效的 Y BlogSquash 被提交（COMPANION-006）
  - 观察到 Host compaction 后的重锚（HOST-006）
- companion-b-head synthetic message 在两次 epoch 切换之间必须保持逐字节不变
- Provider-visible projection 只包含真正进入模型的字段（role/text/reasoning/tool call/result），排除 timestamp/cost/usage/runtimeId

三种触发的共同点：都由一个已经发生的事实驱动，不由插件对容量的测量或预测驱动。 前两种是插件自己提交的领域事实，第三种是 Host transcript 里出现的物理消息。重锚不是「上下文太长了所以换 epoch」，而是「旧 cutoff 索引已经不指向任何真实前缀，必须退役」。

禁止：
- 根据上下文长度、token 数、占比或模型元数据主动切换 Epoch（CTX-001、CTX-002）
- 每次 blogger 成功后修改 X 最早消息的正文
- 把 Y frames 直接放入 X 的 active prefix
- 重建 Blogger 后不发送 full reset frame 就使用旧 projection baseline
- 使用 Host runtimeId/timestamp 参与 canonical equality 比较

## ARCH-005：恢复哲学

- OpenCode Session transcript 是对话事实源
- Git commit/tree/worktree 是代码事实源
- Per-runtime NDJSON 只保存跨进程仍成立的领域事实
- 崩溃后通过 Boot Fold 恢复最新的领域事实，然后用普通程序逻辑决定下一步
- 不是恢复暂停的协程

## ARCH-006：命名原则

允许同一用户表面出现 `executor` 角色与 `executor` 工具，因为语境清楚；实现中必须由类型命名空间区分。

禁止：为消除同名引入 Translator、Governor、Broker 等无价值中间层。

## ARCH-007：不同语义使用不同工具名称

必须：只有 schema、权限、生命周期和结果语义完全相同的工具，才允许共享名称。

```text
Manager:       fork-agent / join / list
Orchestrator:  fork-manager / join
DevOps:        fork-pty / executor / ...
```

join 可以共享，因为两处语义相同：消费当前 owner 的任意可用 completion。

## ARCH-008：禁止词

禁止使用以下单词作为程序计数器或领域状态（不禁止作为 CancellationEpoch、Revision、Incarnation 等真实资源世代识别）：

```text
Stage, Phase, Lease, Owner, Generation
```

当这些单词出现在领域状态中时，CI 应检查所在类型及其参与的行为，不是仅 grep 字符串。

## ARCH-009：有界并发与共享原语契约

业务层的并发扇出只允许一个原语：有界 map。

```text
mapBounded : maxConcurrency -> CancellationToken -> ('t -> ct -> Task<'u>) -> 't seq -> Task<'u list>
```

禁止在业务层直接使用无界扇出（`Promise.all` / `Task.WhenAll` 覆盖整个输入集合）。理由属于 VERIFY-004：无界扇出让失败取决于机器负载而非逻辑，于是「慢」与「死」不可区分，而这正是因果推进门禁要消除的那一类信号。适配器边界内部为实现有界原语而使用 `Promise.all` 不受此限。

### 上限

`maxConcurrency` 必须为正且有限。非正值必须拒绝，不得默认。

```text
禁止：0 解释为「无界」
禁止：0 解释为「1」
```

两种解释都是对调用方意图的猜测，且其中一种静默移除了上限。

### 结果

结果按输入位置排列，不按完成顺序。`results[i]` 是 `items[i]` 的结果。

空输入返回空结果，且 action 调用零次。

### 取消

取消在获取许可处观察，早于 action 被调用。已取消的 token 必须使调用拒绝，不得返回部分结果。

token 必须传递给每个 action，使嵌套扇出可继续取消。丢掉 token 会让内层扇出不可取消。

### 拒绝语义

任一 action 抛出时调用立即拒绝。已获得许可的 action 不被取消，它们运行到完成。

```text
拒绝 ≠ 不会再发生任何事
```

调用方不得把拒绝当作「全部工作已停止」。停止 siblings 是 action 通过 token 自行决定的事，不是组合子的责任。需要「一失败即全停」时，由 action 检查 token 并由调用方持有可取消的 token 实现。

许可必须在 action 失败时归还。泄漏一个许可会让后续调用在更低的实际上限上死锁——那是挂死，不是错误。

## ARCH-010：运行时合成文本的 TOML Instruction/Data 记法

一个文本 payload 同时满足以下四条时，纳入本条：

```text
1. 它最终由 LLM 按文本 token 阅读
2. 它不是原生 system / developer prompt
3. 它不是未经重新包装的人类原始消息
4. 它由运行时、Host、插件、工具、Agent 协作层或 projection 构造、包装、复制或重新投影
```

纳入者必须以 TOML 形态表达。核心原则：instruction 用 comment，data 用 field；instruction 永远在前。

### 记法

instruction 只写为最前方的顶层 comments。禁止以字段承载 instruction，字段名再清楚也不允许。

data 只写为 fields、tables、表数组及其 value。「发生了什么」不得以说明性 comment 代替结构化字段。

同时包含两者时，物理顺序必须是 instruction comment header → 恰好一个空行 → data body。一旦第一个 data 字段或表头出现，后续不得再出现顶层 comment。

三种文档形态均合法：instruction-only、data-only、instruction + data。不得为满足格式而补虚假 data 字段或无意义 instruction。

### 语义分类

分类依据是内容在当前 payload 中扮演的冯诺依曼角色，不是句子的语法语气。

```text
被观察的历史祈使句        data（即使写作命令句）
控制模型如何处理后续输入   instruction
截断事实 truncated = true  data
「不得越过截断边界推断」   instruction
```

事实与规则不得混成一句说明性 comment。

### 字符串

单行字符串使用仓库既有 canonical 单行写法与转义。内容看起来像 instruction 不改变其为 data 的事实。

多行字符串固定使用三单引号字面量，并满足：

```text
1. 字段名、等号与起始 ''' 位于同一行
2. 内容从下一行开始；起始 delimiter 后的第一个换行由 TOML 裁掉，不属于 value
3. 内容行不加格式缩进
4. 原始内容自身的缩进逐字保留
5. closing ''' 单独占一行
6. 因此 value 恰好是原始内容加一个尾换行
7. 不使用 """
8. 不根据内容在多行 delimiter 之间做选择
9. 同一 semantic input 必须产生相同 bytes
```

选 `'''` 而非 `"""` 是因为 basic 多行字符串处理转义序列，而本条要求工具输出、文件内容、diff、编译日志原样进入 value：含反斜杠的正文在 `"""` 下要么使文档不可解析（`\d` 不是合法转义），要么被迫双写反斜杠而使 data 失真。字面多行字符串不处理转义，反斜杠原样通过。

同理不注入格式缩进：TOML 不对字面多行字符串去缩进，格式缩进会成为 value 的一部分，等于 renderer 篡改它承诺原样转发的 data。

两类内容在多行字面量中无合法表示，必须回退到单行 basic string 并完整转义：

```text
内容含 '''        会提前闭合字符串，data 逃逸到文档结构
内容含裸控制字符   TOML 禁止字符串内的控制字符（tab 与换行除外）
```

该回退不是「按内容选 delimiter」——第 8 条禁止的是在多行 delimiter 之间摇摆；此处是该内容不存在多行表示。回退必须可判定且确定。

渲染结果必须真的可被 TOML parser 读回，且读回的 value 等于原始内容加一个尾换行。单向表示不等于可以只做形似：可解析性是本记法唯一可机械检验的性质，门禁、golden test 与 containment 断言都建立在「这是一份合法 TOML 文档」之上。

字符串写法只有一个 owner。各业务模块不得分别决定引号、转义、换行处理、缩进或 closing delimiter 位置。

### Data containment

只有当前 synthetic payload 的可信 renderer 可以生成顶层 instruction comments。

以下来源只能进入 TOML value：人类原始或历史文本的副本、assistant 输出与 reasoning 的副本、tool arguments、tool stdout/stderr、文件内容、diff、编译日志、网络响应、外部文档，以及任何不属于当前 renderer 自身 instruction 的文本。

生产者不得通过直接字符串拼接，让 data 逃逸到顶层 TOML 结构。

本条提供的是明确的视觉与结构边界，不宣称 TOML value 能从理论上彻底阻止 prompt injection。不得以本条为理由削弱现有 authority、origin、tool binding 或 trust-boundary 设计。

### 无统一 envelope

本条统一 notation，不统一 schema。不得仅为统一而要求所有 payload 携带 `schema`、`kind`、`origin`、`authority`、`content_type`、`message_id` 等字段。只有当前模型任务确实需要某项 data 时，局部 schema 才包含该字段。

局部 schema 应使用清晰字段名、优先 `snake_case`、使用 TOML 原生 boolean/integer/array、重复对象用表数组、省略不存在的可选字段、保持固定字段顺序，且不发送模型当前任务不需要的数据。

只输出 LLM 决策需要的字段。runtime identity、digest、freshness、coverage marker 不得进入普通 tool result，除非该工具的用户语义明确要求。

同一语义 artifact 作为 TOML value 传递时必须复用相同 bytes：不得在不同方向改写或套第二层摘要。

### Data body 布局

instruction comment header 与 data body 之间恰好一个空行（见上「记法」）。data body 内部默认单 LF 连续渲染：renderer 不得为字段、table 或 table array 自动插入空行。多行 TOML string value 自身内容中的空行不受此规则影响——那是用户内容，逐字保留。

空字段不输出：`truncated = false`、空 `tool`、空 table 等「无信息」形态禁止。

### ARCH-010-LWR：LWR 是 opaque semantic value

LifecycleWorkRecord（COMPANION-003）作为 TOML value 传递时是 opaque semantic value。TOML renderer 只负责安全承载，不得读取、重排、摘要或补充 LWR 内容；wire renderer 不得解析 LWR 重建内部结构。

### 单向表示

该 TOML 只供 LLM 阅读，永不反向解析。禁止增加业务依赖，要求系统从 TOML 文本恢复领域对象、推断 instruction/data、推断 origin、推断 authority、驱动 fallback、驱动 review、驱动 recovery 或计算 canonical semantic digest。

instruction/data 分类必须在 renderer 之前由生产者明确。

```text
typed instruction + typed data → local renderer → Synthetic TOML → LLM
```

### 排除范围

以下不受本条约束，不得以本条为理由改写：

```text
system prompt、developer prompt、角色 prompt assets、provider 原生 instruction channel
人类原始消息（真实用户原文保持原样）
模型原始输出（原始 transcript 的正文、reasoning、tool call）
provider 原生结构（message role、tool schema、tool call ID、tool-result linkage、
                   structured tool arguments、metadata、ProviderRunIdentity、model selection）
不进入模型上下文的内部数据（Journal facts、projection state、日志、metrics、diagnostics）
```

人类消息或模型输出一旦被复制进 Blogger delta、summary context 或其他合成 projection，复制件不再是原始消息，而是被观察的 data，必须编码为 TOML value。

### 与 transport 的边界

本条只改变 textual body。不得改变 message role、tool call ID、tool result ID、call/result linkage、tool schema、typed tool arguments、runtime session identity、ProviderRunIdentity、PromptOrigin、ContinuationKind。

tool result 仍通过原生 tool result channel 发送。不得为 TOML 统一而把 tool result 改造成普通 user message。

### ARCH-010-TOOL-BOUND：自定义 tool result 抢先截断（留尾）

OpenCode Host 默认对 model-visible tool output 再截断（`packages/opencode/src/tool/truncate.ts`）：

```text
MAX_LINES = 2000
MAX_BYTES = 50 * 1024 = 51200
direction default = "head"   // 留头砍尾
pass-through iff lines ≤ 2000 AND utf8Bytes ≤ 51200
```

本插件自定义工具在 `ToolHostCodec.register` 出口经 `ToolResultBound.bound` **抢先**截断，且 **留尾不留头**（决策相关结尾：Final output、错误、join work_record）。预算为静态字面量，无迭代余量：

```text
Marker        = "...head truncated (tail kept)...\n\n"   // 34 ASCII bytes，2 lines
ContentMaxLines = 2000 − 2  = 1998
ContentMaxBytes = 51200 − 34 = 51166
超限 → result = Marker + tail(content)
⇒ result.lines ≤ 2000 ∧ result.bytes ≤ 51200
⇒ Host 默认 head 二次截断为 no-op
```

未超 Host 上限 → identity。不写 full-output 旁路文件（那是 Host Truncate 的职责）。本条只约束本插件自定义 tool 的 textual body；provider 原生 tool transcript 与 Host 内置工具不在此改写。

### 门禁

纳入范围的文本必须建立 inventory 并接受检查：instruction 未编码成字段、data 未作为顶层 comment 输出、instruction 出现时始终位于最前、data 开始后不存在顶层 comment、多行字符串不出现 `"""` 且 closing delimiter 独占一行、渲染结果可被 TOML parser 读回且 value 等于原始内容加一个尾换行、system prompt 未被纳入迁移、human raw message 未被包装、provider/tool 原生 binding 未改变。

迁移期不得长期并存裸英语 synthetic message 与 TOML synthetic message；最终门禁前必须收敛。

详见 CTX-013（Blogger delta 的 comment/data 分野与 byte accounting）、PROMPT-001（文本形态不构成 origin 或 authority 证据）。
