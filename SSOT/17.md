# SSOT/17 — LLM 退化循环检测与强杀恢复

条款 ID 前缀：`LOOP-`

本文件规定：如何在流式输出中识别「低字符多样性退化循环」，如何强杀当前 provider run，以及如何把该强杀接入既有 AABB 自动恢复（FALLBACK-002…005）。

它不定义新的 cursor 算术、不重写失败分类、不观察上下文容量。 强杀后的恢复与 provider failure 共享同一条 Fallback 路径。

---

## LOOP-001：问题与非目标

### 问题

LLM 流式输出偶发退化：最近一段文本只剩极少数字符反复出现（单字符、短循环短语）。继续让该 run 跑完只会浪费时间、污染 transcript 尾部，并延迟进入有效恢复槽。

### 非目标

```text
不识别「整段长句语义循环」            // 只覆盖低字符多样性
不估算 token / 上下文窗口             // CTX-001
不按错误文字分类 provider 失败         // CTX-005
不发明独立的自动恢复预算               // 复用 FALLBACK-005
不把 part.delta 内容拼装成领域事实     // ARCH-002
不修改 OpenCode 本体                   // ARCH-003
```

---

## LOOP-002：传感器边界（ARCH-002 的唯一定点例外）

ARCH-002 要求碎片事件在最早边界丢弃，业务层只消费粗信号。本条款在该边界上设置一个**纯传感器**：

```text
Host events 流
  ├─ session.status / session.deleted / session.error
  │     → HostEventCodec → HostSignal → 既有业务（HOST-001…004）
  │
  └─ message.part.updated / part.delta / 等价文本增量事件
        → LoopSensor 仅提取新增字符
        → 更新 O(1) 检测器
        → 判定 is_loop=false：丢弃，不进业务
        → 判定 is_loop=true：发射 LoopKill 动作（见 LOOP-006）
```

不变量：

```text
1. 传感器不得写 Journal 业务事实（除 LOOP-006 规定的强杀路径副作用）
2. 传感器不得从 delta 推断 terminal / completion / tool 结果 / Authority
3. 传感器不得把原始 payload 交给 Reconciler 或 FallbackController
4. 业务层永远看不到 part.delta；只看到「某次 attempt 被强杀后的 reconcile 结局」
```

`LoopSensor` 是 transport 边沿上的观测器，不是第二套 Reconciler。

## LOOP-003：判定指标

对已观察到的字符流，用固定个指数衰减核逼近 Zipf 型无限历史权重：

$$
w(d)\approx\sum_{j=1}^{K}a_j\lambda_j^d,\qquad d=0\text{ 为最新字符}
$$

字符 \(c\) 的混合权重 \(S_c\)、总权重 \(Z\)、平方和 \(Q\) 给出等效字符数：

$$
N_{\mathrm{eff}}=\frac{Z^2}{Q}=\frac{1}{\sum_c p_c^2}
$$

其中 \(p_c=S_c/Z\)。这是 inverse Simpson / Hill number of order 2。

判定：

```text
step < MIN_CHARS          → WARMING_UP，不判定
N_eff < LOOP_THRESHOLD    → LOOP
否则                      → NORMAL
```

无连续命中、无迟滞。 单次越阈即 LOOP（与最终讨论的无状态基线等价；状态只服务 O(1) 递推）。

## LOOP-004：固定参数（KISS）

参数是规范常量，不得按模型、角色、上下文长度动态改写（CTX-001）。

```text
K                    = 3
MIN_CHARS            = 256
LOOP_THRESHOLD       = 6.0
HASH_BUCKETS         = 4096

LAMBDA = [
  0.50000000,   // 半衰期 ≈ 1 字符
  0.84089642,   // 半衰期 ≈ 4 字符
  0.98922801    // 半衰期 ≈ 64 字符
]

COEF = [
  0.42375922,
  0.29672805,
  0.27951273
]
```

对应权重：

$$
w(d)=
0.42375922\cdot 0.5^{d}+
0.29672805\cdot 0.84089642^{d}+
0.27951273\cdot 0.98922801^{d}
$$

字符处理：

```text
按 Unicode 标量值 / 实现侧稳定的字符迭代器逐字进入
空格、标点、换行、制表符全部计入
不做 NFKC、大小写折叠、数字折叠、标点折叠
```

## LOOP-005：O(1) 递推与固定内存

### 状态

不保存环形缓冲区，不保存无限增长的字符 Map。用固定哈希桶逼近无限历史：

```fsharp
type LoopDetector =
    { mutable Step: int
      Value: float[][]          // [HASH_BUCKETS][K]
      LastStep: int[]           // [HASH_BUCKETS]
      Total: float[]            // [K]
      Cross: float[][] }        // [K][K]
```

### 每字符更新

```text
bucket = stable_hash(character) mod HASH_BUCKETS
惰性把该桶推进到当前 step
用旧桶向量 old 更新：
  Cross[j][k] ← λj·λk·Cross[j][k] + λj·old[j] + λk·old[k] + 1
  Total[j]    ← λj·Total[j] + 1
  Value[b][j] ← λj·old[j] + 1
Step ← Step + 1
```

然后：

```text
Z = Σ a_j · Total[j]
Q = Σ_{j,k} a_j·a_k·Cross[j][k]
N_eff = Z² / max(Q, ε)
```

### 复杂度

```text
时间：每字符 O(K²) = O(1)
内存：O(HASH_BUCKETS · K)，不随流长度增长
```

哈希碰撞把不同字符并入同桶，使 \(N_{\mathrm{eff}}\) 略偏低（更敏感）。这是可接受的保守偏差；禁止为「更准」改回无限 Map。

### 生命周期

```text
每个 provider attempt 一个全新 LoopDetector
强杀、turn 结束、session 删除 → 丢弃
禁止跨 attempt 复用检测器状态
```

## LOOP-006：LOOP 强杀与 AABB 接入

### 动作序列

```text
is_loop = true
→ 若该 session 当前 attempt 尚未武装 LoopKill：
     1. 记录 LoopKillArmed { SessionId; ArmedAtAttemptHint }
     2. AbortSession(sessionId)          // 现有 SDK /session/{id}/abort
→ 若已武装：忽略后续 delta（幂等）
```

禁止在 abort 返回前发送 continuation。 禁止根据 delta 内容裁剪 transcript 或改写已发出的客户端可见文本。

### 与 Host abort 语义的桥接

Host 对插件 abort 通常落成 `MessageAbortedError` / `finish=aborted`。现有路径会把其 reconcile 为 `TurnAborted`，而 `TurnAborted` **不**推进 Fallback（用户中止与清理中止不得自动 AABB）。

本条款要求：

```text
reconcile 得到 TurnAborted
且 LoopKillArmed 命中该 session
→ 清除 LoopKillArmed
→ 按 TurnFailed 走 continueAfterProviderFailure 等价路径：
     FallbackController.recordConfirmedFailure（FALLBACK-003 唯一写入口）
     若 mayContinue：
       发送 ProviderRetryAttempt continuation（PROMPT-003/005）
     否则：
       FallbackExhausted 终局（FALLBACK-005）
```

`LoopKillArmed` 是进程内局部事实，不写 Journal，崩溃后自然丢失（安全侧：最多少一次自动恢复，不会误推进）。

### Continuation 文本

固定 instruction-only Synthetic TOML（ARCH-010），经 PromptDispatcher 发送：

```text
Continue from the interruption without repeating already produced content.
```

ContinuationKind = `ProviderRetryAttempt`。 不新增 Origin 种类：强杀在领域上就是一次失败 attempt 的自动续跑，cursor 与预算语义与 provider failure 完全相同（FALLBACK-004/005/011）。

### 预算

```text
不设独立 MAX_RESTARTS
连续 LOOP 强杀与连续 provider failure 共享 ConsecutiveFailureCount
达到 AutoRecoveryBudget → FallbackExhausted，不再自动发物理请求
```

## LOOP-007：作用域与豁免

必须检测：

```text
插件 Owned 的 managed WorkSession / CompanionSession / BloggerSession
正在进行中的 assistant 文本流
```

必须忽略：

```text
非 Owned session
compaction pseudo-run（agent/mode/summary 满足 HOST-006 识别谓词）
title / 非 managed 的 Host 内部 run
已 LoopKillArmed 的同一 attempt 的后续 delta
session 已 idle 且无进行中 assistant 的残余事件
```

受限字母表任务（只允许 `是/否`、`A/B/C/D` 等）不在本产品默认 Agent 合同内；若未来引入，须在本文件新增显式豁免条款后才能关闭检测。在此之前默认开启。

## LOOP-008：与既有恢复协议的关系

| 问题 | 归属 |
|------|------|
| cursor 如何推进 | FALLBACK-002…004，唯一写入口 FallbackController |
| 自动恢复是否继续 | FALLBACK-005 预算 |
| 恢复槽是否 armed / primed | FALLBACK-012 + CTX-006 |
| X probe / Y squash | CTX-006…012，仅在失败推进后的恢复槽 |
| abort 后的 terminal 通知 | HOST-004 reconcile + 现有 TurnCompletionProgram |
| 发送 continuation | PROMPT-003/005/006 |

LOOP 只负责：**更早地把退化 attempt 变成一次可恢复的失败**。  
它不绕过 FallbackController，不直接改 Offset，不直接发 prefix probe 或 squash。

失败后是否进入 X/Y 恢复动作，仍由「紧邻失败推进 + 奇数 Offset + 有材料」三者合取决定（CTX-006）。LOOP 强杀与普通 provider failure 在这一点上不可区分——这是刻意的。

## LOOP-009：事件选型与 Host 能力

优先订阅与粗信号同一条 transport（`events.listen` 或 `/global/event`，HOST-003），在订阅回调最前端分流：

```text
isHostSignalEvent → HostEventCodec
isLoopTextDelta   → LoopSensor.push
else              → 丢弃
```

文本增量事件的字段布局随 Host 版本漂移时：

```text
无法稳定提取 sessionId 或新增文本 → 该事件丢弃，检测器不更新
不得猜测、拼接、跨事件重排 part 顺序来「补全」文本
```

本条款不要求 Host 新增 Hook（ARCH-003）。若某 Host 版本完全不暴露流式文本增量，则 LOOP 检测在该版本上静默不工作，不得为此修改 OpenCode 本体；产品仍依赖既有失败路径。

## LOOP-010：诊断

允许日志字段（HOST-007 / CTX-014）：

```text
session_id
operation = "loop-kill"
effective_character_count
detector_step
result = armed | aborted | ignored-duplicate | continue-sent | budget-exhausted
duration
```

禁止：

```text
把完整循环正文写入日志
用 effective_character_count 驱动 Fallback 之外的业务分支
把 LOOP 写成 Journal 领域事实名以代替 FallbackCursorAdvanced
```

## LOOP-011：可测契约

第 1 层（纯函数）：

```text
空/短于 MIN_CHARS → 不 LOOP
单一字符重复 ≥ MIN_CHARS → LOOP
均匀分布的大字母表 → 不 LOOP
N_eff 与批处理等价公式在浮点容差内一致（允许指数近似误差带）
```

第 2–3 层：

```text
delta 序列触发后恰好一次 AbortSession
同一 attempt 重复 delta 不二次 abort
abort 后的 idle reconcile：FallbackCursor 前进一次 + 至多一条 ProviderRetryAttempt
用户主动 abort（无 LoopKillArmed）仍不前进 cursor
```

禁止用 sleep 或 repeat-until-pass 掩盖竞态（VERIFY-004）。

---

## 设计摘要

```text
流式字符
  → 3 指数无限历史 + 4096 桶，O(1)/字符
  → N_eff < 6 且 step ≥ 256
  → AbortSession
  → 标记 LoopKillArmed
  → idle reconcile 把该 Aborted 桥接为 Failed
  → FallbackController 推进 AABB
  → ProviderRetryAttempt："Continue from the interruption without repeating already produced content."
```

传感器在边沿，恢复在 AABB，预算在 Fallback，压缩在 CTX。四者边界不得粘连。
