# SSOT/08 — Companion 与 Projection

条款 ID 前缀：`COMPANION-`

## COMPANION-001：Companion 服务角色

以下角色拥有 Companion（长期 Blogger Session Y）：

```text
Orchestrator   有 Companion
Manager        有 Companion
Coder          有 Companion
Meditator      有 Companion
DevOps         有 Companion
Reviewer       有 Companion
```

以下角色无 Companion：

```text
Inspector     无 Companion
Browser       无 Companion
Blogger       无 Companion（内部 Agent 永远不递归创建 Companion）
Executor      无 Companion（内部 Agent 永远不递归创建 Companion）
```

## COMPANION-002：Eligibility 唯一来源

```text
ActiveLogicalRun
→ AuthorityExecutionProfile
→ CanonicalRole
```

禁止：从当前物理消息的 Agent 字符串、session linkage、last user message、session cache 或 synthetic continuation 推断 eligibility。

## COMPANION-003：X/Y 架构

X = 主 Session。Y = X 的伴随 Blogger Session，使用便宜模型，无工具。

A(X) = X 整个生命周期 assistant 正式正文 + host-visible reasoning 的累积（不含 tool raw stream）。
B(X) = Y 整个生命周期有效工作日志的累积（LatestB / 自压缩后的 B'）。

## COMPANION-004：Y 初始系统消息

```text
You are the blogger of a coding agent session.
See below for the session content.
Write dense, factual work-log prose.
Do not call tools.
Do not reproduce raw code or stream of consciousness.
```

新建 X 的 Y 时提供父 Session 工作记录：优先父 B，无 B 则用父 session-wide formal A；皆空则省略。

## COMPANION-005：Y 增量轮

Y 收到 canonical 投影和普通 prompt。本轮 assistant 正文直接追加进 B。B 只含 Y 的 assistant 正文，不含 Y 的 user 输入和 reasoning。

## COMPANION-006：Y 自压缩

Y 投影接近自身上限时，旧 Y 上下文前缀替换为一条 `kind: existing_blog` user message，请求重构。新 assistant 输出是 B'，直接替代旧 B。

## COMPANION-007：Canonical JSON 投影

每次 Host 即将构造模型输入时生成。JSON 规范化必须稳定（属性排序、空字段策略、换行固定）。

```fsharp
type CanonicalMessage =
    { MessageId: string; Role: string; Kind: string
      Content: JsonValue; ToolName: string option; ToolCallId: string option }
```

## COMPANION-008：忙时跳过

Blogger busy 时不打断、不排队、不推进 BlogBase。下一次可执行 offer 基于未变化的 baseline 计算完整累计 delta，自然覆盖所有跳过内容。Blogger 失败不阻塞主 session。

## COMPANION-009：PrefixEpoch

同一 PrefixEpoch 内：`request[n+1]` 的历史前缀必须逐字节保持 `request[n]` 的 sealed prefix。

Epoch 切换：创建新的 SealRoot；允许一次显式 prefix rebase；不得声称它仍是旧 epoch 的 append-only 延续。

```text
LatestB = Y 的 session-wide 完整累积输出（持续增长）
ActivePrefixEpoch.FrozenB = 冻结的快照版本（epoch 切换时才变）
```

平常回合：FrozenB 不变，LatestB 增长，X 前缀逐字节不变。Epoch 切换：FrozenB = LatestB。

## COMPANION-010：Companion Memory 注入

使用明确标记的低信任 context block。不伪装成人类指令。不使用随机 ID。不使用当前时间。不使用高优先级 synthetic system message。同一 epoch 内内容冻结。

## COMPANION-011：Cutoff 证明

Cutoff 只位于完整 semantic turn 边界。`CoveredPrefixDigest = hash(provider-visible messages[0..cutoffExclusive])`。投影前重新计算该 digest，不匹配则禁止替换。

## COMPANION-012：Provider-visible projection

缓存比较只使用真正进入模型的字段。排除 timestamp、cost、usage、runtimeId、directory、status、finish reason。Companion delta、prefix equality 和缓存门禁测试必须使用同一份 Provider-visible projection。

## COMPANION-013：Synthetic 稳定身份

```text
syntheticId = hash(sessionId + epochId + semanticKind)
同一 epoch 内 role/content/parts/IDs/order 全部逐字节固定
不得使用 GUID、Math.random、当前时间
```
