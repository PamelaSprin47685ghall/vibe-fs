# MF-01 resumed read-only design

Reviewed current main `aad92fa0b476e5a8777c505a64656fec0d1fd2d0`, the retained sandbox candidate, its five test files, the owner-contract evidence, and the saved stopped-process continuation experiment. No source or metadata edits, new sandbox probes, or Host interventions were performed.

## Decision

Use one independent guest process per model run, with a trusted bootstrap and a restricted model realm inside it. The process provides CPU and lifetime ownership; it does not by itself provide an OS capability sandbox. The membrane still has to keep the bootstrap's filesystem, transport, process and environment objects out of the model realm. Do not publish or wire the existing vm candidate: its pause only stops its pump, and its Bun after-await and async Callable deadline failures remain.

Host owns real fs/API closures, as-is ledger and read snapshots, session authority, JsCallLoop decisions, JsSearch and all physical shell/rg process owners. Guest owns the complete model execution graph: top-level program, class, proof/execution instances, constructors, metadata getters, sanity thunks, next/watch/onExit, Promise continuations and serialization getters/thenables. No guest function, Proxy or accessor-bearing object is ever invoked in Host. No function is reconstructed from source.

## Minimum contract

1. **Exact owner.** A private Host owner holds its actual process handle and a non-reused run incarnation. Every RPC, completion, Callable handle and park generation binds that incarnation. Guest-supplied PID/session strings never identify a cancellation target. Closing revokes new requests; accepted work remains Host-owned until settled. Late responses are discarded, not attached to a new run.
2. **Synchronous fs remains synchronous.** write/mkdir/rm/mv/whereAll keep their existing non-await call behavior, failure envelopes, path checks and ledger ordering. The guest blocks only itself waiting for a correlated Host business reply. Host stays asynchronous and runs the actual existing closure. Do not move fs authority or ledger into the child. Existing non-await write followed by actual Host read must observe the committed content.
3. **Separate transport ownership.** Use a dedicated guest synchronous-reply descriptor and a separately owned asynchronous command/reply channel. One descriptor has one reader. Do not combine readSync with a stream reader on stdin. Frames have request ID/run incarnation/length; each direction is pumped independently with bounded transport chunks and incremental UTF8 decoding. Chunk size is not a new semantic result limit. Accepted request plus lost reply is unknown, never an automatic replay. Host must not synchronously wait for guest consumption.
4. **Explicit Callable port.** Host operations are asynchronous construct/read-spec/call-method/invoke-proof-thunk/release, using guest-local opaque class/instance/thunk handles. Read-spec yields validated data plus method-presence flags. Proof and execution use separate instances. Return objects are made passive before crossing; thenable assimilation and property access stay in guest under its deadline. Preserve receiver, lexical closures, mutable instance state, existing sanity verdicts, onExit ordering and ReadOutput checks. No Host Proxy adapter that secretly invokes guest code locally.
5. **Deadlines.** Host owns the existing absolute deadline and nested borrow/reset/release semantics. An external watchdog follows that same owner, including Callable proof/execution borrowing; a second fixed short timeout is not allowed. It can stop a guest blocked synchronously, in a getter, or looping after await. Before reporting physical cleanup, require actual exit/close. Unknown close remains unknown with retained ownership. Program finalization and shell process finalization are distinct facts.
6. **Park.** Active -> ParkRequested -> Parked must include actual physical non-execution observation, not only a parked Promise or stopped pump. The pre-existing raw POSIX evidence is a primitive only. Publication of a parked handle must follow the observed suspension. No requirement to rerun long tests to reason about this design. If a supported physical pause/resume owner contract cannot be implemented and verified, stop this implementation package; do not substitute cooperative park.
7. **Unpark.** Consume the site once in Host. Stage the exact generation's injected value and new deadline while stopped without awaiting a large write into the stopped child's full pipe. Resume the same guest, then require the correlated application acknowledgement; original lexical continuation survives. The value is arbitrary JSON as today. A failed transfer after consuming a handle is not permission to run a second copy. Again-park gets a new handle.
8. **Abandon.** Consume only that exact site's owner, revoke stale requests, cancel its Host execution scope, stage rejection of its original park await plus the existing cleanup budget, and resume. Native finally can call real Host API during that explicit Abandoning state; new park is refused. Catching abandonment cannot restore a normal result. On budget exhaustion, terminate this guest and settle already accepted ledger operations and Host-owned shell resources. Do not claim the finally finished merely because the child died. Reap's current fire-and-forget public behavior can retain a private tracked cleanup owner after removal from the site table.
9. **Data/errors.** Reuse current JsFailure codes, reasons, minimumOutputBudgetBytes and delivered/abandoned families. Wire representation must explicitly preserve existing undefined/absence distinctions and non-JSON validation failures; plain JSON conversion must not quietly turn invalid numbers into null or silently drop fields. Guest serialization itself is executable code and is deadline-bound. ReadOutput is rechecked before each actual exposed slice, never authorized by a guest field or cached initial admission.

## Smallest useful vertical implementation

**Package A, isolated candidate only:** trusted guest bootstrap, two independent transport readers, exact run owner/watchdog, a real synchronous Host write and async cat, one async Callable port that constructs and drives proof/execution instances, then park/unpark the same continuation and abandon with a real Host fs finally. Keep all four lifecycle endpoints in one owner rather than a set of disconnected demos. This can be bounded as an isolated candidate package; it is not public module acceptance. The old failed supervision target-exit assumption must remain a negative control.

**Package B, main Callable port before composition:** change `JsCallLoop`'s current class/instance `obj` contract to explicit asynchronous guest operations. Constructors/getters at 828+, calls at 1120/1195/1327/1456, proof thunks at 1739+ and fresh execution construction all move through that port. Passive command parsing stays Host. Update `ToolsBindings` call handoff and do not leave an old object execution path in production. Existing direct loop test surfaces may use an explicitly named local test driver, not a production fallback.

**Package C, main lifecycle integration:** `JsSandbox.fs/.fsi` own the guest handle and existing deadline lease authority; `ToolWorkflow`'s run/unpark/abandon and `OpenCode/ParkedSites` retain one session/site/ledger owner. `ToolsBindings` gets a transport adapter over its actual closures. JsSearch and process ownership remain Host. Public declaration, build/package support and requirement text describing former vm internals follow this implementation, then public Node22/Bun package consumption and main combination tests.

Do not merge A alone as MF-01 closed. This is substantially more than importing the 380-line candidate: it changes the execution boundary of a roughly 1900-line Host control loop and its lifecycle composition. A bounded isolated vertical candidate is a credible next package. Full Node/Bun production reception in the same small round is not yet defensible without first passing A's transport and suspension gates. Estimate after those gates, rather than promising a deadline from the existing 20/18 test counts.

## Acceptance that cannot be omitted

- Both runtimes: top-level sync/after-await loops, Host-invoked constructor/getter/sanity/thunk/next/watch/onExit, returned getter/toJSON/thenable loops leave the Host responsive; external exact owner terminates and witnesses close. Existing sandbox callback red cases remain visible.
- Actual existing Host fs closure and journal: non-await write + subsequent read, thrown errors and already committed mutations; no duplicate mutation on accepted/lost reply. Preserve path/read-snapshot authority and Prepared/Committed ordering.
- Transport: large Unicode responses, frame splitting, backpressure, overlapping callbacks and simultaneous async RPC with sync calls; no reader competition or Host deadlock. A stopped child with a message exceeding pipe capacity cannot stall unpark setup.
- Callable: lexical capture and receiver, proof instance differs from execution instance, async next/watch/onExit, mutable callback state, exact output budget and passive-data result parsing, actual supervised process close and Unknown boundaries.
- Park/unpark/again-park: observed suspension, no stray continuation CPU or side effects while parked, preserved original closure, source marker and once-only handle consumption. A short deterministic suspension/continuation proof is required; a new hours-long pause is not.
- Abandon: real native finally performs Host write/rm, repeat park is refused, looping finally is cut off, and accepted ledger appends plus exact Host-owned shell scopes still settle. Old run/park/class/thunk IDs cannot affect another run or session.
- Deadline: nested parallel borrow release in both orders, reset while borrowed, legitimate long shell operation, and cancel while waiting for an RPC. No hidden shorter timer changes existing functionality.
- Production authority: real ReadOutput revocation, cancellation/retirement and late replies. No permission defaults from standalone surfaces, no fake zero exit, no success from signal request alone.

Memory cap remains an explicit [006] obligation: a child process is not an exact heap limit. Define and verify the runtime/OS enforcement available on both supported runtimes before claiming that part closed; do not invent a sampled-RSS threshold as an established product contract.

Retained facts: the former paused-owner run was stopped by user at about 20 minutes, not a one-hour pass; its 76-byte transfer and lexical value 41->42 only prove that finite primitive. No previously blocked action was repeated for this report.
