# spec/14 — 结构化程序 DSL（Structured Program DSL）

条款 ID 前缀：`FLOW-`

## 本文件性质

本文件是 ARCH-001 的展开规范与执行合同，规定业务程序必须如何用封闭 DSL 表达，禁止哪些程序计数器与任意 Task 注入。

冲突时以 `spec/01.md` 的 ARCH-001/ARCH-002/ARCH-003 为准。

---

## FLOW-001：结构化程序替代状态机

业务控制流必须用 F# computation expression、代数数据类型（DU）、纯函数与尾递归表达。

禁止在业务 record/DU 中使用以下形态的字段：

* 回答「程序下一步去哪」的字段；
* 两个以上 bool 可形成非法组合；
* 重启后需要猜测如何恢复；
* 等价于调用栈、局部变量或 continuation；
* 名字含 `Stage`、`Phase`、`Next`、`Running`、`Pending`、`Spent`、`Already`、`Should`、`Dirty`。

允许保留的只能是物理世界真实事实：进程已退出、PTY 已关闭、文件存在、Git 工作区 dirty、消息被 Host 标为 completed、输出发生截断、某条持久化事实存在。

## FLOW-002：业务程序是数据

`Program<'result>` 是封闭领域指令的 AST，不是正在执行的协程。

Program 必须满足：

* 不直接执行；
* 不持有 Runtime；
* 不读取时钟；
* 不追加 Journal；
* 不捕获 Host 对象；
* 不序列化自身；
* 不作为恢复中的暂停协程。

崩溃恢复遵守 ARCH-005：Journal facts → Fold → 构造新的 Program → 从事实决定合法入口。不得持久化 Program 节点、continuation 或「执行到第几步」。

## FLOW-003：唯一 Interpreter

每个领域 DSL 恰好有一个生产 Interpreter、一个纯模拟 Interpreter、一个 Trace Interpreter。

Interpreter 只解释单个指令，不拥有业务分支。业务分支必须在 Program 构造阶段或纯 Domain 决策函数中完成。

## FLOW-004：删除逃生口

以下 API 不得对 Program/Domain 层可见：

* 通用 `Flow.lift` / `Flow.create`；
* `fromTask` 等把任意 `Task` 注入 DSL 的 helper；
* 通用 `Runtime -> Task<Result<...>>` 函数。

所有副作用只能由 Interpreter 调用 Infrastructure 端口完成。

## FLOW-005：命名组合子替代任意循环

DSL builder 不提供任意 `While`、无限 `For` 或裸 `TryWith`。

必须提供命名组合子，例如 `repeatUntil`、`retryAtMost`、`reviewUntilConfirmed`、`forEachBounded`、`withOwnedResource`、`onCancellation`。

每个组合子必须固定：最大次数或退出证据、取消传播、错误类型、资源释放、可观察轨迹。

## FLOW-006：规则 DSL 与流程 DSL 分离

规则组合子与流程 DSL 是两个独立层。

```fsharp
type Rule<'input, 'error> = 'input -> Result<unit, 'error>
```

* 有依赖的规则用 `andThen`，首错短路；
* 相互独立的规则用 `validateAll`，一次收全错。

流程 DSL 决定「做什么」；规则 DSL 决定「是否允许」。

## FLOW-007：多个小型语言

禁止建立覆盖全系统的万能 `Operation` 大联合。

应建立多个小型语言：

```text
AgentProgram
CompanionProgram
ReconcileProgram
BloggerProgram
ReviewProgram
OrchestratorProgram
ProjectionProgram
```

共享的只有最小 Program 机制、取消模型、资源作用域和测试工具。领域指令不共享。

## FLOW-008：依赖方向

依赖方向必须为：

```text
Infrastructure → Interpreter → Program → Domain
```

Program 不得引用 Interpreter、Infrastructure 或 Host port。Core 不引用 Runtime。

## FLOW-009：Program 文件门禁

以下形态在 Program/Domain 文件中禁止出现：

* `task { }` 原始 Task 代码块；
* `let mutable`（除纯局部累加器外，需逐条豁免）；
* 调用 `Flow.lift` / `Flow.create`；
* 引用 `Infrastructure/OpenCode` 或 `System.IO` / Git 操作；
* 行为型 bool 参数；
* 通配分支吞掉 DSL case；
* 程序计数器字段。

## FLOW-010：投影 DSL 边界

功能模块只能声明 `ProjectionIntent`，不能直接接收并修改 `Message list`。

不同 intent 修改同一锚点时必须：有明确定义的合并律、或返回 `ProjectionConflict`、不允许依赖注册顺序。

---

## 完成定义

以下必须同时满足：

* `Program` 层原始 `task { }` 数量 = 0；
* `Program` 层 `let mutable` 数量 = 0；
* `Flow.lift` 生产调用数量 = 0；
* workflow 行为型 bool 参数数量 = 0；
* workflow 程序计数器字段数量 = 0；
* 每个顶层 workflow 返回领域 `Program`；
* 每个 `Program` 有生产、模拟、Trace Interpreter；
* `Interpreter` 不拥有业务分支；
* `Projection` 只有一个生产 owner；
* `LegacyProjection` 已删除；
* 旧 `Flow` 与旧 `RuntimeState` 已删除；
* CI 负例证明绕过 DSL 必然失败。
