# spec/14 — 结构化程序 DSL（Structured Program DSL）

条款 ID 前缀：`FLOW-`

## 本文件性质

本文件是 ARCH-001 的展开规范与执行合同，规定业务程序必须以直接执行的 F# computation
expression 表达，禁止再造「指令 AST + Interpreter」的第二套运行时。

冲突时以 `spec/01.md` 的 ARCH-001/ARCH-002/ARCH-003 为准。

> **历史纠偏（SUPERSEDED）**：本文件早期版本把 DSL 误定义为「封闭指令 AST + 纯 Program +
> 唯一生产/模拟/Trace Interpreter」，并宣称 `computation expression ≠ DSL`。该方向与
> ARCH-001「语言运行时已提供 continuation/调用栈/取消，业务层直接用 computation expression
> 写流程」相悖，是复杂度膨胀的根源，现整体撤回。本节为唯一现行表述。旧版本中值得保留的
> 价值（纯决策、有界递归、命名组合子、可检查的执行轨迹、规则 DSL、从 Journal 恢复）已
> 换用直接 CE 承载，见 FLOW-004/005/007/008。`Kernel/Program.fs` `Kernel/TraceInterpreter.fs`
> 属第二运行时产物，应删除。

---

## FLOW-001：流程直接由语言表达

业务流程必须直接使用 F# computation expression、`let!`、`do!`、`match`、`return!`、纯函数
和有界递归表达。

```fsharp
orchestrator {
    let! targetHead = ops.ReadTargetHead job.TargetRef ct
    let! rebase = ops.RebaseOnto job.Worktree.Path job.TargetRef ct
    match rebase with
    | Conflicted(files, head) -> return! resumeConflict ops job files head ct
    | Rebased candidate      -> return! reviewThenPublish ops job candidate targetHead ct
}
```

F# 调用栈就是流程栈，`let!`/`match`/`return!` 就是流程与分支。禁止 `CurrentStage`、
`NextAction`、`Running` 等程序计数器；它们描述的是「程序下一步去哪」，而这是语言运行时的职责。

## FLOW-002：DSL 是可执行语法，不是中间表示

领域 DSL 是 computation expression 与领域命名操作构成的源码表面，直接执行。

禁止要求业务流程先构造内部 AST 再执行。`Program<'instruction,'result> = Pure | Suspend`
形态、`Command/Reply` 总线、`Step` continuation AST、以及任何把普通调用序列编码后再回放
的解释器都属于第二运行时，禁止引入或保留。

## FLOW-003：领域操作必须强类型、具名

业务流程只能通过具名 capability 调用副作用：

```text
awaitManager
readTargetHead
rebaseOnto
publish
readSnapshot
observeSnapshot
```

每个操作只返回自己那一种结果，返回类型在编译期确定。不公开泛化的 `execute Command`。
禁止用大 Reply DU 承载所有回复——那会让每步都要处理十几个理论上不可能出现的分支。

## FLOW-004：纯决策与效果流程分离

领域层负责：

```text
Evidence -> Decision
Facts    -> Projection
Input    -> Result
```

纯决策函数只描述「观察到了什么、应采取什么决策」，不执行副作用：

```fsharp
type ReconcileDecision =
    | RereadWithBackoff of clearCandidate: bool
    | Publish
    | StopPass

val decideStep : ReconcileEvidence -> ReconcileDecision
```

Application 层根据 Decision 直接执行效果。规则组合子（`andThen`、`validateAll`）作为纯
Domain 组合子保留；流程 DSL 决定「做什么」，规则 DSL 决定「是否允许」。

## FLOW-005：恢复从事实重新进入普通流程

恢复过程：

```text
Journal facts
→ Fold
→ 纯恢复决策
→ 调用普通 workflow 的合法入口
```

不得恢复 Program 节点、continuation 或「执行到第几步」。崩溃后经 Boot Fold 恢复领域事实，
再用普通程序逻辑决定下一步（ARCH-005）。

## FLOW-006：禁止第二运行时

以下形态一律禁止：

```text
通用 Program<Pure,Suspend>
业务 Command/Reply 总线
Step continuation AST
内部业务 Interpreter
ProtocolMismatch 补偿分支
持久化执行位置
obj/unbox 驱动的通用业务程序内核
```

允许保留的是对真实物理事实的区别：进程是否退出、PTY 是否关闭、消息是否被 Host 标为
completed、某条持久化事实是否存在。外部协议（JSON/TOML/Host wire）的 codec/parser/
interpreter 不属第二运行时，可保留。

> **外包层禁止**：本条款的意图是实际替换语义，不是给旧实现换皮。CE builder 不得在 Bind
> 内部回头构造 AST；旧 coordinator / RuntimeState 不得在直接 CE 入口后面继续暗跑；删除旧的
> 执行面之后，新 CE 路径必须是完整、可运行、可测试的。删得掉旧路径才算完成。

## FLOW-007：循环和并发必须有界

允许普通递归和并发组合子，但必须具有明确：

* 预算；
* 退出条件；
* 取消传播；
* 资源释放；
* 错误类型。

命名组合子如 `repeatUntil`、`retryAtMost`、`forEachBounded`、`withOwnedResource`、
`onCancellation` 可用来固定这些性质。并发扇出仍遵守 ARCH-009（业务层只允许有界 map；反
对无界扇出）。本条款不要求通过 AST 表达。

## FLOW-008：通过可观察效果测试流程

流程测试使用 fake capabilities 记录调用、参数、facts 和结果，断言执行顺序：

```text
ReadBinding
ReadSnapshot
Delay
ReadSnapshot
Publish
Observe
```

此类轨迹来自 fake port 记录，不来自 Program 树形，也不引入 Trace Interpreter。行为级
unit/integration/e2e 保持为验收途径。

## 建议的最小实现

优先内置 `task {}`；仅当 `Result` 短路样板明显过多时，保留一个几十行的 `TaskResultBuilder`
（`Bind` 直接 `match!` 到真实 Task，不构造 AST）。`agent`/`companion`/`orchestrator` 可以是
该 builder 的语义别名，甚至全部直接使用 `taskResult`。`AgentProgram` 与 `CompanionProgram`
当前「functions, not a Flow AST」、直接以 `task`/`let!`/异常映射执行的写法是参考实现。

---

## 完成定义

一个子系统只有满足以下条件才算纠偏完成：

1. 业务主流程可以从上到下直接阅读。
2. 不存在该子系统的 `Command + Reply + Step/Suspend`。
3. 不存在解释该内部 AST 的生产 Interpreter。
4. 不存在由大 Reply DU 导致的「不可能回复」分支。
5. Domain 中只剩事实、证据、决策和值对象。
6. 异步、取消和错误直接使用语言运行时。
7. 恢复从 Journal facts 和 projection 重新进入正常 workflow。
8. 测试通过 fake ports 验证调用顺序和外部结果。
9. 行为级 unit、integration、e2e 全部保持。
10. 删除旧实现，不留下长期双路径。

量化门槛：

```text
目标子系统 ProtocolMismatch 数量           = 0
目标子系统内部 Program Interpreter 数量    = 0
目标子系统 AST trace-only 测试数量         = 0
```
