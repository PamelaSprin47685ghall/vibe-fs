# spec/09 — 执行模型

条款 ID 前缀：`EXEC-`

## EXEC-001：Fork/Join/List

Manager 控制面：`fork-agent` / `join` / `list`

Orchestrator 控制面：`fork-manager` / `join`

DevOps 额外控制面：`fork-pty`

## EXEC-002：Fork-agent 语义

```json
{
  "agent": "fast-coder | deep-coder | ... | <existingAgentId>",
  "prompt": "string"
}
```

新建 Agent：prompt 非空，agent 为准确角色名。已有 Agent ID + prompt：nudge/continue，fire-and-forget。

Busy existing agent：不创建新 RunId、不安装新 listener、不创建新 completion。nudge 归属于当前 active Run。

## EXEC-003：Fork-pty 语义

```json
{
  "agent": "pty | <ptyId>",
  "prompt": "string",
  "signal": "TERM | KILL | INT | HUP | QUIT | USR1 | USR2 (optional)"
}
```

PTY ID + prompt 非空 = write。PTY ID + prompt 空 = read。PTY ID + signal = 发信号。

## EXEC-004：Join 语义

等待任意一个完成项。返回 handle ID、kind、role、status 与 `workRecord`（最终 LWR）。`formalRecord` 已废止，不存在。

成功 wire 只含：`status`、`agent`、`work_record`（LWR opaque string）。失败 wire 只含：`status`、`agent`、`[error] code/message`。runtime-only 身份（agent_id、run_id、child_session_id、authority_root、provider_run、directory、digest、freshness、covered_through、tier、fallback_peer）不得进入 LLM-visible join 结果；需要时留在 typed runtime / journal / diagnostic surface。

每个 RunIdentity 对应 single-assignment completion cell。Terminal/SendFailure/Cancel 竞争 TrySetResult，首个成功者唯一生效。Join 消费后从 active/completed mailbox 索引删除，并写入永久 `HandleRetired` tombstone。

无活跃资源时返回 `NothingToJoin`。

## EXEC-005：List 语义

```json
{ "kind": "all | agent | pty (optional)" }
```

返回当前运行期资源的派生视图，包含 Running、Busy、CompletedAwaitingJoin 三种状态。不包含 Retired。不承担 Agent catalog 功能。

## EXEC-006：Child Run 生命周期

新建 Agent：先监听 terminal，再发送 prompt（极快 terminal 也不丢）。

child 初始上下文 = 创建时物化的父 LWR（`includeOpening=true`：Opening + Y frames + X gap + terminal，COMPANION-003）。gap/terminal 均经 LWR 投影，不含 raw tool call/result。不存在「B else A」分支：Y 从未成功时也是同一物化算法（Opening + 0 frames + 全 X gap 投影），没有旁路语义。

child 的 OpeningPromptRaw 是 fork 原始 assignment 与权威 requirements，不是带 `parent_work_record` 的 synthetic transport envelope——后者是继承 context，不复制进 child 自己的 Opening，否则多代 fork 递归嵌套。

terminal 提取 child 最终 LWR 供 join：`includeOpening=false`（布置者已知任务）；`TerminalOutputRaw` 只取 formal text + host-visible reasoning；completion 只携带该 LWR。不存在独立的 session-wide A 提取，不把末回合 tool call/result 写入 work record，不把 child Opening 回传父模型。

## EXEC-007：Nudge

Fire-and-forget：不建插件队列，不等待当前 run。如果 Host 不支持 busy append，返回 `BusyNudgeUnsupported`。Busy→Idle 竞态以 Host AcceptPrompt 返回的 run/message identity 为唯一归属依据。

## EXEC-008：Parent Background

子 Agent 创建时的不可变快照。始终使用创建时物化的父 LWR（`includeOpening=true`，frozen bytes 冻结于 `ChildRunCreated`）。FrozenRecordPrefix 专用于父 Session X 的前缀缓存保护，不应用于 child background。不存在「无 B 则 session-wide A」分支——同一物化算法覆盖全部状态。

创建失败重试、Host retry、restart recovery 必须读同一个 frozen parent LWR blob，不重新物化，否则同一 child logical run 的背景可能漂移。

## EXEC-009：Handle 生命周期持久化

```fsharp
HandleLinked
HandleCompleted
HandleAbandoned
HandleRetired
```

```fsharp
type HandleLifecycle =
    | Active
    | CompletedAwaitingJoin of HandleCompletion
    | Abandoned of HandleAbandonReason
    | Retired
```

HandleId 创建一次并持久化。重启恢复同一个 ID。

四态语义：

* `Active`：已 link，尚未完成或放弃
* `CompletedAwaitingJoin`：完成 cell 已写入（Terminal / SendFailure / Cancelled），`join` 可消费
* `Abandoned`：持久终态；不可 join、不可回退为 Active/CompletedAwaitingJoin；父取消经 `HandleAbandoned` 进入此态（不再经 `CompletedAwaitingJoin(Cancelled)` + retire）
* `Retired`：`join` 消费完成后的 durable tombstone。Retired ID 永远返回 `RetiredHandle`，不得退回到"把输入当成 Agent 名称重新 fork"

`HandleAbandoned` 事实由 `HandleController.recordAbandon` 唯一写入（CAS：首个生效）。`join` 对 Abandoned 必须立即返回明确 Abandoned 结果，不得阻塞或误报 Completed。

**中断 ≠ 终态。** loop-detect 中断、Host abort 后自动续跑（LOOP-006）、ProviderRetry 等 wake **不得**写入 `HandleAbandoned`，也不得用 Aborted 填满 pending completion cell 并向父 Join 广播终态。`HandleAbandonReason` 仅：`ParentCancelled` / `DeadlineExceeded` / `HostSessionGone`。

Agent、PTY、ManagerJob 分别具有 typed handle。父取消必须逐项取消所有 owned physical resources。

## EXEC-011：Process Deadline

```fsharp
let effectiveDeadline request configuredHardLimit =
    min (TimeSpan.FromSeconds(float request.EstimatedRunningSeconds * 3.0),
         configuredHardLimit)
```

LLM estimate 不能突破管理员硬上限。Hard limit 必须有限。Timeout 后 SIGKILL 整个进程树，kill 后等待真实 onExit。不设置第二套互相竞争的业务 timeout。

## EXEC-012：大输出摘要

触发条件：`stdout bytes + stderr bytes > 3 × estimated_output_bytes`

200KB chunked ripple-carry reduce。Map 并发，结果按 chunk index 排序。Executor IDs 由 hash 生成（确定性）。Map/reduce 失败时返回 partial summary + 最后 200KB raw tail。

## EXEC-013：Large Gate

SemaphoreSlim(1,1)。只限制 Large。Medium 无并发限制。success/failure/cancel 都由 use! 释放。

## EXEC-014：Executor 私有 Runtime

每个 parent session 拥有一个私有 Executor runtime。Executor map/reduce completion 不进入 Manager mailbox。

## EXEC-015：PTY 行为

```
- TERM 后默认等待 5 秒再 KILL
- Close = stdin EOF（不是 SIGKILL）
- 每次 read 返回自上次 read 后的 unread delta
- UTF-8 半字符：保留在内部 buffer
- Buffer 上限 > 64KB
- PTY completion 只由 backend onExit 触发
- Signal/Close 不提前完成
- parent abort 后 await process-tree 收敛
```

## EXEC-016：Background Join Guard

拥有 `join` 的角色在 assistant terminal 时，若仍有未消费的后台资源，不得以 Completed 收束；发送 Continuation `JoinGuard`，优先于 Manager Review Guard（REVIEW-007）。

适用范围：`Manager`、`Orchestrator`、`DevOps`。其它角色无 `join` 义务，本条不适用。

### 何谓 outstanding

派生谓词，不是程序计数器：

| 角色 | outstanding |
|------|-------------|
| Manager | 本 session 的 handle 处于 `Active` 或 `CompletedAwaitingJoin`（EXEC-005 listable） |
| DevOps | 同上，或本 session 仍有 live PTY（EXEC-015；PTY 以 runtime 视图为准） |
| Orchestrator | 仍存在 non-terminal `ManagerJob`（ORCH-004 `activeJobs`） |

Executor 私有 runtime 永不进入此谓词（EXEC-014）。

### 行为

```text
TurnCompleted
→ outstanding?
  → yes: 延迟 Completed；发送 JoinGuard Continuation；本 turn 不进入 Review Guard
  → no:  再走 REVIEW-007 / Reviewer Guard 等既有路径
```

JoinGuard：

* Continuation（PROMPT-003）：不建新 Logical Run、不改 profile、不重置 Fallback
* 经 PromptDispatcher（PROMPT-005）；fire-and-forget = Detached（PROMPT-007）
* 同一 session 已有 outstanding JoinGuard claim 时不再重复发送
* 文案 instruction-only（ARCH-010），固定英文：要求先 `join` 收取完成项；需要视图时用 `list`

禁止：

* 在 outstanding 时报告 terminal Completed 让 join/AwaitManager 提前返回
* 用 Host background-subagent 通知语义替代本仓 `join` 义务
* 为 JoinGuard 引入 Stage / Lease / Generation 程序计数器
* 扫描完整 journal 历史判断 outstanding（PERSIST-008：投影 O(1)）
* Executor map/reduce completion 触发本 guard
