1. Protocol (typed domain facts, no giant DurableEffect union)
--------------------------------------------------------------
External side effects share one protocol, expressed as domain-typed facts:

  Requested / Claimed
  -> idempotent physical effect
  -> Accepted / Created / Published

  Crash: Requested-without-Accepted = not happened (retryable).
  Accepted proves physical completion. Duplicate Accepted is idempotent.
  Accepted must never fold back to Requested.

Mapping implemented:

  | Effect           | Request                         | Accepted              | Reconcile                                      |
  |------------------|---------------------------------|-----------------------|------------------------------------------------|
  | Worktree create  | WorktreeCreateRequested         | WorktreeCreated       | git worktree list --porcelain / OrchestratorSweep |
  | Git publish      | PublishClaimed                  | Published             | ORCH-007 ref/head probe (already closed)       |
  | Prompt send      | (PROMPT-011)                    | PhysicalAccepted      | PROMPT-011 at-most-one                         |
  | Blogger request  | BloggerRequestMaterialized      | BlogEntry/Squash...   | ProviderRun receipt                            |

Session create — physical-limit exception (documented in SSOT/11.md):
  Host issues child SessionId only after session.create returns. No
  SessionCreateRequested. Accepted evidence is HandleLinked /
  CompanionBloggerLinked.

3. Worktree create path
-----------------------
Effect identity = WorktreeCommands.identityOf(jobId) = manager/<job>
  (deterministic before git runs).

Writer: Application/Orchestration/Orchestrator.fs forkManagerCore
  1. append WorktreeCreateRequested { ManagerJobId; WorktreeIdentity; WorktreePath }
  2. WorktreeResource.Create → git worktree add -b manager/<job>
  3. append WorktreeCreated { same identity/path }
  4. StartManager → ManagerJobCreated (unchanged ORCH-006 ordering)

Fold: Journal/Fold.fs
  WorktreeCreateRequested → OrchestratorProjection.requestWorktree
  WorktreeCreated         → OrchestratorProjection.acceptWorktree

Projection: OrchestratorProjection.WorktreeEffects
  Map<WorktreeIdentity, WorktreeEffectStatus>
  WorktreeEffectStatus = Requested | Created  (RequireQualifiedAccess)

Idempotency rules (locked by tests-mjs/Orchestrator/job.test.mjs):
  - request on empty → Requested
  - request after Requested → no-op
  - request after Created → no-op (no Accept→Requested regression)
  - accept after Requested → Created
  - accept after Created → no-op
  - fold of [Requested, Created, Requested] stays Created
  - fold of [Requested, Created, Created] stays Created

Reconcile (existing, unchanged):
  OrchestratorSweep.sweepStaleArtifacts
    owned = activeJobs |> map WorktreeIdentity
    git.ListWorktrees() porcelain
    remove manager/* worktrees not in owned
    delete manager/* branches not in owned
  Requested-without-Created leaves no durable job → next sweep cleans orphan
  worktree/branch if git succeeded but process died before WorktreeCreated.
