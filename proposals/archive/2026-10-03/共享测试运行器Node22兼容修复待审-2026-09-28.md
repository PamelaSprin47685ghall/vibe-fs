## 已确认的问题和规范依据

`verification-system[021]` 要求准确报告原定范围、实际完成范围及未完成原因，不把没有有效结论的事项计为通过；`[006]` 要求监测真实因果推进。

## 待批准的准确改造范围

仍使用 Node 公开 `run()`、原单一外部监督器和原并发上限，不升级 engines/CI、不提高 watchdog、不改变测试结果、skip、TODO 或取消规则。

每个 stream 只运行一个已经确定的计划入口。调度层因此知道其真实所属入口，可为旧 Node 转发事件时附加入口元数据，而不从注册路径或名称猜测。若 runtime 提供 entryFile，则先核实它与计划入口指向同一个真实文件；合法路径别名不能误拒绝，无法核实或实际矛盾必须使验证无有效结论。

`run-inner.mjs` 需要增加 `availableParallelism`、`realpathSync`、`PassThrough` 导入，采用下列关键实现。其余 HOME/配置隔离和参数筛选保持原样。下面为待审代码，不代表验证完成。

```js
export function bindTestEntry(event, entryFile) {
  const planned = resolve(entryFile)
  const actual = event.data?.entryFile
  if (typeof actual === 'string' && resolve(actual) !== planned) {
    // /var 与 /private/var 或 symlink 可以表示同一文件；失败不可默默忽略。
    if (realpathSync(actual) !== realpathSync(planned)) {
      throw new Error(`Test event entry mismatch: expected ${planned}, received ${actual}`)
    }
  }
  return { ...event, data: { ...event.data, entryFile: planned } }
}

const concurrency = parseConcurrency(process.env.NODE_TEST_CONCURRENCY)
const workerCount = Math.min(files.length,
  concurrency === true ? Math.max(availableParallelism() - 1, 1) : concurrency)
const startedAt = performance.now()
const runState = createRunState()
const output = new PassThrough({ objectMode: true })
let failed = false
const reportError = (error) => {
  failed = true
  process.send?.({ type: 'runner:error', data: {
    name: error?.name ?? 'StreamError',
    message: error?.message ?? String(error), stack: error?.stack,
  } })
  console.error(`run-inner: stream error: ${error?.message ?? error}`)
}
output.on('error', reportError)
const composedStream = output.compose(createCompactReporter({ state: runState }))
composedStream.pipe(process.stdout)
const reporterFinished = finished(composedStream).catch(reportError)
const eventTypes = [
  'test:start', 'test:pass', 'test:fail', 'test:complete',
  'test:diagnostic', 'test:stderr', 'test:stdout',
]
const runFile = async (file) => {
  const stream = run({ files: [resolve(file)], concurrency: 1 })
  const drained = drainTestStream({ stream, send(message) {
    failed = true
    process.send?.(message)
  } })
  for (const type of eventTypes) {
    stream.on(type, (data) => {
      try {
        const event = bindTestEntry({ type, data }, file)
        applyEvent(runState, event)
        process.send?.({ type, data: {
          name: data?.name, file: data?.file, entryFile: event.data.entryFile,
          testId: data?.testId, line: data?.line, column: data?.column,
          nesting: data?.nesting, durationMs: data?.details?.duration_ms,
        } })
        output.write(event)
      } catch (error) {
        reportError(error)
      }
    })
  }
  stream.resume()
  await drained
}
const pending = files[Symbol.iterator]()
await Promise.all(Array.from({ length: workerCount }, async () => {
  for (let next = pending.next(); !next.done; next = pending.next()) {
    try { await runFile(next.value) } catch (error) { reportError(error) }
  }
}))
// 单 stream 的 summary 不参与整组 wall 计算；此处只记录实际总耗时。
output.end({ type: 'test:summary', data: { duration_ms: performance.now() - startedAt } })
await reporterFinished
if (failed) {
  process.exitCode = 1
} else {
  process.send?.({ type: 'runner:summary', data: summarize(runState) })
  process.send?.({ type: 'inner:drained' })
}
```

`drainTestStream` 另需把未收到 end 就 close 的情况视为验证过程错误，输出 runner:error；不能把 close 当成功 drain。保留既有 error/end 竞态只结算一次的规则。

`test-run-state.mjs` 的 Node 22 身份兼容也属于此次待审内容。现代 runtime 仍使用实际 entryFile/testId；旧 runtime 的真实 verdict 只有 testNumber，没有可跨父项复用的稳定 id，因此以本进程收到的**实际 event.data 对象身份**去重，不用名字或 testNumber 值冒充唯一键。listener 与 reporter 收到的是同一个转发对象，必须共用映射。建议关键实现如下：

```js
// constructor
this._legacyVerdicts = new WeakMap()
this._nextLegacyVerdict = 1

_resultKey(data, file) {
  if (data.testId != null) return `${file}::id:${data.testId}`
  if (data.testNumber != null) {
    if (!this._legacyVerdicts.has(data)) {
      this._legacyVerdicts.set(data, this._nextLegacyVerdict++)
    }
    return `${file}::event:${this._legacyVerdicts.get(data)}`
  }
  // 无 runtime 身份的旧受控事件仍沿用既有显式位置键及矛盾检查。
  return `${file}::${Number(data.nesting ?? 0)}::${data.name ?? '<unnamed>'}`
}
```

叶子和容器都使用该键。相同 data 对象重复消费只计一次；同一实际身份给出不同 final verdict 仍拒绝。不能声称旧 runtime 中两个不同对象仅凭同名就能被判定为“同一执行的矛盾结果”；那正是此次必须避免的错误推断。正式回归需覆盖实际重复名称以及同一事件重复/冲突，决定最终代码是否充分。

## 获批后的实际实施与定位验证

用户批准后，已在上列相同文件范围实施多 stream 兼容修复，未构建或修改共享 dist、未提交或推送。方案代码块保留批准时版本；最终实现以 `run-inner.mjs`、`test-run-state.mjs` 及正式 021 回归为准。全仓正式验收由根代理在最新上游合并、冻结和新构建后统一运行。

实际机制：

- 每个 `run({ files: [oneFile] })` 有独立真实 runtime stream；统一调度仍按显式并发数或 Node 默认的 `max(availableParallelism()-1, 1)`。没有增加测试预算。
- 入口与原始注册位置分开保存；runtime 入口字段缺失时附上该 stream 唯一实际入口。显式损坏字段、真正不同文件或无法核实的别名拒绝归属；合法 symlink 和 `/var`/`/private/var` 别名按真实文件核对。完成归属仍回到计划入口。
- 每个 stream 用 WeakMap 把同一原始事件对象只绑定一次，实时 listener 和 reporter 共用绑定结果。Node 22 缺少稳定 testId 时按真实事件对象去重；相同文本的不同执行分别计数，同一执行矛盾的最终结果仍拒绝。外层 file wrapper 与内层 suite 属于不同 native root，即使 testId 相同也分别保存失败容器。
- 实时事件继续提供因果进展；报告用异步迭代及等待写入回调限制新增合并缓冲。Node 原生 TestsStream 自身的缓冲不由此实现控制，不能声称整个运行时已有统一内存上限。
- 只有报告或结果流真正出错才停止队列并 abort 活跃的独立 controller；这不是新的叶子超时或总时限。premature close 和 reporter 异常不生成最终权威汇总。正常路径在所有文件流及 reporter 消费结束后只发送一次 summary 和 drained；单流 summary 不覆盖整组 wall。
