durable-events017：真实 raw Append I/O 有限正式测试方案（只读设计）
2026-10-06；未修改repo，未build/test/Git。

一、最小结论与公开入口

建议先做017-I0 test-only I/O包。唯一产品调用仍是正式登记的
Persistence/EventStore/Surface.js：create(commonDir,writerId)、
append(handle,events)、read/head、dispose。canonical incoming字节通过正式
CodecSurface.encode产生。本文rawAppend指现有Surface.append，不是不存在的
新导出。现Surface.create -> EventStore.createLocal -> integrator.ReloadLocal
同步完成activation；计量必须等create与head/read正控成功后才清零开始。
WorkspaceEventStoreSurface.activate存在，但它没有raw append公开桥；不从
不透明store挖出私有Append/Integrator，也不新增compat facade。

017现两例是无Git源码词形和字节prefix/cold/corrupt-tail，不证明history增大时
rawAppend I/O不变。新例不删除现断言，不用墙钟阈值，也不把批量数量N或
writer数量K代入公式充当实际调用/字节计数。

本包只能证明以下fixture与已覆盖Node I/O边界：正常已激活rawAppend不读取
旧event内容、仅追加本次完整canonical字节、fsync实际执行、当前/冷结果合法、
无Git CLI/原生进程launch与Git object/ref文件访问。history fold次数仍未证；
不声称整条WHAT017、关联payload写入、所有内存数据结构复杂度或完整首次准入
成本闭合。

二、已有可复用接缝

- native录制模式：node:fs default对象原方法包装后调用syncBuiltinESMExports，
  原call必须完整转发。仓库已有registered-prefix.mjs、grounding006同模式。
- ProcessEventLog用了named fs imports；proper-lockfile的processAwareFs在模块
  import时Object.assign捕获原fs。这是必须在任何dist import前装配的原因。
- append真实路径：Surface.append -> Store.Append -> native withStoreLock ->
  validate/PrepareLive -> ProcessEventLog.append -> appendFileSync -> openSync r+
  -> fsyncSync -> closeSync -> actual Commit -> release。新helper不复制任何一步。
- Node child生命周期沿用runVerificationToolProbe实际monitor/selected-process
  owner，signal来自正式test.signal；不要裸spawn后遗留PID。
- Surface.create明确进行正规replay；不手工fold，也不通过空Current假称已激活。

三、固定fixture与批量准备（避免N次独立append）

建议固定1个历史writer，两条正式leaf分别历史长度8和128（数字是输入设计，
不是成本计数）。同一target stream 'proof/append-io'，合法线性parent链，
最后历史event id固定'a'.repeat(40)、payload固定{anchor:'stable'}。
中间events id固定hex identity且各不重复，JobRequested为原known vocabulary；
每个envelope payloadRefs=[]。全部events一次Surface.append(seed,batch)准备，
不是每event一个锁/进程/fsync。

可由017父test的正常Surface完成seed，seed返回.ok=true且cuts=[]后dispose。
meter child用新的WriterId，禁止接管历史writer；之后独立cold child也新WriterId。
两个场景measurement前都只有1个实际历史ndjson，append后实际writer集合都是
historical+meter两个文件。用真实readdir/原bytes验证该集合，不能从K推算访问数。

incoming完整对象在两场景完全相同：id固定'c'.repeat(40)，stream同上，parents
只有固定历史head，payload含固定Unicode文字（如'万象-é'）、固定数字/字段，
payloadRefs=[]。先用正式CodecSurface.encode得到同一canonical JSON+LF，
Buffer.from(text,'utf8')保存实际expected bytes；不能用String.length当UTF8 bytes。
历史最后head的identity与payload相同，incoming大小/内容不随历史长度变化。

目录为实际私有temp root，commonDir按现Surface合同直接使用其.git路径，
无需git init。Git recorder正控可真实执行git --version（原exe/argv确被录制且
原执行正常返回），不依赖repo初始化；随后计量清零。文件对象/refs recorder
另以owned私有路径的真实文件访问证明可见，不能把CLI正控代替直接I/O正控。
不操作workspace/user repo，正式计量阶段不做Git setup。

四、child先装配原I/O recording，再dynamic import正式Surface

允许新窄helper位于requirements/durable-events/tests/support/append-io-child.mjs；
只静态import Node builtins，所有dist imports是可静态判定的literal dynamic
imports且只指向现登记Surface/CodecSurface。父runner/helper不得import生成
IntegratorEngine/StructuralIntegration/内部Fable runtime，亦不枚举generated exports。

提前保存原函数；wrapper用Reflect.apply(original,this,args)，返回原值/原Promise，
保留原Error，不插fake成功/假rows，也不跳过I/O。下面明确的记录表足够当前原路径：

1. sync fs：readFileSync、readSync、openSync、closeSync、appendFileSync、
   writeFileSync、writeSync、fsyncSync、statSync、readdirSync、existsSync；
   namespace effect另外记录mkdirSync、rmSync、unlinkSync、renameSync等已触发调用。
2. fs.promises：readFile/writeFile/appendFile/open/access/stat/readdir/mkdir/
   rename/unlink。必须覆盖它们，因为现GitObjectDatabase可直接以fs.promises
   操作objects/refs，不是所有Git操作都spawn CLI。open路径已可判Git访问；
   不必为了零Git断言造一个通用FileHandle框架。
3. child_process：execFile/execFileSync/spawn/spawnSync/exec/execSync/fork均记录
   原executable/argv并转发。measurement内assert所有native launch为0，强于
   仅查字符串'git'，防止shell/默认runner变体躲过Git计数。
4. syncBuiltinESMExports在装配后执行；正常结束finally恢复原方法并再次sync。
   child独立，因此不会污染父test或其他文件的builtin state。

每个record保存方法、实际path或fd、实际returned read bytes、实际incoming
argument UTF8/buffer bytes、成功/失败状态；fd->path由真实openSync返回的fd
登记，close后删自己登记。未知fd/无法归因的读写只能记unattributed并拒绝该
计量证明，不能静默归零。fd-number重用不能继承旧path。

path仅以真实commonDir/event/payload/Git目录和明确文件做边界分类：
 event content=events/*.ndjson；payload另栏；lock/owner.json另栏；
 Git infrastructure=objects/**、refs/**、packed-refs、HEAD等对象/引用路径。
记录实际触发的原call，不把metadata stat算event bytes read，不把lock owner.json
read冒充历史读，也不从N/K估计read bytes或操作数。

bytes度量：readFileSync返回Buffer按byteLength；readSync按实际返回整数。
appendFileSync成功后记录真实传入的canonical byte buffer/UTF8字节，不估算。
同时在measurement结束后以未计量的原read验证writer实际suffix恰等于完整
expected bytes、旧文件prefix逐字节不变。这是实际落盘写bytes正控，不能只
凭append参数或一个统计计数称写成功。若Node内部可见嵌套write调用，同时
记录其层级/结果，勿把append argument和内部write bytes重复相加；最终byte
proof以实际writer增量+完整suffix为准。

五、时序与完整正控

父test(seed.batch once) -> meter child：
 a. 装配recording（flag先false）、syncBuiltins；真实read/Git recorder正控，
    要看到实际返回与被记录call一致；clear。
 b. dynamic import Surface/CodecSurface；Surface.create新的meter writer。
 c. 保存activation records，核确有实际历史event bytes读取；read历史head的
    native event对象与head结果准确。此证明recorder接到原named fs路径，
    不是只包装default fs后自己调用一次。
 d. 清零并开measurement，await Surface.append(handle,[incoming])，只这一
    native operation在窗口内；Task完成含fsync、Commit与真实lock release。
 e. 立刻停止并冻结report；此后read()/head()与原filesystem字节验证不混计量。
 f. exact result {ok:true,cuts:[]}，实际read(incoming)==完整incoming对象，唯一
    head是incoming，writer完整suffix==expected canonical bytes；历史原bytes
    仍完全相同。dispose原handle，finally恢复recorders。报告stdout一个bounded
    JSON对象：actualPID、writer files、activation/append阶段实际records、bytes、
    exact result与heads/payload证据。不得通过日志成功文本代替assertions。

父test -> 独立cold child：正常新Surface.create+read/head，核历史链与incoming
完整原字段/父边/payload仍合法、no cut/fork/collision、所有文件实际完整LF结尾。
冷进程不用instrumentation，更不能复用meter child的Current。两child正常
close与原monitor验收后父test才cleanup owned temp root，失败也按原owner回收。

正式assert（两历史长度分别运行、不只比较两个可能同样错误的report）：
 append窗口内所有event content read calls/actual bytes===0；
 legacy writers read/write/rewrite bytes===0；
 native Git/process launch===0，Git object/ref文件访问===0；
 actual append writer byte增量===同一expected incoming bytes.length；
 actual suffix===expected bytes，fsync至少一个有效incoming-writer fd记录；
 未归因read/write=[]；结果/head/cold/旧bytes均exact合法。
不对stat总调用数、所有lock辅助操作固定数字，不使用wall阈值。

六、history fold未证的明确停止线

I/O零旧bytes不证明cached history不会在内存再次fold。现正式Surface没有任何
onIntegrated/onRuleFold native observation；JS直接修改exported
StructuralIntegration_rule.Integrate或import生成IntegratorEngine违反JS002/006。
单纯包装program中的Structural副本也不可靠：原structuralStep直接使用私有
builtin StructuralIntegration.rule，可能完全漏记structural fold。

因此本次仅I/O有限包，不新增production observation，不触碰generated module，
不把history-fold=0写为assertion或计划已证。以后若需这一能力，由canonical
engine owner在真正唯一single-event integration步骤加bounded eventId观察，
同一原算法、原返回值，无第二fold；需另冻结语义与callback失效合同。本包
不先设计/落地该新factory，也不以从N/K减去incoming数推算历史fold次数。

七、正式red/green分类与反事实

原rawAppend当前源码没有ReloadLocal，预期新I/O例baseline green；若实际绿，
必须叫新增有限证据，不能为造diff称旧产品bug红。先record baseline原日志。

随后由唯一Store owner手工在实际append前加原integrator.ReloadLocal(commonDir)，
不mock历史、不替代I/O、不换fold。统一fresh build后同017两例必须因为真实
old bytes/read calls>0红，同时原append/cold/完整canonical输出仍合法。这个
controlled mutation证明cost oracle有效，不是原业务bug红。恢复原字节、
统一build/fresh并重跑017应绿；每份snapshot/原件按实际输入独立记账。
不得为这个变异并发编辑当前U0 owner Store.fs；由root串行批准与执行。

该I/O观察也不能声称删除metadata stat就解决完整first admission：Surface.create
activation仍读历史/replay；未来guardedcall的fresh-read、准入、payload闭包和
receipt/Release都有独立成本与truth obligation。窗口排除这些动作的结果必须
明确称activated rawAppend，而非完整start/Host first-effect。

Surface/factory、无新的registry/owner/fold、无预算改变，不重复seed N次。
若actual I/O recorder无法覆盖imports、发生未归因fd、callback/恢复改变原
I/O异常或真实cold不合法，停止为能力前提，不削断言。若需要关联payload写
capability或fold observation，拆下一包，不用fake payload/fake积分强行闭合。
