# 原始材料载体与后缀重放

本批接续 `d5992761e`，总计划 N05-B/T388 的有限范围已验收：自动 Grounding 保留实际读出的合法 UTF-8 字符串，以统一强类型载体附加来源；已持久化的旧呈现原样重放。gen137 正式相关223/223排空、1454pass/0fail，真实 Host integration 1/0。整体 GAP-085/086 与发布义务仍保留。

## 根因与修复边界

WHAT[requirement-grounding-007] 要求正文保持原始读取字节。旧 `cursorResult` 把正文交给 Instruction renderer，添加 `#`、把 CRLF/裸 CR 变为 LF；空正文、末尾换行和尾空格也不能用归一化后相等证明。公共 `OriginalMaterial` 单独保存原正文与 typed Data metadata，只由 `LlmFacing` 渲染一次；普通 Instruction/Data 的既有合同不改。独立 oracle 为原正文加统一来源后缀，完整比较 UTF-8 字节。

另一个根因是旧 Pair/Grounding 后缀清理对整段结果做全局文本替换。真实 Host 结果和新材料正文都可以引用完整旧 Guidance、旧材料载体，不能据文本相似推定属于当前呈现。新路径先从 XTrace 读取唯一匹配 message、optional part、call 身份且摘要有效的原 Host 结果，保护完整原正文；呈现边界只来自当前 ResultGap 的 durable occurrences，按历史顺序形成完整累计组合。真正无 part ID 的结果精确匹配 durable None，不能借 Some，也不使用数组位置猜原文；双 None 候选仍拒绝。不能借别的消息、部件或锚点的文本来裁剪。缺失身份/原结果不猜，损坏证据明确拒绝。重锚前后若同一字节组合对应不同的 owner 保留结果，必须拒绝歧义；现有日志没有额外投影 receipt 时不猜测历史分段，也不引入新的兼容协议。

正式相关回归还发现 capture 早于后缀清理：无 ID 的历史 projected tool result 被重新捕获成含提示的新原结果，导致两个候选，后续提示正确拒绝后无法投递。薄 coordinator 现在仅为 observations 生成 Pair→Grounding 清理副本，两个调用均传空 legacy suffix 集；outObj 与返回 RawMessages 不改。三个投影循环后的 canonical 工具结果恰好是两份原文，有效公开红见[捕获边界红例](baselines/vibe-fs-t388-capture-before-strip-red.log)。没有更改 Capture 的冲突规则，未知正文仍保留；无 ID 的 user/text 呈现不在这项证明范围。

正式回归覆盖 CRLF、裸 CR、空正文、无末尾 LF、Unicode、BOM/NUL、来源/系统标记样文本，三个 provider 的注册原生 after hook 与实际 JS read；原始结果中完整旧载体、材料以 Guidance 或旧载体开头，以及同锚点多个版本的组合歧义另做回归。canonical XTrace 不吸收呈现，再入 projected wire 保持相同消息与字节。012 继续用独立进程删除源材料、追加新版和冷重放，并加入旧公开 producer 真正生成的 NDJSON 黄金日志，不用新 renderer 重写旧事实。

## 真实 Host 序列化证明

007 的 integration 使用安装版 Host1.18.29 与薄 hook，调用编译出的 Pair/Grounding owners。它记录 after output/title/metadata、SDK completed transcript、下一次实际 provider POST 的原始 HTTP 字节与解析后完整 tool result、原始材料 oracle 和实际 journal。两次原生 read 分别触发旧/新材料版本，第二次请求之后旧消息保持冻结前缀。错误、晚到 provider 失败和回收错误均使探针失败；沿原 5s readiness、30s 观察和 45s 子进程预算。

该证明范围是薄 owner hooks 加真实 Host serialization，不是完整注册生产插件的全部 Long Stroke。Host 原生 read 自身丢失换行/长行的事实未修，仍为 PartialFile；本批保真的是自动读取的规范材料。无 XTrace 的 legacy/user fallback、无 ID user/text 的 canonical 呈现隔离、非法 UTF-8 文件及其它表示调用路径不能借本批升级为完整无损证明。整体 GAP-085/086 继续保留未证范围。
