## 实际读取版本

旧 Gate 丢弃返回内容，Runtime 按路径重新读取当前磁盘；JS 又把事务 freshness 快照当作显式读取。因此旧返回 v1 可以抑制新磁盘 v2，partial 被当成全文，grep 也会取得全文资格。三种正式行为红例和两个真实 symlink 红例见 baselines 下 `vibe-fs-grounding006-*.log`。

新 `GroundingFileRead` 携带实际返回字符串、路径和 CompleteFile/PartialFile。新 durable `RequirementGroundingReadObserved` 保存内容摘要及范围，只有精确匹配的 CompleteFile 能抑制当前完整材料；部分输出仍记录，但不能替代全文。JS 在真正读取处捕获 resolved path 和返回文本，回调前 alias 换目标不改变读事实归因；外 root symlink 返回原 PATH_DENIED。grep 保留事务 freshness，后续真实文件变化仍拒绝提交，但不产生显式读取观察。失败读取不回调、不造事实。

生产 Gate/Runtime/ToolWorkflow/ToolHost/ToolRegistry 已接新契约。旧 MaterialObserved 的 codec 和可见语义保持，正常 boot 能读两类事实，reanchor 清空当前资格。历史黄金日志只证明旧 schema 恢复和不重写；不能恢复旧 producer 当年没有保存的返回内容，也不能据此称所有既有事实的归因都已重新证明。

原生 Host 1.18.29 实际执行七个 read。完整 after output/title/metadata、SDK completed transcript 和下一次实际 provider POST 逐项一致，但 LF/CRLF/无末尾 LF 的正文与 metadata 坍缩；长行裁至 2000 字符，仍 `truncated:false`；50KB 上限的 totalLines=35 不表示实际 70 行。因此当前原生返回均为 PartialFile，不猜测原始换行或补读磁盘。正常与真实晚到 HTTP500 均正式验证，负例要求恰一 provider SyntaxError、零主流程/回收错误和两个推理请求，不能以预期失败遮蔽泄漏。原始协议证据在 [正常](native-read-normal/oracle.json)与[晚到错误](native-read-late-error/oracle.json)目录。该被动协议探针不冒称完整生产插件的 Host Long Stroke。
