# N06-B1-A2：三个 producer 的真实 source 穿透与一次接口冻结顺序

基线：`198e8251e`，2026-10-05。本文只读调查，不是已实现契约或验收证明。工作区未改；未运行 build/test。与 `/private/tmp/vibe-fs-n06-b1-a2-handoff.md`、contract agent 的 `/private/tmp/vibe-fs-n06-b1-a2-observation-lease-handoff.md` 配套阅读。后者的具体 lease 草稿以其独立审查为准。

## 1. 先纠正基线，避免重复施工 D0

D0 已将 root/continuation 的实际 `onAccepted` 注册移到 Await/Detached 分支之外，在 claim 持久化之后、实际 Host 调用之前注册。Detached 回调已能接到真正 durable PhysicalAccepted。旧 A2 handoff §4.1 中“Detached 忽略 callback”的现状已过时。

D0 没有关闭同 call 因果归属、观察资源释放、callback 异常和整个 A2。现 `PromptPhysicalAcceptance` 仍是全局每 PromptKey 单 callback；`register` 覆盖同 key；`cancel` 会一起删除 callback/waiter；`awaitConfirmation` 超时也调用全 key cancel。`accepted` 先从 registry 取出并删除 callback/waiter，再执行 callback，最后结算 waiter。callback 抛异常仍能让已持久化事实的处理报错、取出的 waiter 永不结算。这是独立前置包的真实边界，不能被 source 穿透遮住。

## 2. source 含义与唯一绑定时点

每个 source 必须至少原生保留：

- SessionId；
- 实际 source PhysicalUserMessageId；
- source AuthorityRootUserMessageId；
- 实际 source ProviderRunIdentity。

这些字段回答“哪个实际 terminal 触发了这一次 successor”。它们不是 successor 的 physical identity，也不是 call identity。绑定时要由现 `SyncDelegateRuntime` 对该实际 source 验证当前 concrete invocation 的所有权，并生成只捕获该 call 的观察能力。绑定成功之后，callback 不能再查当前 child/current call。

同 call 的 successor 只有在原 Send owner 持久化实际 PhysicalAccepted 后，才加入该 call 的 accepted-attempt 集。source 绑定和得到 PromptKey 不等于已经接受 successor；Receipt、AlreadyAdmitted boolean、RetryVerdict.Dispatched/Superseded 都不等于实际 physical acceptance。

## 3. 三条生产路径：现有签名、丢失位置、应冻结的最窄改动

### 3.1 ProviderRetryAttempt

现入口：

`src/Wanxiangshu/Execution/Delegation/SyncDelegate/Runtime.fs` 的 `SyncDelegateRetryPort.Retry` 接收完整 `ReconciledTurn -> ExecutionFailure -> string -> Task<Result<unit,string>>`。

`src/Wanxiangshu/OpenCode/Plugin/PluginSessionWiring.fs` 的 `delegateRetryPort` 将完整 turn 交给 `ProviderRecoveryWorkflow.continueDelegateCallAfterConfirmedFailure`，把 Dispatched 和 Superseded 都映射成 `Ok()`。这个映射保留现 retry 策略，但不提供本次接受的 identity。

`src/Wanxiangshu/Participant/Provider/Attempt/Fallback/Workflow.fs` 的 `sendRecoveryContinuation` 尚持有完整 turn 和精确 authorization，但调用：

```fsharp
HostSessionNudge.trySendGateContinuation
    sessionPort rootWorkspace turn.SessionId prompt
    ProviderRetryAttempt turn.Directory (Some durable)
    (recoveryGateKind authorization) authorization.ProviderRun
```

完整 source physical/root 和绑定到具体 call 的观察能力没有穿过这条签名。`OpenCode/SessionNudge.fs` 的内层已有 `onAccepted` 参数，公开普通 wrapper 传 None。

不能只修改这一个 fresh send。`redispatchAfterFailure` 在 `recoveryAlreadyAdmitted` 为 true 时提前返回 Superseded，根本不会进入 `continueWorkMain -> sendRecoveryContinuation`。当前 GateNudgeAlreadyAdmitted 的 bool 同时包含 pending/accepted；`GateNudgeAcceptedPhysical` 读 payload-occasion summary，只返回 physical，不返回原始 PromptKey。只在 fresh path 注册观察，会漏掉原 key 已存在的分支。

需要先冻结 Dispatch owner 的 exact occasion evidence 读契约，原生区分：

1. 未接纳：可按现 single-flight claim/send 路径尝试发送；
2. pending：保留原 PromptKey、原 admission/occasion identity，观察只能关联这个原 key；
3. actually accepted：保留原 PromptKey、实际 physical/root，并由现 PhysicalLandings 校验同一原 key 的事实。

不是给 GateNudgeAlreadyAdmitted bool 拼第二个 lookup，也不是 caller 解析 payload。随后 retry 的早退分支与 fresh send 才能使用同一个已绑定具体 call 的 observation。

已有原 key 必须证明属于同 call，才能幂等续接/读取。若原 key 属于另一 call、原 owner 已丢失且没有持久化同 call 证据，返回明确未确认/需恢复的结果；不把它转移给当前复用 child 的 call。原 bool early return 的业务策略和 stop fence 不宜顺手重写。

现 `PromptDispatcher.Runtime.RunGateNudgeOnce` 是同 occasion 的 single-flight send owner。保留它，不能再建一个 flight 或为取得 callback 重发原 key。

不能以现 `trySendGateContinuationPhysical` 代替观察：其 accepted 只返回 physical，pending AlreadyAdmitted 报错，fresh 路径等待 acceptance；会改变 Detached/等待语义，并且没有原 key+同 call 的完整证据。

建议冻结范围：Retry port 增加“已绑定 source 的 observation 能力”，ProviderRecoveryWorkflow 原 WorkMain/InteractionRepair 继续路径原样下传；fresh 与 early AlreadyAdmitted 都交给 Dispatch exact occasion owner。类型名称随 lease 契约定，不提前暴露 bare callback。

### 3.2 InteractionRepair（普通 repair 路径）

`src/Wanxiangshu/Interaction/Repair/InteractionRepair.fs` 的 `InteractionRepairWorkflow.sendRepair` 有完整 `ReconciledTurn`，调用：

```fsharp
HostSessionNudge.trySendIdleGateRepair
    quiescence permit sessionPort rootWorkspace
    turn.SessionId prompt turn.Directory journal repairKind turn.ProviderRun
```

这里是普通 repair 丢 source physical/root 和具体 call observation 的边界。应在 source owner 尚持有 full turn 时绑定，随后与原 quiescence permit 一起穿过现路径：

`trySendIdleGateRepair -> trySendIdleGateContinuation -> trySendGateContinuationWithAdmission -> sendGateContinuationWithAdmissionProfile -> SendIdleGateNudge -> SendContinuationWithDigestAttempt`。

最下层现 `SendIdleGateNudge` 传 `onAccepted=None`，下层原 Send owner 已支持 callback；无需第二套发送器。只需要冻结这条链的 optional typed observation 参数及原 key evidence 返回/接管时点。

必须保留 final physicalsend 处的 `TryConsume permit` 与 native definiteNotSent 才能 release 的政策。不能为绑定 delegate 把 permit 提前消费，也不能 unknown 当 definiteNotSent。

无 active SyncDelegate call 的普通 repair 仍按原 owner 工作，observation 可以 None；不能因为未绑定 delegate 而停止所有 repair。

Blogger 的 `InteractionRepairNudge` 带 BloggerRequestId、terminal run、独立 repair budget，是另一 lifetime。不要为了“统一 repair”重写它；本包按实际普通 SyncDelegate source 路径接线。

### 3.3 DegenerationGuard（需要特别防止绑定太晚）

`src/Wanxiangshu/OpenCode/Host/LoopSensor.fs` 的 armed 保存 `(DegenerationKind, ProviderRunIdentity)`；activeInterrupts 保存 `(ProviderRunIdentity, Task, Task)`。它确切拥有 Session+run，但**并未拥有 source physical/root**。不要从“exact run”推断它已具备完整 causal source。

现低层 `ILoopSensor.ConsumeAbortCause`：

```fsharp
sessionId:SessionId * expectedRun:ProviderRunIdentity * directory:string option
    -> Task<AbortCause>
```

`HostTurnObserver.abortCauseOfTurn` 刚好持有完整 `context.Turn`，但仅将 session/run/directory 传给 Consume。这是绑定 full source 的最窄生产边界。必须在进入 Consume 的 await 和 continuation launch **之前**捕获 immutable source，并由现 runtime 绑定具体 call。

Consume 现过程先 await exact interrupt，再在 gate 内验证 armedRun=expectedRun、storedRun=expectedRun、原 task ReferenceEquals，移除旧 armed/interrupt，安装本次 continuation proxy；随后 `StartContinueWork -> ContinueWorkerTask -> TryContinueSession -> constructor continueSession` 走既有 `runOwnedWork`。这些原 proxy/reference 检查和 finally FinishContinue 必须保留。

现 constructor continuation：

```fsharp
SessionId -> DegenerationKind -> string option -> Task<Result<unit,string>>
```

`HostSignalBootstrap.continueFn` 仅有 session/kind/directory，调用 `sendContinuationResult ... DegenerationGuard ... AwaitMode.Detached None`。因此 source+已绑定 observation 要随原 proxy-owned continuation 的参数穿透到 continueFn，再下传现 Send owner；不能在 continueFn 临时查 latest provider step 来补 source。

不要 Consume 返回后再绑定：effect 已启动。不要让 callback 查 ActiveInterrupt/current call；不要单独 raw CreateChild+SendPrompt；不要另起 guard task、额外 listener 或 runner。

类型层次要先定：SessionContract 属于低层 host-session-contract，不能为这次透传直接依赖高层 SyncDelegate 或 dispatch-runtime。可以在低层定义只含 Foundation.Identity 的 `GuardContinuationSource`（上述四个 fields），同时使用经 review 的低层 opaque observation/transfer contract；不要把 ChatExecutionKey、完整 ReconciledTurn、Runtime 对象或 obj 偷渡进低层。

若 lease 在 Dispatch owner 层实现，低层 guard 携带的应是已绑定观察能力及其 before-effect ownership transfer 约定，而不是直接迫使 SessionContract 引用高层 lease concrete type。这个层次关系必须与 contract 的 lease 卡一起冻结后才改 fsi。

## 4. 与 observation lease 的衔接

contract 卡将独立定义 per-registration opaque token lease。关键语义保持：

- 每次 register 都创建新 token，即使 callback instance 一样；Dispose compare-remove 自己 token，不能删除替代 registration；
- Dispose 是观察资源释放，不能调用全 key cancel，不能改 waiter、Pending/PhysicalAccepted/Abandon 等 claim truth；
- register 的真实生产消费者有三个：Send root、Send continuation、Fork/Host/RunLifecycle 的 Unknown reattach。返回 lease 的签名必须一次迁移这三个 owner；Fork reattach 不能保留按 key cancel，也不能 Pending 返回就释放。具体位置以 contract 卡为准；
- claim key 的 same-call 幂等接续由 call+occasion owner 证明，不能等同“同 callback 引用”；
- 实际 register 的 lease 必须在 Host effect 之前转交给具体 invocation owner；sender 内 `use` 到 Detached 返回就释放会错过后来真实 ingress；
- accepted 已原子取出 callback 后，简单 Dispose 无法撤回在途通知。closure 仍要检查自己捕获的具体 call 及本次资源存活，不能把 compare-remove 误称为“返回后绝无 callback”；
- Accepted/native definite Refused/实际 call retirement 的释放由现 owner 执行；Unknown 不能伪造 Abandon；
- callback 只是通知已提交事实，异常不能回滚 claim 或把 accepted 说成 refused。现 callback throw 会打断 waiter settlement，需独立正式反例与 owner-safe sequencing 修复；不能靠 consumer 凭口头承诺绝不抛来关闭；
- 不新增第二 registry/fold/listener。lease 不承诺跨进程保存 call owner；冷启动原 key 没有同 call 的持久证据时不能接给新 call。

retry 原 key pending/accepted 查询必须给 lease owner 足够精确证据。callback 单 key overwrite、旧 waiter timeout 全 key cancel 尚未修好时，不能上线三 producer 的共享观察，把它们称为已归属。

## 5. 可施工的一次接口冻结顺序

按依赖先定契约，之后手工逐段修改 fs/fsi 与真实 callers；不要一边编译一边随意改接口。

1. **先冻结低层 identity/source 与 observation ownership。** 明确 source 四字段、opaque capability 所属 package、注册 token、before-effect lease 转交、Disposed/foreign-call/未确认语义。Guard source 可放低层 host contract；高层具体 lease 不向低层反向依赖。contract 卡的 compare-remove/timeout/callback 异常范围一起 review。

2. **先闭合 Dispatch observation lease 与 exact admitted occasion evidence。** 正式红例区分旧 token Dispose、旧 waiter timeout、callback throw，保 accepted durable truth。读取 existing pending/accepted 时返回原 key，保 single-flight。新 owner query 只读现 projection，不增第二 fold/事实。lease 包可先独立提交；whole A2 仍 open。

3. **冻结 SyncDelegate concrete-call binder。** 方法接 immutable actual source，按 existing call ownership 匹配，得到只捕获该 invocation 的 observer；实际 accepted-attempt 集由原 callback 更新。退休 A 后晚到 accepted 只能落到 A 的已关闭观察，不得再 lookup B。普通 API 行为保留；不存在 source owner 时由 producer 原业务处理，不造 active call。

4. **冻结 retry public seam 与 early dedupe。** RetryPort -> PluginSessionWiring -> ProviderRecoveryWorkflow 的生产闭包下传已绑定 capability；fresh 和 recoveryAlreadyAdmitted early return 都处理精确原 key。不得仅修改 sendRecoveryContinuation 的新发送路径。

5. **冻结 ordinary repair seam。** full turn owner 绑定，随原 permit 穿过 SessionNudge/SendIdleGateNudge；未绑定 delegate 的原 repair 不改变。Blogger 独立 lifetime 留在其原路径。

6. **冻结 guard seam。** HostTurnObserver 在 Consume 前绑定；SessionContract/LoopSensor constructor/owned proxy/HostSignalBootstrap 逐层下传 exact source+capability；continueFn 使用它，不再补查当前状态。原 interrupt fencing、proxy equality、runOwnedWork/finally 全部保留。

7. **最后冻结生产 composition 与正式 harness。** 三 producer 各从实际公开业务入口触发，真实 originalkey claim+durable acceptance；不得只有 Surface 的人工 callback injection 就关闭生产接线。ordinary HandleTurn 与 fallback 两入口均证明：A 的 accepted successor 能完成 A；A 退休且 B 复用同 child/root 后，A 的旧 retry/guard/repair terminal 不能完成 B；A pending successor 晚到 acceptance 也不能归 B；B 的合法本次 terminal 能完成 B。每个负例独立 cleanup，不能第一断言红后其余未执行仍说复现。

8. **证明各合法 continuation 都接通后，再删除宽历史 kind 判定。** 不先一刀只接受 initial physical，破坏合法本次 retry；也不保留 root+任意历史 ProviderRetryAttempt/DegenerationGuard/InteractionRepair 作为兼容 fallback。计划状态按 lease / source seam / actual production path / cold recovery 分开记，局部 green 不关闭整个 A2 或 Sphinx B1。

## 6. 明确禁止替代证据

- current/latest child、latest physical、当前投影的 provider step、当前 authorityRoot 相同；
- root+任意历史 continuation kind、arrival-time/调用开始 cursor 截断；
- Sending PromptKey、Host Receipt、RetryVerdict.Dispatched/Superseded、AlreadyAdmitted bool 当作 actual accepted；
- 从 prompt/payload digest 自行猜 source 或只读 occasion summary 返回 physical；
- terminal 完成之后 TryFind/latest 补 receipt；
- 用 `trySendGateContinuationPhysical` 的额外等待代替 before-effect observer；
- Unknown 时主动 Abandon、CancelSession 冒充本次物理 abort、lease Dispose 调全 key cancel；
- same key 上无 token compare 的覆盖/释放、sender `use` 到 Detached 返回；
- 拿第二 listener/fold/runtime 或第二 raw send owner 绕过 existing owner；
- 从上一进程既有原 key 推断属于现在的新 call。

## 7. 下一独立小包建议

首先做 observation lease 的旧 token/timeout 不跨世代删除，以及 accepted callback 异常不破坏真实事实和 waiter settlement。它能独立闭合且正式测试入口很窄。随后冻结 exact occasion 原 key evidence，再接 retry source；guard 的低层 contract 与 proxy-ownedwork 一起做，不能把 guard exactsource 误写为已经存在。

本文仅给一次冻结顺序与已定位边界。具体 public types/signatures 需由 root 合并 lease 卡 review 后一次冻结；不在这份调查补卡中宣告尚未实现的 API 已存在。
