## 逐项断言强度

- 实际 handles：seed 原 Append 成功并 close；新 left/right 各自原 store.create，从同一个 base head、完全相同 Current 出发；分别原 prepareTransition 同 intent、不同 commandId，两个不同 eventId、parents=[同 base]，payload.events=[同 request]。Pure seal 后 Current 不变。
- 左边 Append 完成后，右 handle 仍是原完整 Current，store.read(left.id)=null；右随后原 Append 仍返回 ok/cuts=[]。这直接展示锁下原 Append 没有替 stale Current 做 fresh business acceptance。
- exact event 重放：左边第二次 Append 与第一次返回同形原 `{ok:true,cuts:[]}`，目录全部 names/bytes 不变。因此这个 raw success 不能证明本次新写，更不能独立授权 Host。
- 两 OS processes：原 fork 两个不同 ChildProcess/PID，新的不同 WriterId；每个 child 自己 boot、read Current、seal，再发送 sealed。父收到两者才 release。release.map 同步记录两个 go，孩子后续事件只能在该栈返回后进入父事件循环；完整 trace 必须 sealed,sealed,go,go,appended,appended。
- 不使用 sleep、delay、setTimeout、增大预算、retry、调度碰运气、锁内 await 对手。原 append native lock 只按现有 owner 竞争。
- fixture IPC 身份与创建所得 ChildProcess.pid 严格相等；消息 writerId 与各自原 input 匹配。每个 child 自己 writer file 在 sealed 时不存在，appended 后原文件完整 canonical bytes 与原 event 相同；actual receipt 无 Cuts，local Current 含原 pending binding、无 receipt。
- 原子事实：最终目录恰三份完整 canonical single-fact writer bytes（seed + 两分支），无额外 intent/cut；cold 前后整个目录名字与 bytes 相同。没有把 JSON parse 后形状当字节证据。
- 独立 cold：另用原 runVerificationToolProbe 启动新进程，pid 不同于父/协调者/两 writer；新 WriterId 不创建文件。原 store.read 取到全部三个原 DTO；heads 恰两分支 id，head=null；原 canonicalCurrent 全 DTO 恰 `{ok:false,error:{code:'DomainConflict',stream:同原stream,heads:两id}}`，不是仅匹配 error.code，不接受 StorageInvalid/semantic cut/任选赢家。
- 正负控：seed/各分支 local Current 可读是正控；合法并发得到 DomainConflict 是限定的边界事实；exactduplicate 零新 bytes。changed-same-id collision 已有 sphinx019 正式叶，验收选完整019，不在 C0 复制。

## 子进程所有权与失败收尾

test worker → 原 runVerificationToolProbe → 原 monitor → selected coordinator → fork children。后两 children detached=false，继承 selected group；原 monitor 仍对 group 有完整回收职责。没有第二 monitor/资源 registry、ps 扫描或从 pid 文本构造 kill。

coordinator 正常路径必须两个原 child close 都 code0/signal=null；失败 finally 只对自己创建且未结束的 ChildProcess.kill(SIGKILL)，再 await 各自 closed。所有 stream/protocol failure 在 close 后仍拒绝；cleanup 异常保留而非覆盖主失败。test t.signal 传入原 probe，取消由原 lifeline 触发整组回收。不能把原 monitor 的 cleanup 退出误称生产并发成功。
