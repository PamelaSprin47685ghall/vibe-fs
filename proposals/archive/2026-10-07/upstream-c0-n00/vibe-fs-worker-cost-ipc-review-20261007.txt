Current causal chain
1. Watchdog is constructed before spawn(inner). Its constructor records now and
   arms the 300ms first window. file-start and worker-cost do not renew it.
2. The fixture waits for the first 10ms interval before any cost send; every send
   callback writes and renames a receipt synchronously. count is incremented in
   that callback, while payload selection happens in the interval callback.
3. Consequently count===1 does not define a strict second-send ordinal when send
   callbacks are delayed. Multiple sends can select the same payload state.
4. A successful process.send callback only establishes sender/channel completion;
   it does not certify receiver dispatch or the supervisor's subsequent handling.
5. The production cost branch validates and records evidence, and returns before
   watchdog.advance. Once invalid, later valid snapshots cannot repair it.

Smallest useful fixture change, with the existing first window retained
- Do not alter production supervision, silenceMs=300, 0-blocking assertion, active
  file expectation, failure code, or actual PID/group cleanup assertions.
- Replace the initial timer-dependent selection with an explicit, serial prefix:
  valid missing snapshot; malformed extra-field snapshot; valid missing snapshot;
  valid missing snapshot. Call the first send immediately. Start the next only
  after the previous real send callback and receipt publication have completed.
  Preserve sender sent>3; publish actual counts/payload ordinal in failure output.
- After the prefix, retain a 10ms background stream of valid missing snapshots.
  Serialize it so delayed callbacks cannot select or reorder the intended prefix.
  This removes unnecessary precondition latency; it is not proof of the unique
  cause of the historical failure and cannot guarantee native scheduling in 300ms.
- A four-frame initial burst alone is insufficient evidence of continuing traffic.
  Keep/add receiver-side evidence of at least one actual subsequent frame. In the
  generated launcher only, observe the real ChildProcess message boundary without
  replacing messages or emitting acknowledgements. A forward-first emit observer,
  filtered to the actual spawned inner PID and exact fixture entryFile, can retain
  the received prefix/full payloads in memory after the original listeners return.
  This uses an existing native boundary and needs no production callback/API.
- Freeze that receive trace at the original WATCHDOG diagnostic, rather than at
  eventual process exit. Late IPC during termination must not satisfy the traffic
  precondition. A narrowly scoped forward-first console.error observation of that
  exact watchdog line can snapshot the in-memory trace; it must neither feed the
  watchdog nor defer the diagnostic. Restore hooks in launcher cleanup.
- Assert the exact received four-frame prefix plus >=1 later valid frame BEFORE
  the diagnostic, followed by the exact invalid snapshot in the diagnostic. Those
  observations jointly prove that invalid evidence was consumed, later valid
  traffic was consumed, it did not repair invalid state, and it did not renew the
  original silence window. Receipt writes can occur after supervision completes;
  per-frame filesystem logging in the receiver is unnecessary.

Prohibited shortcuts / boundaries
- Waiting for ready or the first IPC before constructing/resetting the watchdog
  changes the first-silence origin and violates WHAT 006.
- Treating ready/file-start/diagnostic receipt as a blocking verdict likewise
  changes the original criterion; a fabricated test:pass is not actual progress.
- Raising 300ms, lowering sent>3, accepting only the initial burst as continuing,
  skip-on-readiness-failure, or rerun-until-green weakens the frozen acceptance.
- A real completed preliminary test would be genuine progress, but adding one
  here changes the existing zero-blocking scenario; it is a different test, not a
  repair of this case's original criterion.
- If startup or delivery still fails to establish the prefix and continuing frame
  within the original window, report a failed fixture precondition with receipts.
  Do not call that production renewal failure or a passing verification.
- This proposal adds native adapter evidence; deterministic clock tests remain
  the authority for exact first-window and renewal timing. It does not establish
  arbitrary cold-start reliability under every physical scheduling condition.
