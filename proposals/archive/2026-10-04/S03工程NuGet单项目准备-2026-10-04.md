## 本批实现与真实对象

owner 先用选定 SDK 实际执行 MSBuild evaluation。只接受单一 `net10.0` 且没有 ProjectReference 的原 F# 项目，不将不支持的项目图静默缩减。此次真实集成选用原 `src/Wanxiangshu/Wanxiangshu.Owner.dispatch-protocol.foundation-identity.fsproj`，保留原 project、两层 `Directory.Build.props` 与 `global.json` 字节；不据此宣布全仓工程图已封闭。

恢复所需的四包为 Fable.Core 5.0.0、FSharp.Core 10.1.203、FsToolkit.ErrorHandling 5.2.0 和 Thoth.Json 10.5.1。归档由调用方以明确路径和 raw SHA512 选择；owner 一次读取核对后写入私有 feed。明确包身份不等于认证发行者，不能把旧用户缓存或诊断中的源地址认作本批来源证明。

HOME、CLI、NuGet cache 与临时目录均私有。实际 restore 使用私有 NuGet.Config、唯一选定 feed 和独立 ArtifactsDir；显式禁用外部附加源、fallback、SDK 隐式 library-packs feed 以及 targeting/runtime pack 下载。随后核对实际 assets 的 sources、config、packageFolders 和 project path，任何外借或未选包均拒绝。

## 两次实际 restore 与两种包身份

第一次 restore 从原 project/props 解析并生成自有 `artifacts/packages.lock.json`。这是本次选定输入的派生 lock，不是源码已经提供的 lock，也不修改源码中的版本下界。验证首次实际 graph 后清空私有 packages cache，选定 SDK 再执行 `--locked-mode --force`；第二次必须保持 lock 原字节和完整 graph。它证明该有限输入在新包缓存下复验，不证明任意浮动源或全仓项目的可重现性。

阶段之间先验后行：MSBuild evaluation 结束先复核 source/SDK；第一次 restore 结束先复核原输入、完整普通输出库存、选定 feed/config 字节与成员，再检查实际 graph。首阶段的外借 outputPath、非法 library/compile/runtime 形状、越界依赖或 target/lock 依赖声明不一致必须拒绝，不能先删 cache 或启动第二次 restore 再报错。第二次结束仍复核这些边界，成功后才发布 receipt。这里对依赖边做的是选定 ID 边界与实际 target/lock 声明一致检查；版本范围的求解由真实 NuGet 负责，不在 JavaScript owner 中重写 semver 或另造解析模型。

包身份分别核对：

- 完整恢复 nupkg 的 raw SHA512 及 `.nupkg.sha512` 必须等于调用方所选归档的完整字节摘要。
- assets 的 library sha512、lock 的 contentHash 与 `.nupkg.metadata` 的 contentHash 必须一致；metadata.source 必须是该次自有 feed。
- raw signed nupkg SHA512 与 NuGet contentHash 是两个身份，不能互相代替或要求等值。真实四包回归分别断言它们。

实际 assets、lock、cache 与选定集合须完整相等；compile/runtime asset 及 library 文件必须为自有普通文件。receipt 绑定 sourceDigest/treeId、sdkDigest、原项目路径、选定归档集合、完整 graph 与输出库存。公开 `revalidate()` 同时检查原输入 owner、receipt 字段和全部输出目录模式、文件字节及成员集合；dispose 只释放本次工程输出。

## 源码准备补齐与验证边界

源码准备现在从 canonical parent 分配真实自有根；完整普通库存包括 Git metadata，公开 receipt 字段也参与复核。改源码字节、权限、增删成员、变更 root/digest 声明或父目录链接换向不得借用原身份。此处是发布和复核边界，仍不能发现过程内改后恢复，也不授予只读执行能力。

正式轻量用例覆盖缺失/非普通输入、归档摘要错误、原 props/project 变更、非单目标或 ProjectReference 拒绝、实际执行失败、Error/null 取消、进程排空和各自资源回收。独立真实 integration 明确选择 tree、完整 SDK 及四个包归档，核对原输入不变、完整 assets/lock/包库存、raw/content hash 区别、移除夹具归档后的 revalidate 与按所有权清理。最终数量、原始红绿日志、选定身份和统一门禁结果只见[本批验收记录](baselines/2026-10-04-nuget-project-acceptance.txt)；未结束的运行不算通过，也不从轻量进程替身推出真实 SDK restore 成功。
