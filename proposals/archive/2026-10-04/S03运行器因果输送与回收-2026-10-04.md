## coverage：父进程可以响应真实子进程

`scripts/coverage.mjs` 原来以 `spawnSync` 等待 unit runner 和 c8 reporter。正式 011 的子进程在继续实际工作前向同一父进程发 HTTP 请求；父进程被同步等待阻塞，无法回答，两个真实路径均死锁。修复用薄的异步 spawn/close 等待，父事件循环可以响应；silent 输出仍排空，继承输出方式保持，真实覆盖率分母与完整报告断言不变。红例分别保存在 `/private/tmp/vibe-fs-coverage-runner-permission-red.log` 和 `/private/tmp/vibe-fs-coverage-reporter-permission-pattern-red.log`，修复后的实际 HTTP 回归见 `/private/tmp/vibe-fs-coverage-effects-focused-green.log`。

另一正式红例让真实 c8 完成报告后收到 SIGTERM。旧实现只看报告及 status，误报成功；现实际 signal 必须拒绝，返回 `C8_REPORT_ERROR`，不能拿已经落盘的报告覆盖进程失败。原始红例见 `/private/tmp/vibe-fs-coverage-c8-signal-single-red.log`。

异步改造还暴露 stdin 兼容边界：旧无 input 的同步调用给子进程 EOF，新默认 pipe 却未结束 stdin。两个正式 wrapper 先读完整 stdin 并核对零字节，再运行真实 runner/c8，旧改造分别约 5005/5003ms 等待失败。silent 改为 `['ignore', 'pipe', 'pipe']`，inherit 保持原语义；并未放大等待窗口。红例见 `/private/tmp/vibe-fs-coverage-runner-stdin-red.log`、`/private/tmp/vibe-fs-coverage-reporter-stdin-red.log`。最后完整 011 定向为 18 passed、0 failed，1/1 文件排空，原进程组回收 accepted；日志 `/private/tmp/vibe-fs-coverage-whole-011-stdin-green.log`。这是 011 的证据，不是统一选集结论。

## supervisor：失败先收口，再交还调用方

原 watchdog 的默认 terminate 直接退出调用进程，越过 caller 的 catch/finally；被杀的 inner 也不能再承担 HOME 清理。supervisor 现在拥有本次 inner 的独立 HOME，传给 inner 使用；静默失败先有界终止、观察退出并核对原进程组，再回收 exact HOME，最后才向 caller 交付失败或执行外层退出。正式 006 从真实 caller catch/finally 核对 inner/file PID 已退出、HOME 已消失及 caller 清理标记；红例 `/private/tmp/vibe-fs-s03-silence-runner-home-red.log`，含原有 backstop 诊断的定向绿色 `/private/tmp/vibe-fs-s03-silence-runner-home-green.log` 为 3/0。

同步 spawn 抛错必须停止 watchdog 并保留原 TypeError，不能留下稍后触发的终止回调或 `finishExit is not a function`。standalone inner 只清自己分配的 HOME；调用方提供的 HOME 及其标记必须保持。正式原始红例 `/private/tmp/vibe-fs-s03-supervisor-owner-errors-red.log`，修复后对应 3 项通过、0 失败，见 `/private/tmp/vibe-fs-s03-supervisor-owner-errors-green.log`。

真实 suite 失败后再让 HOME 的母目录不可访问，清理失败必须拒绝，并同时保留原 verdict 和 cleanup cause。单个原异常不丢失，复合失败以 AggregateError 保留 cause；原值为 null 时也不能用真假判断吞掉。权限反例不伪造 Windows 或 root 用户的访问失败。单项红绿见 `/private/tmp/vibe-fs-s03-supervisor-cleanup-cause-red.log` 与 `/private/tmp/vibe-fs-s03-supervisor-cleanup-cause-green.log`。此前完整 006/021 定向截面 45/0 见 `/private/tmp/vibe-fs-s03-supervisor-home-full-green.log`，不替代随后新增场景或本批统一输入验收。

physical backstop 的 active/queued/drained 和 lastVerdict 诊断沿已有 fileWaits 输出。300000ms physical backstop、5000ms verdict-silence 与默认 workers 都未调整；stdout/stderr/diagnostic 仍不能充当判决进展。原进程组核对和 HOME 清理只证明这些 exact owner 的收口，**不证明全部 descendant 已回收**。
