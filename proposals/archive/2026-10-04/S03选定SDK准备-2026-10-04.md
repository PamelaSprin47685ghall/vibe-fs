# S03 选定 SDK 准备

本批接续 `3628b5cba`，只完成明确归档身份的 .NET SDK 准备与真实选择探测。产品边界仍来自 verification-system WHAT016；T418/T419 与 GAP-055 保持未闭合，不将准备 receipt 当实际验证证书。

## 已施工边界

`prepareVerificationDotnetSdk` 接受完整 SDK tar、明确 SHA-256、源码根与预期实际 SDK 版本。共用完整归档物化规则，拒绝越界链接、非法成员、摘要不符及不合规可执行角色。捕获原始 global.json 字节，拒绝源码根或文件链接，以及额外 SDK 搜索位置；不改写仓库的 SDK 选择配置。

在自有 cwd、HOME、CLI_HOME、XDG、临时与 NuGet 缓存目录下，使用绝对候选 dotnet 路径运行 `--version`、`--list-sdks`、`--list-runtimes`、`--info`。实际 SDK、Base Path、全部报告的 SDK/runtime 目录与 global.json 路径相互核对；所有 SDK/runtime 路径须属于选定归档，拒绝包装器借用 live SDK。探测后检查私有 global.json 字节及完整候选库存，再回收探测目录并发布 receipt。

receipt 的 sdkDigest 绑定归档、完整成员、原 global.json、dotnet 字节、实际 SDK 和 runtime 身份。发布的 revalidate/dispose 仍属于同一个归档 owner。Node/npm 与 SDK 共用已有有界工具探针，原输出限制、POSIX 进程组终止、管道排空及 Error/null 取消原因保留。

## 实际证据

正式 016 增加轻量公开失败用例与显式 SDK integration 入口。缺可执行角色、归档摘要不符、非法路径/链接、无执行权限、实际工具失败、版本不符、借用外部 SDK，以及启动前/真实挂起探针的 Error/null 取消均分别观察；取消验证实际进程与后代消失、自有 root 回收。入口尚不存在时的失败日志只是 API 施工前红证，不冒称旧生产行为缺陷。

真实正例完整捕获 `/opt/homebrew/Cellar/dotnet/10.0.302/libexec`，包括 SDK、packs、shared、host、templates、library-packs、sdk-manifests 与内部链接。原 global.json 的 `10.0.100 / latestFeature` 实际选择 SDK10.0.302，两个 runtime 为10.0.10；这是 CLI 的实际选择，不是自造版本解析器。选择规则参见 [SDK 官方文档](https://learn.microsoft.com/en-us/dotnet/core/tools/global-json)。完整库存为5,588成员、688,059,912文件字节、331内部链接。最终逐文件字节、模式、路径及链接的独立断言和回收结果，随本批日志归档。

初次真实正例4报告项通过（父组及三个有序叶），轻量14报告项通过；完整 SHA 库存断言补齐后，最终实际入口与正式受监督选集分别验收，实际计数、原始日志及构建身份见[验收记录](baselines/2026-10-04-sdk-acceptance.txt)。不把 native 定向入口换写为全量 integration 或 release 通过。
