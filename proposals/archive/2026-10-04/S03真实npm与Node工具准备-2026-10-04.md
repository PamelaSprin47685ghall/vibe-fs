## 安装来源

`installVerificationDependencies` 一次读取选定 package.json/package-lock.json 字节，在自有工作目录执行真实 `npm ci --ignore-scripts --include=dev --include=optional`。Node 字节复制到私有入口，Node/npm CLI 明确 SHA-256 与实际 npm 版本均须相符。packageManager 不匹配、workspace、file/git/link 来源、锁外 registry URL、缺完整 integrity 等均拒绝。递归 overrides 同样检查，不能借 override 绕过来源边界。

HOME、XDG、临时目录、npm 配置与缓存均独立；继承环境中的 NODE_OPTIONS、NODE_PATH、PATH、npmrc、cache、prefix 不成为执行权限。registry 限 HTTPS 或本地 fixture HTTP；这是 lock 中 resolved authority 的检查，不是 HTTP 重定向防火墙。

成功后复核 package/lock 未变，按 lstat 枚举全部 node_modules，包含隐藏成员、权限、字节和链接，拒绝 hardlink/特殊文件。归档再独立物化；完整实际安装清单必须与候选清单一致，不能依赖 tar 静默跳过成员。receipt 绑定原 package/lock、归档与安装身份。私有安装目录先回收再返回独立候选。

该入口的 npm CLI 仍从调用者选定路径启动；其摘要只代表 bootstrap 准入，不覆盖整个 npm 包运行期间的不变性，receipt 明确使用 `bootstrap-admission`。禁用 scripts 不代表 native addon 或 OpenCode 平台安装已经可用。正式 fixture 使用实际可用 npm 11.18；本仓声明的 npm 11.12.1 尚未由这一批执行安装。

## 工具与归档

`prepareVerificationNodeTools` 接收明确摘要的 toolchain 归档，独立物化完整 Node/npm 成员。Node、npm CLI 及 npm manifest 的角色必须是真实文件；Node 必须可执行。实际 Node 版本、平台、架构以及 npm 版本均从准备目录探测，npm 版本须与 bundle manifest 一致。探测结束重新复核全部目录、权限、文件摘要和链接目标，拒绝工具探测自行添加文件后仍返回成功。

工具 receipt 使用 `selected-node-npm-bundle`，摘要覆盖全部选定成员。这不证明官方分发来源、OS 动态库、Git、SDK/runtime/packs 或 NuGet 已被封闭。准备目录与 receipt 仍可写；结束时复核也不是阶段内 write/restore 的证明。

追加实际借用反例发现，Node 的父目录查找会让缺失的 npm 库从 candidate parent 的 node_modules 被补上，私有 HOME 与空 NODE_PATH 不能阻止它。工具现在按真实 package manifest 递归检查声明的必需生产依赖，查找范围止于所选 npm 根；直接 graceful-fs 和传递 @gar/promise-retry 缺失均明确拒绝。optional 声明缺失允许，已存在者继续检查。这是声明生产图的有限闭合，不是全部动态 module 加载、绝对文件读取或 OS 闭包证明。

归档 owner 抽为共用实现；原依赖归档 owner 的公开行为与摘要规则保留。完整 tar/gzip、终止块、成员图、内部相对链接及独立物化规则不削弱。复核保存独立预期清单，调用者修改公开 entries 不改变内部判据。
