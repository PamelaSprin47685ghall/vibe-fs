# Host023 真实 canary 的监督修复

## 原失败

63 文件正式选测得到 333 通过、1 失败、3 跳过、28 TODO，全部计划文件完成。唯一失败发生在 Host023 业务检查之前：工作树的 `opencode-ai` 没有执行 postinstall，本地入口仍是 479 字节提示脚本，启动返回 ENOEXEC。日志 `/private/tmp/remainder-sphinx-host-speculative-formal.log`。

同一工作树已安装真正的 darwin-arm64 二进制，实际 `--version` 为合同要求的 1.18.29。通过既有 `OPENCODE_BIN` 指向它，023 的原单个同步 canary 被 5 秒无 verdict 监督终止，未产生业务断言结果。日志 `/private/tmp/remainder-host023-real-binary-formal.log`。没有增大预算、放宽版本或改到未启用层级。

原 ProcessHost 创建独立进程组，因此外层强杀 runner 组后留下该次 Host。已通过 PID、PGID 和唯一临时 workspace 确认归属，只终止本次残留组并复核退出。随后 Host 向已关闭 collector 发送观察产生的连接错误属于监督终止后的结果，不能冒充原业务失败。

## 修改

023 保留活动入口和最终完整 evidence 断言。专用 canary 改为异步执行同一 Host 生命周期，依次提供六项可独立断言的实际观察：安装版本、Host 健康与会话建立、公共 hook 到 provider、助手开始与终态到 idle、重复投递、Hook 拒绝。

每项观察由顺序的 Node 子测试进行实质断言，测试运行器自然收到 verdict。没有 stdout 心跳、重复日志续期或新增通用进度协议。原五秒静默窗口与总监督设施未改。

ProcessHost 的可选 `detached` 沿创建与停止路径传递，默认仍为 true；仅023选择 false。准备阶段用实际 `ps` 结果断言 Host 和测试进程属于同一进程组，Host 没有另起组。普通停止只处理自己的 Host 与已枚举后代，保留端口与泄漏检查；外层硬终止可以同时回收该监督组。

这些追加修复及证据范围会在最新统一构建后完整复验，最终结果见[兼容验收记录](20模块兼容修复与验收-2026-09-28.md)。物理证据来自macOS，CI为Linux；新增组核验明确不支持其它平台，不以跳过检查返回true。此前Windows纯用例可能正常退出，新入口会因缺少该核验而拒绝；这是可移植性变化，不是等义重构，未声明Windows验收。
