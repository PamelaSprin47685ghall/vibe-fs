## N1：先修验收入口

依据 E03/E04、distribution-007 和 verification-system-016。最后完整 release 在 255/870 个文件后触发 5000ms verdict-silence，没有权威总计；这是待诊断失败，不先认定只是慢机器。

1. 固定同一候选，比较 distribution-007 原生运行、正式监督和最小前序组合；定位到具体测试及输入采集、嵌套验证、子进程或收尾阶段。只记录能区分原因的阶段证据。
2. 按归因修实际工作或夹具。长的真实物理操作若确实符合既有有限等待合同，使用 begin/end ACK；纯计算或无进展挂起不能申请假等待、打印心跳或放宽默认静默门。
3. 核对 Node26 复制夹具为何遗漏动态 libnode。先保持安装器测试的真实目的，再采用完整运行时或能覆盖动态依赖的真实夹具；不伪造 Node 成功、不把该运行时整组跳过。
4. 定向运行 distribution-007、verification-system-016 及实际受影响监督条款。N1 收束后运行一次完整 release，记录后续第一个独立阻断；旧 TODO 仍使正式验收不通过，不能为“全绿”接受 TODO。

验收：原失败反例转正；恶意 pre-import 挂起仍被拒绝，未知收尾仍保留；完整文件汇总与 owned 回收可核对。完整 release 若还有别的旧问题，报告新边界，不把它变成本包无限清账任务。

## N3：资源关闭必须落到真实事实

E02 归本包。选一个当前仍存在的 Host 调用链，组合 Ownership、Journal、Process 与 Work；不将 abandon 投影当物理退役。

## 两仓交付与停止条件

每包先保存反例和合同，再手工修改。独立库的规则/测试与实现同目录，主仓沿用 WHAT 编号。构建只用 `node scripts/build.mjs` 或仓库正式 Fable 入口，不用 `dotnet build`。

涉及库修改时：在 `codex/` 分支按包提交 → 相关库测试和独立构建 → 精确 npm pack/仓外安装及声明消费 → 普通快进推送自有 `origin/main` → 核对远端 SHA 可获取 → 主仓更新确切 gitlink/真实调用方 → 主仓相关 requirement、包消费 → 普通推送 `origin/master`。独立库工作区与子模块随后仅快进同步；禁止 force push、把未推送库提交写进主仓或用邻仓源码兜底。

基础纯计算按实际支持运行时检查；进程、SQLite、输入输出和包消费覆盖相关 Node/Bun 物理路径。Linux 证据只在实际 Linux 环境取得，无法执行则写清未测，不借 macOS 通过推断。

每包记录源 SHA、包摘要、运行时、通过/失败/skip/TODO、实际物理收尾及未覆盖项。互相重叠的套件不相加，原始红日志不覆盖。小的边缘问题可留档继续；期限失守、取消失效、数据损坏、历史误读和权限放宽阻断受影响包。

不扩大到 Blogger 全退役、清空 `.Herdchestra`、旧 GAP 清零、任意新模块抽取、第二宿主重建或通用恶意 JS 隔离。运行部署另记：源码已提交、远端已同步、验证已通过、运行已切换是四个不同事实。
