# 可复制的施工单

返回 [看板](BOARD.md) / [操作指南](README.md)。下面都是模板或示例，不是已认领、已批准或已运行的事实。

不用把所有模板都建成单独文件。一张实际卡用一个 `cards/CUT-NN.md` 即可；证据较多再用 `evidence/CUT-NN/README.md` 索引原日志。不得把完整测试日志里的密钥、用户私有原文或环境凭据提交进仓库。

## 3. CUT-02 的填表示例

**这是建议的首个子范围，不是已经实施的结果。**

```text
目标：把一个现有非 PTY run 调用链的进程启动/管道/退出移交 ProcessSession。
不做：PTY；模型蒸馏；全仓进程 API 重命名；取消现有硬期限/输出外存。
A：ProcessSession，真实进程及管道，有界内存与独立等待。
B：现有输出外存和归属 owner，暂时留在旧侧，C 分别调用。
C：单次运行组合，校验期限/预算，启动、持续排空、申请取消、观察真实退出。
状态：A 的真实退出不由 C 的计时器填写；C 只拥有等待/结果关联。
新事实：无，不为此次内存/物理替换改持久化格式。
反例1：期限到、TERM 被忽略。等待可结束，归属仍不能被报为已终结。
反例2：连续大输出。不得堵管道或丢掉 WHAT 要求的完整外存。
反例3：父退出但后代占管道。Closed 不能过早出现。
删除：所选真实调用者不再经过旧 NodeProcessHost/NodeProcessWait；
      只有 grep 和调用链均证明无其他消费者，才删除对应文件。
暂留：Pty*；Spool；LargeGate 中仍有消费者的规则，分别链接 CUT-20/21。
独立验证：ProcessSession 在没有 Work/Journal/Trace/Ownership 产物时仍可使用。
组合验证：测试调用原 run 入口，不是只在测试里手工创建 ProcessSession。
```

若实际调查发现一个当前 run 的强制保证尚无人承接，先补完整职责；准备阶段拆出子卡时，父卡仍须保留未完成义务。不能把保证扔掉后宣称“库很好用”，也不能在验收失败后自行缩小承诺换取 DONE。

输入标识：源码、工具、锁、资源、生成语料、manifest generation

pass / fail / skip / TODO / cancelled / failed containers：
哪些 skip 是层级未启用，哪些是平台或缺环境：
原始日志位置/可复取 artifact：
四类证据索引：真实消费者 / 公开产物 / 关键反例 / 旧职责退出
用例证明的是：
用例不证明的是：

反例是否先观察到失败；失败是否确由被测行为造成：
若原实现已正确，保留何种正控/隔离变异，不伪造业务红：

结果缺失写 `未取得`，不是 `0`。不要把真实 Node/Bun 两次结果相加说成双倍覆盖，也不要把同一用例在库、主仓和集成层重复计数当新增证明。

## 6. 卡完成检查

拆分/接收卡须先填写[交付清单的四类证据收据](UPSTREAM-DELIVERY-CHECKLIST.md#delivery-receipt)，每项指向具体候选、命令和观察结果；仅勾选以下方框不能代替证据。四类证据、适用风险门禁、非作者复核及最终集成核验全部通过，才能标 DONE。

- [ ] 这项职责的库能独立理解、构建、运行、验证；没有反向依赖或模拟兄弟调用脚本。
- [ ] 真实打包安装使用同一份被验证字节，类型与公开 JS 入口一致。
- [ ] 旧系统真实使用新能力，主线有明确接线 commit。
- [ ] 新旧状态不双写；旧实现、过期项目引用和已替代路径已退出。
- [ ] 剩余路径有真实理由和独立卡；历史数据及在途效果不会失主。
- [ ] 成功/拒绝/重复/未知/恢复及必要物理边界有证据；未证部分没有算通过。
- [ ] 相邻 reviewer 核对了公共协议、共享文件与能力/身份边界。
- [ ] 与集成时最新 master 比较有净改进；没有放宽 gate 换绿。
- [ ] BOARD、单卡证据、COVERAGE 和对应正式条款映射同步更新。
- [ ] 工作树干净与否、已提交/已推送/已合入、运行进程分别如实报告。

不涉及的检查细项写明契约理由及复核结论，不能默默跳过，不能将四类必要证据整类记为“不适用”。相关失败、未运行、TODO/skip 或失效候选均保留为未通过。大型主卡分子卡时，子卡完成不自动关闭父卡；事先定义的调查/原型成果也不代替生产迁移验收。

## 8. 常见异常怎么处理

| 现场情况 | 处理 | 禁止 |
|---|---|---|
| master 或 lib main 前进 | fetch、比较实际接口/语义变更，在自己分支建立新候选，受影响部分重验 | 把旧验证 SHA 改成新 SHA |
| 两人改到同一公共文件 | 暂停该文件写入，协调者决定一次接线；保留两边分支与已验证行为 | `checkout --theirs` 一把盖掉或强推同伴分支 |
| 库协议不足 | 提交契约差异与反例，约定最小完整扩展；此卡可保持 BLOCKED | 注入旧 Context、加隐藏源码导入或默认成功 |
| 只有全量失败 | 保留完整失败原件，定位到文件/实际边界，补窄反例，再验证完整候选 | 无限重跑直到偶然绿、降低测试预算、扩大 skip |
| 旧存储坏、另一 work 好 | 正常业务仍拒坏历史；恢复按明确 owner 隔离失败，继续独立工作 | 删除坏行、重写历史、吞异常装成无事发生 |
| 外部效果结果未知 | 查同 operation/实例的可信证据，保留原归属与记录 | 以 timeout 或找不到 session 直接授权再执行 |
| 提交结果未知 | 重开对应存储、核对同 request/record，未确认前不发布新效果 | 把候选内存状态当 durable commit |
| cleanup 失败 | 保留原错误与清理错误、精确资源身份，交给该资源 owner | 全局 pkill、清空共享数据库、掩盖最初失败 |
| 工具/环境导致无法验证 | 明示命令、错误与未证范围；准备可复跑输入再交接 | 宣称已完成、用替身冒充真实环境 |
| 合入后发现回归 | 保持可追溯的新修复/显式 revert，先核对新数据与在途效果 | reset 公共主线，或假定代码回退能撤销物理行为 |

对无法解释的现象保留原件，比编出一个“已经解决”的故事更有用。认领人承担把自己的工作交成完整能力的责任，协调者承担让这些能力有序进入同一主线的责任。
