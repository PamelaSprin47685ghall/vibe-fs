# CUT-00-R1：正式验证的有界物理等待

基线主仓 `c385b8fab`，独立库保持 `8bb1021 / 0.6.12`。交付候选为构建 689；本包只改验证设施和物理探针调用点，不改产品、库、持久事实或 PTY 终态规则。

## 结果与合同

正式入口完整执行 verification-system 005/006/008/010/021、process-execution 003 和 managed-session-lifecycle 025：**321 pass、0 fail、0 skip、0 TODO**，7/7 文件完成并排空，内层正常退出，自有进程组核查通过。最低支持版本 Node 22.13 的完整 006 由非作者独立执行：**84/0**，输入哈希稳定，原生事件和完整汇总保留。

默认静默窗仍为 5000ms。真实 PTY 的 5.3 秒等待及约 7.9 秒重启矩阵由具体调用声明有界操作，收到外层确认后才开始。每次真实 TestContext 只可申请一次，绝对截止至多 30000ms，end 不续期或清除截止；只有匹配的真实 native complete 才结束许可。其他活跃文件保留各自截止，所有晚到转换先检查是否已经过期。

`NativeTestSupervision` 统一持有文件生命周期、原生调用及截止。旧 `createFileWaitTracker` 和正式入口的第二套 Watchdog 时钟退出；通用 E2E Watchdog 保留原用途。可信 inner 给真正 dequeue/complete 事件分配单调序号，只有 complete 推进时钟，pass/fail 仅参与统计。没有 dequeue 的原生 skip/abort complete 仍可正常消费，不把 testNumber 或名字假作唯一原生 ID。

许可初版只授予能唯一绑定的顶层普通调用；嵌套或并发重名请求拒绝。beforeEach 预登记 context，生命周期结束时封存；旧未用 context 和伪造副本不能绑定下一次同名调用。丢失、拒绝、迟到 ACK 不执行操作、不重发；操作与 end 同时失败保留两者及原 cause。

外层为每个入口分配私有 socket、随机执行身份及能力。inner 核对分配的父进程，preload 在加载 node:test 前核对入口、主线程与实际父 PID。普通同入口或不同入口 fork 继承导入时不初始化测试设施。文件排空立即关闭通道，最终 finally 仍确认全部清理；关闭幂等。

## 验收证据

证据、脚本、原生事件、源码快照和清理记录见 [归档目录](evidence/CUT-00-R1/README.md)。主要复验：

- 真实监督：无限物理等待、end 后挂起、另一文件静默、旧 context、伪日志、同步突发、缺 summary/drain、TODO 和失败保持；反控均非零退出并检查自有收尾。
- 真实 ACK：拒绝、丢失、迟到、context 关闭、错误执行身份和非布尔确认均不执行 callback；end 丢失不重发且保留原异常。非作者另验证了本地 timeout 回调尚未调度时的 elapsed 拒绝。
- Node 26.6 与 22.13 的真实原生输出分块反例；六种正文输出、预先缓存 canonical Console、普通继承进程输出精确保留。直接写协议 fd1 或继承原生协议描述符不属于诊断 API。
- 文件间实际 socket 释放、重复 close、子进程 PID、HOME、原生汇总和进程组退出。
- 构建 689 及静态门禁通过；526 条既有 report-only 提示不计本包关闭项。临时安装的 680 公开包所含 **2904 个文件**与当前对应文件逐字节一致，库工作树干净。

本包通过 Git 分发验证设施，npm 产品字节和公开类型没有变化，未发布 registry 或部署 Host。后续文档收尾构建不改变上述已验运行代码。没有用户数据迁移。

## 后续复核：相邻调用的双通道竞争

G140-B1 的700相关142文件中，008的第四个有界探针在4ms即被拒为重复申请，物理 child 尚未开始。实际顺序是前一用例收到 end ACK、下一真实 TestContext 已开始，socket begin 先于上一用例的 native complete 到达。689的模型一直保留旧 allowance 至 complete，却把这时的合法新请求也当成重复；这是本代理先前R1修改引入的竞态，不归G140产品。

补修只允许一个新token暂存，旧 allowance 未end时仍拒绝；只要旧 allowance尚存，bindPending就不授权。旧绝对截止不变，匹配native complete清除后，下一次真实dequeue才能授权。同名下一用例、重复token、单pending、缺complete到期均有永久反例；前两项原红保留。

非作者以真实node:test上下文和Unix socket控制原native事件的交付顺序，在Node26及实际最低Node22.13都重现旧NACK/第二action不执行，新版则两个action执行且无native失败；没有合成native事件。另10组边界两runtime通过，包括不预借额度、不续期、跨文件截止、取消、嵌套和终止拒绝。首版额外假设summary扁平字段的夹具红单独保留，已按实际native事件校正，不归实现。
