## 实际修改

1. **补齐真实编译边界。** 按源文件实际依赖修复 owner 引用与先后顺序；给歧义字段补明确领域类型；公共清单按现存源和正式 owner 手工同步。详见[认知、持久化与委托记录](构建闭包修复-认知持久化委托-2026-09-28.md)与[Sphinx记录](20模块兼容修复-Sphinx集成-2026-09-28.md)。
2. **完成插件的既定协议迁移。** 当前 speculative-investigation WHAT 是 Shadow、DryRun、Treatment，不再定义 `delegate_readonly_rounds` 或 `self_note`。插件还调用上游已删除的 StrengthDelegate 与 ProtocolArgumentVault；改为当前 `StrengthSpeculate.tryApply`，保留普通请求的投机位置、前缀隔离及 Replica 路线。撤掉旧 schema 装饰、capture、vault 恢复及无其它调用的 ToolSchemaJson/ReadonlyDelegationContract；Manager review 的 contract 隐藏与同源恢复仍保留。历史 canary 原样归档并核对 SHA-256，不当新版本通过证据。
3. **适配真实模型租约签名。** `ModelRouting.tryLease` 当前第5参数是 lenderSessionId；两个调用删除已废止的 purpose 参数，保留 `None`。不新增角色或路由政策。
4. **恢复参数的完整顺序。** Manager review 隐藏 contract 前保存其位置，恢复时在同一对象上重排必要后缀，保留值引用与属性描述符。无法恢复的对象在隐藏前拒绝。正式回归先复现居中键、非枚举键与不可重排对象问题，再验证修复；真实 Host 完整证明仍保留。
5. **如实传播恢复写入失败。** ChildWorkRecovery 不再丢弃 journal append 的 Error，而抛出既有 JournalAppendException，停止后续结算。测试向真实 journal 注入不可用及 outcome unknown 的 writer，检查实际第一次追加、未改变投影及不声称成功；不是在接缝里复制结算。异步加载完成前的屏障仍归 GAP-149。
6. **修复真实 MCP 启动。** zString 的 Emit 需要 schema 与 description，原调用少传 schema 导致启动异常。补齐实参，并从真实 stdio 子进程验证初始化及七工具参数声明。工具业务 handler 未接 Runtime 的问题独立保留。
7. **在副作用前拒绝已废止身份。** 实际测试发现 Coder/Inspector 先创建子会话，到发请求时才被拒绝。先保留并运行“创建数必须为0”的失败断言，再把拒绝放在普通和批次共用的生产 admission；Engineer 正例及历史身份解码保留。
8. **保留 Host 的真实拒绝。** Sessions 的终止入口原来丢弃 AbortSession 的 Error。现在返回真实结果，缺少 Host transport 也明确拒绝。恢复许可接缝改为调用真实 FamilyRecoveryPermit，终止接缝驱动真实 managed termination，保留原先的成员单调性、身份和 drain 顺序断言。详见[Recovery 与 Sessions 记录](20模块兼容修复-Recovery与Sessions-2026-09-28.md)。
9. **测试通过正式边界消费状态。** context-compression 028 保留10个用例与有效断言，改为原生输入驱动实际 XWire、authority fold 和受控物料端口；不从 JS 拼内部 DU。durable-events 020 改为消费同一 store 的 Journal Current，保留损坏历史反例，增加空仓和合法重放正例。另八处控制嵌套只整理原有求值顺序、锁和异常边界，不新增扫描豁免；其中部分来自本批，不能全部归因上游。详见[控制边界与 Current 记录](20模块兼容修复-控制边界与Current读取-2026-09-28.md)。
