# 控制边界与 Current 读取修复

日期：2026-09-28。范围：统一静态检查剩余的八处控制嵌套和 WorkspaceEventStoreSurface 的历史读取越界。由主代理授权局部修复，不修改 WHAT，不新增扫描豁免。

## 归因

与 upstream `1450f49d` 对照，Fork Host 两处、JoinDrain 一处、SessionExecutionBinding 两处及 PluginRecoveryWiring 一处来自上游原有实现。ChatAdmission 的 malformed carrier 分支和 Grounding 的缺失路径解析来自本批迁入。WorkspaceEventStoreSurface 在该 upstream 基线不存在，已在首批提交 `83cd4bf` 中迁入，不能把这些问题全部归为上游遗留。

## 控制结构整理

- `Execution/Delegation/Fork/Host/Runtime.fs`：分别提取 durable 子会话收养和本地未登记时的 await 结果。保留先查进程缓存、未命中才读 durable 的求值顺序；收养仍只登记 dormant child，不接管当前进程的取消或 teardown 权限。
- `Execution/Delegation/Handle/JoinDrain.fs`：提取缺少 completion body 时的分流。Cancelled 仍进入原有真实消费路径，其它 lifecycle 仍使用原有缺失结果；不改变 read、decode、证明与 CAS 的顺序。
- `OpenCode/Host/ChatAdmission/Intent.fs`：将三个 carrier 名称的纯格式化独立出来，拒绝分类与输出文本不变。
- `OpenCode/Host/SessionExecutionBinding.fs`：提取 durable parent/agent 查询与缓存回填。辅助操作仍在原有锁内、仅在缓存未命中后执行，空白 agent 不写入缓存。
- `OpenCode/Plugin/PluginRecoveryWiring.fs`：提取同 Blogger session 与同 RequestId 的 live-flight 判断。子 run 结算、Blogger 结算、恢复信号的先后和异常传播不变；没有处理 GAP-149 的异步加载屏障。
- `Requirement/Grounding/Catalog.fs`：提取是否允许向父目录追溯的判断。仍先尝试 realpath，仅 ENOENT 的缺失路径可上溯；悬空 symlink、工作区外路径和其它读取错误不能因此获得覆盖。

这些改动只整理现有控制结构，不改变合同或合并不同生命周期概念。

## 消费 Current，而非读取历史头

原 `allHeadsCount` 只有 durable-events-020 一个调用，用来触发延迟激活，并没有验证头数量的业务命题。现在删除该 API，改为 `journalCurrent`：对获取的同一 store 调用 `TryCurrent("Journal")`，只投影实际 Current 的 session 标识，不读取历史、不自行 fold。

依据是 durable-events-019/020/022：业务读取 canonical Current，能力获取与实际消费分开。真实注册为 `CanonicalIntegrator.baseRules → JournalIntegration.rule`，初值是 `Fold.empty`；`AgentJournal.CanonicalProjection` 也从相同的 `TryCurrent("Journal")` 读取。

返回 `available=true, sessions=[]` 表示已初始化的空 Current；`available=false, sessions=null` 表示没有该 Current，不能把它解释成空历史。调用本身会消费并激活，返回值不能用于声称“仍未激活”。当前合法 workspace 程序固定注册 Journal，测试不伪造缺失注册场景。

020 保留 malformed retained history 在获取时不报错、首次消费才拒绝、失败不改写文件的反例，并增加两类正例：空仓首次消费得到真实空 Current 且不产生 writer；合法业务 append 后通过新的 workspace capability 消费同一仓库的 Journal Current，读到预期 session 且原文件字节和文件集合不变。没有新增 physical reader 或 allowlist。
