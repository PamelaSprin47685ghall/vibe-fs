## 口径与解释

- 冷读两边相当：首次都须全量解码。差异来自 WP-023 的进程内已解码前缀缓存——修后自第二次起 stat 精确命中直接复用（热读 4 ms vs 16.4 s，约 4000 倍）。
- 装载/积分为墙钟近似（store 打开、首次 streams），integrator 合并的精确分割未单独插桩；clean no-op、锁争用、目录解析三项本轮未测。
- 一致性：两边同输入文件、同 nowMs，`streams` 计数均为 201。事件级摘要（event_id 序列/整流哈希）因 `readStreamsAt` 返回结构非数组、harness 未适配而未采集，标未验证。

- 独立校验（不加载 dist，直接按行解析 ndjson 取 `event_id`）：`node /tmp/gap225/independent.mjs /tmp/gap225/wanxiangshu/events` → 同摘要、同总数、同每 writer 计数，malformed 0。三者逐 id 相等。
- 冷热：`node /tmp/gap225/harness.mjs repeat /tmp/gap225 1792140000000 5` → runsMs `[290, 1.2, 0.9, 0.7, 0.8]`，总 293.6 ms；5 次摘要全等。即缓存的第 2..5 次命中返回与首次全量解码完全相同的规范事件。

### 4. 目录解析 spawn/耗时 —— 已测（结论：每 workspace 每进程恰 1 次 spawn）

用 PATH 前置 git 垫片计数（`/tmp/gap225/bin/git` 记录 argv 后 exec 真 git）：

- `WXS_GIT_SPAWN_LOG=/tmp/gap225/spawn1.log PATH=/tmp/gap225-bin:$PATH node /tmp/gap225/harness.mjs resolve /tmp/gap225-ws1 5` → 5 次 `stateRoot` 只 spawn 1 次，命令为 `-C /tmp/gap225-ws1 worktree list --porcelain -z`；perCallMs `[4.36, 0.1, 0.03, 0.04, 0.03]`，总 4.56 ms，结果唯一。
