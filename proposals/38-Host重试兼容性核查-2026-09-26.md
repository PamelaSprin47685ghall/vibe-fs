# 38 Host 重试兼容性核查

日期：2026-09-26。这是实测记录与待决事项，不修订产品合同。

## 结论

当前固定的 OpenCode 1.18.29 不满足 host-provider-failure-ownership[002]。生产配置投影确实设置 `experimental.chatMaxRetries = 0`，但同一物理运行仍发送第二次 provider 请求。不能把版本固定或赋值成功视为兼容性通过。

正式回归位于 `requirements/host-provider-failure-ownership/tests/002.test.mjs`。目前保留“一次运行只请求一次”的失败断言，标记 GAP-144 TODO；没有改成接受重复请求。

## 实测与边界

安装二进制和 plugin 均为 1.18.29。独立 HOME/XDG、临时 Git 工作区、本机受控 provider、无真实凭证。专用观察插件调用生产 ManagedAgentConfig 配置投影，公开事件用于观察 assistant 身份。会话显式设置标题，排除标题生成；端点返回 503，第二次请求即触发中止与清理。

结果：`configuredRetries=0, providerRequests=2, providerRuns=1`。中止时尚无最终错误/终态，不能推断完整错误呈现链。初次未设置标题的结果混有旁路请求，不能作为单次运行计数证据；已由以上隔离场景取代。中间一次误用不接受 title 的 `/api/session` 也在前置断言失败，未计入结果。原始日志分别为 `/tmp/vibe-fs-38-isolated-canary.log` 与同名 `-error.log`；关键事实保存在本文，临时日志不是长期唯一证据。

## 根因依据

对应官方版本中，session processor 在 LLM stream 外应用独立的 SessionRetry.policy；LLM 的 SDK 重试默认零，并没有消除这个外层循环。[processor.ts](https://raw.githubusercontent.com/anomalyco/opencode/v1.18.29/packages/opencode/src/session/processor.ts)、[llm.ts](https://raw.githubusercontent.com/anomalyco/opencode/v1.18.29/packages/opencode/src/session/llm.ts)。

该 policy 固定最多五次重试，调用参数没有 chatMaxRetries 配置；503 属于可重试错误。测试所用响应头只控制其等待时间。[retry.ts](https://raw.githubusercontent.com/anomalyco/opencode/v1.18.29/packages/opencode/src/session/retry.ts)。这解释了实测重复；源码核对不替代本地运行证据，也不证明其它版本相同。

## 38-D1：兼容基线如何成立

建议保留 [002]/[005] 的单一恢复所有权，选择能真正关闭 Host 重试的受支持 Host 版本或与上游协作补齐能力，然后重跑真实回归，再更新 [007] 基线。具体版本尚未调查，不预称已有替代品。

若决定接受 Host 内部重试，需共同修改一次 physical run 的定义、恢复授权、容量和预算计账，不能仅放宽这个测试；影响 31、33、36、37、38。此路线改动更大，尚未采纳。

本轮未改用户 OpenCode 配置、依赖版本或安装二进制；也未用伪造非重试错误来规避实际 503。完整原生 UI 和唯一终态呈现仍按 GAP-143 待证。
