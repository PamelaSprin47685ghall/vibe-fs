# Sphinx v2 集成构建兼容修复

本轮只修复真实编译依赖、已有接口迁移和启动调用错误，不恢复旧 Sphinx，也不把七个工具尚未接通的业务宣称为完成。

## 改动

- `sphinx-v2-integration` owner 引用现有 EventStore integration contract、CanonicalIntegrator、local store、Host session contract 与 delegation runtime。`Server` 排在调用它的 `ServeEntry` 之前。
- OpenCode adapter 删除重复的 `promptOptions`、`createSession` 定义和重复 import；保留同义的原实现。
- MCP `zString` 的 Emit 需要 schema 与 description 两个参数，原函数却只传 description，生成了 `"Idempotent command identity".string().describe(undefined)`。现显式传入原有 Zod 对象，不改变工具业务或 schema 内容。
- `sphinx-v2-036` 增加真实 stdio server 初始化与 `tools/list` 回归，检查七个工具及其 commandId schema。使用共享等待预算，测试结束关闭客户端与子进程并清理临时 store；完整工具路由仍为 TODO。

## 无调用者的旧持久化接缝

全仓 Fable 编译通过后，surface manifest 拒绝没有正式测试导入的 `Sphinx/V2/Persistence/Surface.js`。再次搜索确认其五个公开函数没有生产或测试调用者；六处旧测试导入此前已因完全未使用而移除。

该接缝不是当前持久化合同的有效证明：登记的020规定三哈希，但它只独立返回 Replayability，并将同一值强制解释为 ExportMode，没有调用真实 Export。故删除这两个 Surface 源文件、owner 的对应 Compile 项、manifest 登记及 compile-order 两行，不恢复占位 import。真实 Export、Codec、Integrator 均保留，现有三哈希、完整重放及导出业务的证据缺口不因此关闭。

清退后，`js-surface-manifest` 只读检查通过（171项登记）；清单语法与修改范围 diff 检查通过，源码、活动测试和构建登记中已无这条接缝及其函数的残留引用。本次未运行共享 dist 构建，新的完整构建由主任务统一执行。

## 实际测试结果

17份现有正式测试文件按原内容复制到隔离目录，dist链接指向成功编译的真实临时产物，并使用仓库已安装的SDK依赖。逐文件核对复制字节相同。

- 最终共39项：27通过、12 TODO、0失败，日志 `/private/tmp/vibe-fs-sphinx-integration-test-final.log`。TODO不计为通过，完整业务缺口未删除。
- 新stdio回归验证真实服务启动、初始化和七工具schema，测试正常结束并清理临时store。首次隔离运行因symlink入口不满足ServeEntry的真实文件判定而退出；夹具改为realpathSync后通过，没有更改生产入口政策。原失败日志 `/private/tmp/vibe-fs-sphinx-integration-test.log` 保留。
- MCP的Emit参数错误先由真实生成代码确认；不把symlink夹具失败冒充这一产品缺陷的失败回归。
- 两个修改F#文件的Fantomas检查、修改范围diff检查和17测试文件的语义边界扫描通过。

以上是合法owner产物上的隔离诊断，不是全仓正式构建或发布验收。

## 仍未完成的业务

- 七个 MCP handler 仍忽略业务参数并读取空 inquiry 的状态。启动与名单正确不证明工具已接通 Runtime。
- OpenCode adapter 的 ReadStatus、ReadResult、Reconcile 仍是固定结果；两个 Host adapter 的 BindingIntent 仍使用默认值，真实角色与执行绑定尚需落实。
- Provider adapter 把 receipt 字符串传给 `HostForkRunLifecycleSurface.create`，而该接缝创建独立 pending-run，未连接实际 Host terminal；等待 completion 不能作为真实完成证明。
- 持久化 codec/fold、完整取消、恢复及保证传播的现有 TODO 保留。成功编译和启动都不关闭这些缺口。

正式构建和统一验收仍由主任务负责；临时产物上的诊断结果须单独标明。
