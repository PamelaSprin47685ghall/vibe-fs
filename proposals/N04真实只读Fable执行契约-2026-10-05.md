# 只读输入挂载：物理边界与恢复纪律

> 现行落点：`scripts/lib/verification-readonly-inputs.mjs`（被 `verification-fable-project.mjs` 与
> `requirements/verification-system/tests/support/readonly-input-tests.mjs` 消费）。
> 本文只留会挡住改这块程序的事实；跑过的轮次、日志条数、digest 值与逐格收据不再维护，需要时读 git 与 `archive/2026-10-05/baselines/`。

## 一、能力边界

- 挂载形态是 macOS 的 disk image：可写镜像 capture（UDRW）→ 转换 → 只读挂载（UDRO）。实测两阶段布局成立：
  UDRW create 约 14 秒，UDRO convert 约 3.4 秒，`imageinfo` 明确为 UDRO。整库存一次性 create 会撞 30 秒命令上限，那是准备失败，不是功能红。
- UDRO 只约束**经该文件系统访问**的输入。它不证明：镜像 backing 文件不可写、消费者提前持有的可写 FD、
  同权限进程 detach/remount、父路径与符号链接的瞬时 ABA、整个 OS 或 Node/monitor/Git/native 库来源不可变。
- 平台现状：`process.platform !== 'darwin'` 时在消费前明确拒绝（`Readonly input mounting currently requires macOS`）。
  Linux 没有等价强制能力，Windows 未证。拒绝发生在挂载之前，所以 Linux/Windows 上的只读输入保护实际不存在。
- 同一绝对路径被挂载顶掉之后，原目录 owner 校验（parent/root 的 dev/ino 仍是分配时那一对）必然失败，这是正确行为。
  禁止为了「看起来还能用」去更新旧 inode、只比内容，或接受任意新 inode。
- 布局优先保持原绝对路径：NuGet assets、`g.props/targets`、resolver 都带着原路径。路径保不住就明确拒绝该布局，
  再选经过验证的 relocation 契约，不做全局路径替换。

## 二、所有权转换的顺序

1. 原 prepared owner 完整校验，捕获成员并制作镜像，核对镜像与原 receipt。
2. 在固定绝对路径建立只读挂载，记录 exact image/device/mountpoint 身份；按唯一身份登记，不按 basename 猜所有权。
3. readonly view owner 显式接管执行期路径，编译只消费这一份能力；此阶段原 owner 不做旧 inode 断言。
4. 编译与消费者登记进 view；退出 action 后先停止新接入，取消并等待已登记消费者排空，才 detach。
5. detach 后核对原 parent/root 的 dev/ino 与库存恢复，原 owner 才能重新 revalidate/dispose。

compiled receipt 只在 active view 内消费与复核；detach 之后必须拒绝过期 receipt，不声称它能跨 scope 独立复核。

## 三、失败与回收

| 失败位置 | 可以做什么 | 必须保留的边界 |
| --- | --- | --- |
| 镜像未挂载 | 按 private identity 回收自有目录和镜像 | 不清理已被替换的 parent/root |
| attach 报错、结果未知 | 从真实 `hdiutil` 记录定位 exact owned image/device；无法确定则保留 | 命令失败不证明没有挂载 |
| 编译失败或取消 | 先终止并排空 owned process group，再 detach | 不能先 detach，让活跃进程读到原可写目录 |
| mount/device 被替换 | 拒绝发布结果，只处理已证明自有的资源 | 不按路径删 foreign mount，不猜 parked 目录 |
| detach 已完成 | 核对原 dev/ino 和库存恢复，再调用原 dispose | 路径不存在不证明原所有权恢复 |
| detach/恢复校验失败 | 尽力清理其它已分配自有资源，聚合资源错误并保留原业务原因 | 不覆盖原 Error/null，不输出成功结果 |

## 四、各阶段的输入与绕过面

这是核对表，不是「都已实测」的声明。

| 阶段 | 固定输入/执行来源 | 可写产物 | 重点绕过面 |
| --- | --- | --- | --- |
| `format:check` | 源码与配置、选定 SDK/Fantomas、Node/npm/wireit | 自有 CLI/cache/temp、wireit 状态、日志 | PATH 回落、父目录配置、用户 tool cache、旧成功缓存 |
| `check` | 脚本及其 imports、源码/规范/资源、选定 Node/依赖 | 自有缓存和日志；新增输出逐 checker 登记 | 原 workspace 的 scripts/lib 或 generator corpus、漏捕获依赖、环境输入 |
| 单工程 Fable | prepared owner、`fsproj`/props、SDK packs/runtime、Fable 依赖、NuGet 恢复图 | compileRoot 的 seed、JS、HOME/CLI/tmp/cache、日志 | 恢复绝对路径外借、安装回落、DLL 旁加载、旧 dist、反写输入 |
| 全仓 build | 单工程输入加全部 owner graph、build/generator corpus、完整依赖 | dist/staging、合法 build state/cache | 源码闭包漏项、incremental 旧输入、生成器读原 workspace |
| unit | runner/test/support、实际 build 输出、资源、选定 Node/依赖 | 受控临时 workspace/journal/HOME、日志 | 原 dist、外借 monitor/Node、未声明 OS 命令、跨文件副作用、瞬时扰动 |
| integration/e2e | unit 输入加选定 Host/SDK、provider 端口合同与 OS 前提 | 自有 Host workspace/history/journal/database/socket、日志 | 环境 Host/模型回落、未绑定网络输入、子进程脱离 owner、未排空资源 |
| package | manifest/resources、实际 build 输出、选定 npm/归档工具 | 自有 pack/tgz、隔离消费者、日志 | 原 workspace npm pack、遗漏或额外文件、安装网络、旧产物、mtime/mode 改变 |

已知缺口：现有 `verify.mjs` 仍从环境启动 npm、使用当前 Node、在 workspace 分配 verify 日志，并在阶段之间比较输入；
同一 candidate 身份尚未随真实阶段与结果一路传递，Node/monitor/Git/SDK/native/OS 来源也未逐个绑定到选定 owner。
补齐这些属于支撑程序瘦身，不是新的证明装置；先问删掉哪段保护会让谁立刻做不成事，答不上来就不加。
