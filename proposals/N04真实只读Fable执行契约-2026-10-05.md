## 原 owner 与只读 view 的交接

原目录 owner 的合同要求 parent/root 仍是分配时的 dev/ino。挂载让同一路径解析到卷内根，旧 owner 此时拒绝是正确行为；不能更新旧 inode、只比较内容或加入接受任意新 inode 的兜底。

优先物理考察保持原绝对路径的布局。NuGet assets、g.props/targets 和 resolver 已带原绝对路径；保持路径可避免未经核对的重写，但仍须证明实际解析落在只读 view 内。

1. 原 prepared owner 完整校验；捕获成员并制作镜像，核对镜像内容与原 receipt。
2. 在固定绝对路径建立实际只读 mount，记录 exact image、device、mountpoint 身份。
3. readonly view owner 显式接管执行期路径，编译只消费该能力。原 owner 不在此阶段执行旧 inode 断言。
4. 编译及消费者实际退出、进程组回收、pipe 排空后，校验并 detach owned device。
5. 确认原 parent/root dev/ino 及完整库存恢复，原 owner 才能重新 revalidate/dispose。

这是物理能力的所有权转换。不能通过展开旧对象、替换 root 字段来伪装同一 prepared receipt。若保持路径的物理布局不成立，应明确拒绝该布局，再选择受验证的 relocation 契约；不能任意全局替换恢复产物中的路径。

### 已取得的物理布局证据

自有临时目录上的实际 hdiutil 探测证实：UDRO 能直接 readonly 挂到已有普通成员的 root。同路径读到镜像中不同的内容，原目录独有成员被覆盖视图隐藏；原文件写入、新增、删除均报 `EROFS`。原 dev/ino 为 `16777234/154293243`，挂载后为 `16777237/2`；按唯一 image/mount/device 核对后 detach，原身份及两文件字节恢复。最后无 owned 挂载，临时 root 已回收，无 unknown attach。

[原始记录](archive/2026-10-05/baselines/n04-readonly-layout-probe.log) 只证明候选布局可行。探测没有挂载 workspace 或真实 SDK，也没有执行四 owner 的真实 Fable；不是正式回归或编译证书。下一步实现显式、有界 view 作用域，再让现有正式 repository fixture 覆盖实际消费者。

## 失败与回收

| 失败位置 | 可以做什么 | 必须保留的边界 |
| --- | --- | --- |
| 镜像未挂载 | 按 private identity 回收自有目录和镜像 | 不清理已被替换的 parent/root |
| attach 报错、结果未知 | 从真实 hdiutil 记录定位 exact owned image/device；无法确定则保留 | 命令失败不证明没有挂载 |
| 编译失败或取消 | 先终止并排空 owned process group，再 detach | 不能先 detach，让活跃进程读到原可写目录 |
| mount/device 被替换 | 拒绝发布结果，只处理已证明自有资源 | 不按路径删除 foreign mount，不猜 parked 目录 |
| detach 已完成 | 核对原 dev/ino 和库存恢复，再调用原 dispose | 路径不存在不证明原所有权恢复 |
| detach/恢复校验失败 | 尽力清理其它已分配自有资源，聚合资源错误并保留原业务原因 | 不覆盖原 Error/null，不输出成功 receipt |

## 先取得的正反例

1. 实际 source/props、SDK、Fable、packages 消费路径上，写入、新增、删除被真实文件系统阻止；不用无关 `source.txt` 替代。
2. 原可写准备目录出现可辨认变化时，Fable 不能把它作为备用输入。恢复产物的绝对路径必须指向只读 view，布局无法保证就拒绝。
3. 真 Fable 成功，Identity/Quiescence 真 Node 消费，四 owner 库存与实际输出绑定保持。
4. selected DLL/runtime/native 成员缺失时，不能借环境安装恢复；负例按实际加载闭包选择。
5. mount/root/device 消失或被替换时不发布结果，也不删除 foreign 资源。
6. 真编译成功、失败、取消三个场景都证明进程排空与 owned device 回收。

当前工具校验只覆盖 `.deps.json` 的 managed runtime 资产，尚未完整覆盖 native/runtimeTargets、runtimeconfig 探测路径及系统共享库。SDK bundle、SDK packs、工具自带 FSharp.Core、native 与 OS 库分别记账。

UDRO 只保护经该文件系统访问的输入，不自动证明镜像 backing 文件、提前打开的可写 FD、同权限 detach/remount、父路径/链接 ABA 或整个 OS 不可改变。这些属于 N04-C 的独立义务。第一切片即使通过，也不得关闭全仓多工程、Linux/Windows 或完整 T418/T419。
