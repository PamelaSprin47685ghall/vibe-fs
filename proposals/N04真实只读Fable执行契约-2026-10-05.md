## 原 owner 与只读 view 的交接

原目录 owner 的合同要求 parent/root 仍是分配时的 dev/ino。挂载让同一路径解析到卷内根，旧 owner 此时拒绝是正确行为；不能更新旧 inode、只比较内容或加入接受任意新 inode 的兜底。

优先物理考察保持原绝对路径的布局。NuGet assets、g.props/targets 和 resolver 已带原绝对路径；保持路径可避免未经核对的重写，但仍须证明实际解析落在只读 view 内。

1. 原 prepared owner 完整校验；捕获成员并制作镜像，核对镜像内容与原 receipt。
2. 在固定绝对路径建立实际只读 mount，记录 exact image、device、mountpoint 身份。
3. readonly view owner 显式接管执行期路径，编译只消费该能力。原 owner 不在此阶段执行旧 inode 断言。
4. 编译及消费者实际退出、进程组回收、pipe 排空后，校验并 detach owned device。
5. 确认原 parent/root dev/ino 及完整库存恢复，原 owner 才能重新 revalidate/dispose。

这是物理能力的所有权转换。不能通过展开旧对象、替换 root 字段来伪装同一 prepared receipt。若保持路径的物理布局不成立，应明确拒绝该布局，再选择受验证的 relocation 契约；不能任意全局替换恢复产物中的路径。

## 失败与回收

| 失败位置 | 可以做什么 | 必须保留的边界 |
| --- | --- | --- |
| 镜像未挂载 | 按 private identity 回收自有目录和镜像 | 不清理已被替换的 parent/root |
| attach 报错、结果未知 | 从真实 hdiutil 记录定位 exact owned image/device；无法确定则保留 | 命令失败不证明没有挂载 |
| 编译失败或取消 | 先终止并排空 owned process group，再 detach | 不能先 detach，让活跃进程读到原可写目录 |
| mount/device 被替换 | 拒绝发布结果，只处理已证明自有资源 | 不按路径删除 foreign mount，不猜 parked 目录 |
| detach 已完成 | 核对原 dev/ino 和库存恢复，再调用原 dispose | 路径不存在不证明原所有权恢复 |
| detach/恢复校验失败 | 尽力清理其它已分配自有资源，聚合资源错误并保留原业务原因 | 不覆盖原 Error/null，不输出成功 receipt |

1. 实际 source/props、SDK、Fable、packages 消费路径上，写入、新增、删除被真实文件系统阻止；不用无关 `source.txt` 替代。

## 2026-10-06：N04-C3 独立消费者失败的有限证明

现有 scope 已经正确处理这些失败，本包只补正式行为证明，不修改生产 helper。`016.test.mjs` 注册三个 Darwin native integration 用例：真实 Node 先读 mounted member，然后输出实际 PID/读取字节、写原 stderr 并退出 73。action 等该消费者完全结算，才成功返回或抛原 Error/null，避免把 scope abort 误当作另一份独立失败。

- action 捕获 consumer 失败后正常返回，scope 仍须拒绝，原因与原 consumerError 是同一对象，不能发布 action 的成功结果。
- action 再抛 Error 或 null，scope 须拒绝为 AggregateError；cause 保留原 action 值，errors 精确为 `[原 action 值, 原 consumerError]`。
- 每例同时检查 exitCode/signal/stderr、原读取字节、实际 PID 的 ESRCH、消费者退出时原 inode owner 仍拒绝 mounted namespace，以及 detach 后四 owner 的 dev/ino、mode、member size/bytes 和目录清单完整恢复。业务拒绝断言放在实际清理完成之后。

gen167 的[初次真实绿色](archive/2026-10-05/baselines/n04-c3/native-green.log)为 3/3、0 fail/skip/TODO，37.733 秒，前后 freshness 一致。两份手工受控变异分别证明 oracle 有效：[丢弃失败 consumer](archive/2026-10-05/baselines/n04-c3/drop-consumer-red.log)为 0 pass/3 fail，实际成功结果泄漏或独立错误缺失；[错误 null 回退](archive/2026-10-05/baselines/n04-c3/null-cause-red.log)为 2 pass/1 fail，仅 null cause 同引用断言失败。每例实际 exit73、进程回收和四 owner 恢复仍通过，均不是准备失败。随后生产文件手工恢复并核对原 SHA256；最终固定输入、完整 11 项小物理回归、正式 unit 选集和静态门禁以[本包验收收据](archive/2026-10-05/baselines/n04-c3/final-receipt.txt)为准。

## N04-C 接续：先证明物理能力，再接实际 verify

以下顺序接续 C3；不能沿旧计划把上述失败传播证明当作全过程 immutable 已完成。需求已经明确，调查目的在于选择能履行需求的物理能力，不是缩窄 WHAT016。

1. **C-R0，物理能力调查。** 逐项写明实际消费进程能否写 backing、修改祖先目录、持有准备期可写 FD、执行 detach/remount；分别检查 Darwin/Linux 能否强制限制这些操作。记录同 UID 和外部进程可施加的扰动、保护由哪个 OS 能力承担、能力不足时在哪个消费前入口拒绝。只读 view、readonly filesystem 与整个验证候选的不可改性不能混为同一个承诺；不能新增 chmod/watch 或边界哈希兜底。
2. **C-R1，运行期 mounted 路径矩阵。** 复用本支持文件、四 owner 和登记的实际 Node consumer，在自有 output 中用 ready/release 握手暂停消费者。正例真实读输入、写合法 output、终止并回收。负例在暂停点尝试改写、新增、删除、内部 rename 和链接替换：真实 EROFS 拒绝，消费者随后仍读原字节。每个负例保留原选择、实际 PID、完整输出、owner 恢复及镜像回收断言；不靠测试自建状态推算结果。这只完成经 UDRO namespace 访问的有限矩阵。
3. **C-R2，持久 namespace 替换与资源归属。** 先为独立扰动方建立自己的目录/镜像 owner，再从真实 OS 记录取得 exact image/device，不能按 basename 猜所有权。持续替换 mount/root/device 时，生产 scope 必须拒绝结果且不删除 foreign 资源；扰动方最后只回收它自己证明拥有的资源。unknown attach 和未确认产物分别立独立黑盒例，不将命令失败当作“肯定没挂载”。
4. **C-R3，FD/backing/ABA 和准备混代。** 依 C-R0 的实际强制能力选择实现；先用同权限 actor、实际消费者和 write→restore/rename→restore 立红，证明消费者确实读过变化且旧前后库存相同。随后证明变化被物理阻止，或候选失效并停止后续真实阶段。只在最终 dev/ino、字节和哈希上补判断不能修这个根因。已有可写 FD 指向隐藏原目录时，必须分清它改的是被消费的快照还是已隔离的原准备目录，不能把允许的原目录并行编辑误判为快照破坏。
5. **N08，逐真实阶段接线。** C-R3 的能力及实际加载闭包明确后，按本文件阶段矩阵接 format/check/build/unit/integration/e2e/package。同一 candidate 身份随真实阶段与结果传递，失败/取消阻止后续阶段；Node/monitor/Git/SDK/native/OS 来源单列。全过程保护和同候选结论两项都证明后，才讨论移除 T418/T419。

**C-R0必须交出的四项材料。** 第一，实际消费闭包：四prepared owner与Node/monitor/Git/native/OS来源分别列出，含路径解析和继承FD的所有者。第二，actor能力矩阵：消费子进程、同UID外部进程、backing/祖先目录持有者各能做什么，哪项实际OS能力强制拦截；Darwin/Linux分别记录，Windows未证保留。第三，正式探针设计：自有扰动资源、ready/release暂停点、实际读结果这一独立oracle、失败/取消清理，不能只凭OS命令返回值判消费安全。第四，逐格结论：已保护、消费前明确拒绝、尚未证明；每格挂真实证据或待补反例，不用chmod/watch/hash补写保护承诺。

**可并行的边界。** C-R1 mounted路径矩阵和C-R2持续替换/unknown attach可作为有限工作包推进，但同一support文件由一人整合。C-R3的FD/backing/瞬时ABA/准备混代须等C-R0能力结论，不用原目录允许修改来伪造隔离快照失效。N08依赖实际保护与完整加载闭包；缺任何必要能力就明确拒绝相应平台/入口，不能静默退回可变workspace。
