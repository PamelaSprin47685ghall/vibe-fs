# 待核：fork 子视图是生产路径上的死参数

从旧「交付迁移待核事项」收口。原文的 oracle 可注入缝、`requirements/GAP.md` 落点建议一并去掉：
那条中间态能不能红不是产品问题；这里只留一条与程序对得上的事实，解除条件是这条缝被接上或被删掉。

## 事实（按当前 `master` 静态核对，未运行）

- 生产接线 `src/Wanxiangshu/OpenCode/Plugin/PluginHooks.fs:926`：
  `let childViewForRun = fun _ _ -> Task.FromResult None` —— 宿主生产路径给子派发的是恒 `None`。
- 默认值同样恒 `None`：`src/Wanxiangshu/OpenCode/Tools/ToolRuntimeScope.fs:177`
  `defaultArg childViewForRun (fun _ _ -> Task.FromResult None)`。
- 参数一路穿过 `Execution/Delegation/Fork/Host/{ChildDispatch,RunLifecycle,Runtime}.fs` 与
  `OpenCode/Host/PluginHostInterop.fs`，只有 fork 的测试面 `Execution/Delegation/Fork/OpenCode/ToolSurface.fs`
  提供真实函数。也就是说生产上没有任何一条路径能让它返回材料。
- 交付材料的真实读取不走这条参数：生产在 `Execution/Delegation/Fork/Host/RunLifecycle.fs:308`
  经 `JsDeliveredValues.tryPeekMaterialWith` 取正文，`JoinSurface.fs:455` 同。

## 待改

一条恒为 `None` 的形参不是「留着以后用」，是让每个读这条链的人都得判断一次「这里到底有没有东西」。
两种收法，任选一种，人手一刀：

1. 生产确实需要「按 provider run 取子视图」——那就把真实视图接进 `PluginHooks`，删掉默认值兜底，
   让缺视图成为类型上不可表达的状态。
2. 不需要——删掉 `childViewForRun` 形参与其默认值，测试面改用真实读取路径，减少一层间接。

判断依据是总流程：用户在 fork／加入子工作时，是否有一步真的需要「按那次 provider run 的视图」呈现材料。
不得为了保留可观察缝而维持这条死参数。
