# Host032 参数保真修复记录

日期：2026-09-28。范围为 host-boundary-032 的生产参数清理边界及其正式回归。当前状态：修复已写入，待统一新构建与正式复验；本文不登记最终验收数字。

## 原问题与真实红例

Generation 4 的正式选测通过了构建新鲜度检查，但 `032.test.mjs` 在同步等待真实 canary 时没有持续给出验证结果，最终触发既有五秒静默门禁。其独立 Host 留在另一进程组，已依据 PID、PGID、实际命令及专属工作目录核对身份后回收。这次失败不能归为业务通过，也不能用更长的监督窗口处理。

改为同一 Host 的异步验证阶段后，公开 Hook 与 SDK 给出了明确反例。正常文件读取已完成，原始参数对象也在 `after` 恢复，但 Host 保存的输入仍没有 `contract`：

| 实际观察 | 结果 |
| --- | --- |
| `before` 前的原始入参含 `contract` | 是 |
| 原生产 `before` 返回后仍含 `contract` | 否 |
| `after` 后同对象、原始值和键顺序恢复 | 是 |
| SDK 中终态 ToolPart | `completed` |
| SDK 终态输入保留 `contract` | 否 |
| SDK 终态输入等于原始输入 | 否 |

这说明“后来恢复内存对象”没有恢复 Host 已经保存的材料。不能靠手工调用 `after`、修改历史输入或恢复上游已经退役的 Vault 来补齐证明。

原红日志为 `/private/tmp/remainder-semantic-host-formal.log`；公开接口反例为 `/private/tmp/remainder-host032-staged-diagnostic.log`。后者是显式跳过新鲜度检查的设施诊断，使用此前 Generation 4 的生产产物，不代表本次源码已完成新构建。上表保存其关键事实，避免临时日志消失后只剩一个结论。

## 最窄修复

`ManagerReviewContract.wrapReviewExecutors` 包装实际注册的 `js-manager.execute`，复用现有私有暂存、隐藏与恢复逻辑。只在真实执行器调用期间隐藏提示字段；其实际 Promise 完成或拒绝后，在 `finally` 中恢复同一对象、原始属性描述符与键顺序。不存在或不可调用的注册入口明确拒绝，不静默跳过。

`PluginHooks.configureClient` 对实际 `ToolRegistration.Tools` 装配这一包装。原 `before` 中的权限、grounding 和估算门禁保留，移除的是发生过早的字段删除；原 `after` 恢复仍然幂等。没有让底层 Codec 或 ToolRegistry 反向依赖 composition，也没有增加取消政策。

正常恢复时，执行器原错误对象原样传播。若执行和恢复同时失败，使用 `AggregateError` 保留两个错误及原始 cause；只有恢复失败时，该真实错误仍使调用失败。测试 Surface 只转发同一生产包装，不另写清理算法。

## 测试证明范围

局部正式回归直接调用生产包装，覆盖真实在途 Promise、同步抛错、异步拒绝、实际 AbortSignal 导致执行器拒绝，以及执行与恢复双故障。观察保留执行时的独立快照，不能等字段恢复后再拿同一引用证明早期状态。

物理 canary 保持同一 Host、同一生命周期，以实际版本、就绪、正常调用、后续历史、受控异常和受控取消等断言形成异步子测试。Host 使用现有 `detached:false`，并实际核对与监督器继承同一进程组；没有新增心跳或放宽静默限值。清理保留主错误与各清理错误。

| 场景 | 实际执行对象 | 证明边界 |
| --- | --- | --- |
| 正常读取 | 生产 `js-manager` 执行器读取 `fixture-sample.txt` | 完整比较真实读取输出，并检查对象身份、原值、键顺序、SDK 持久输入及后续 provider 历史；普通拒绝文本即使为 `completed` 也不能通过 |
| 执行异常 | 同一生产包装内的受控注册执行器抛出真实错误 | 经真实 Host 异常出口，检查包装实际拒绝、原错误、同源恢复和 SDK 终态；不人工调用 `after` |
| 取消 | 同一生产包装内的受控注册执行器，收到真实 Host 的公开 AbortSignal 后拒绝 | 先观察实际执行器已进入和 Host 在途状态，再观察其真实 Promise 结算、恢复和 SDK 终态；不是手填取消结果 |

错误场景不再把“读取不存在的文件”充当执行器抛错。原 fixture 实际返回的是 `# failed` 业务结果，Host 将该调用记为 `completed`，因此它不能证明异常出口。

“在 `before` 返回后删除字段”是旧实现位置，不是 WHAT 指定的位置。相应断言已改为公开入参保持原样，并在真实执行器边界证明提示字段已隐藏。对象身份、原始值、键顺序、异常恢复、持久输入和历史保真的实质要求仍保留。

## 未关闭的缺口

生产 JS 取消尚未完成证明。[JsToolSpec](../src/Wanxiangshu/Repository/Programming/Js/OpenCode/ToolHost.fs) 当前没有消费 `HostToolContext.AttachAbort`，而是等待沙箱的既有十秒期限。原真实 `await new Promise(() => {})` 场景在 Host abort 后进入错误终态，不等于底层执行器已经结算，也不等于其恢复逻辑已执行。

受控 AbortSignal 拒绝只证明包装和真实 Host 的 Adapter 边界。它不关闭生产 JS 的取消与底层沙箱退出缺口；正式 `032` 中已明确保留 TODO。原下游 Hook 异常整链证明的 TODO 也未关闭。没有使用 `Promise.race` 伪称底层工作完成。
