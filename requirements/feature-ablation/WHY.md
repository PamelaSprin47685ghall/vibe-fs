# feature-ablation — WHY

## 不可替代的存在理由

人工巡检与渐进验收要求在审查早期机制时，下游未审能力不得反噬或污染当站观察。若只能依赖“不启动某个 agent”或通过源码硬编码临时开关，系统便无法在形式上区分“机制从未存在”与“机制被正式关停”，更无法依拓扑序逐级解除隔离。

全功能消融机制将“关停什么、借用什么、何时完全启用”从不可控的操作习惯与临时代码分支，固化为可配置、可审计、受拓扑约束保障的一等机制。

## 核心张力

- **消融 DAG ≠ 语义依赖 INDEX**：消融顺序由主审站的验收推进驱动，反映能力何时被信任并准许开放，这与底层的模块编译或语义依赖树有着本质区别。
- **Borrowed ≠ Active**：受限基础设施借用只开放有限切面，绝不产生完整的包级下游语义。
- **零影响基线**：Ablated 状态下 owner 路径必须与从未装载该机制时一致，不得改变可见工具、行为或等价副作用。
- **编号迁移不错位**：消融 DAG 与 Profile 编号迁移必须保持拓扑单调与显式对应，严禁静默错位。
- **角色与能力目录同步**：消融节点与工具映射必须严格同步当前合法活跃角色体系（Engineer、DevOps、Manager、Orchestrator、Blogger、Bookkeeper 等）；当特定能力演进或退役时，其独立的消融开关与现有活跃角色必须解耦，不得相互连带误关。

## 节点注册与层级划分 [001]

- **单包单一主节点**：消融的基本归属边界与语义包（package）物理边界严格对齐。每个包恰有一个同名的主消融节点，建立“包即责任单元”的基准映射，防止消融范围与代码所有权割裂。
- **包内子节点与 parent 显式声明**：当包内存在需要独立借用或关停的细粒度子切面时（例如 `delegation.sync-delegate` 与 `delegation.async-fork`），允许在同包内拆分子节点。子节点必须显式声明 `parent` 指向父节点，确立父子从属树，防止将固有的包内隶属结构退化为平级拓扑边，避免父子生命周期发生语义脱节。
- **静态清单承载（nodes.json）**：消融节点清单与序号由 `resources/ablation/nodes.json` 单一真源承载，使消融元数据独立于易变的执行逻辑，保证审查时图结构清晰、可复查、可离线分析。

## 三态语义与零影响基线 [002]

- **三态区分的必要性**：二元开关（开启/关闭）无法表达基础设施在受限场景下的“局部借用”。系统必须通过 `ablated | borrowed | active` 明确切面边界：
  - **ablated（零影响）**：该切面不启用；对外表现必须等同于从未加载，不得改变可见工具、行为或等价副作用，杜绝未审能力暗中破坏受限环境。
  - **borrowed（受限借用）**：仅 resources/ablation/nodes.json 明示的借用面可运行（如同步委托调查链）；不得触发完整包级下游语义。
  - **active（全功能启用）**：包级机制按各自 WHAT 正常运行。
- **未配置时生产默认全部 `active`**：消融是面向测试、逐级巡检与隔离验证的审查手段，不是生产常态。未配置 profile 时 production 默认全部为 `active`，确保不向普通运行强加消融负担，只有在明确指定巡检站或特定 profile 时才进入消融状态。

## 消融 DAG 与拓扑约束 [003]

- **有向无环图模型**：消融拓扑构成 DAG，精确约束各主审站机制逐级放开的先后秩序，杜绝逻辑循环。
- **两类边的因果分离**：
  - **station-order 边（主审站拓扑）**：表达审查推进的主线因果。仅当前置审站的 `from` 节点已处于 `active` 或 `borrowed` 时，后续的 `to` 节点才可设为 `active`，防止在未经验收的脆弱基础上建立下游假象。
  - **borrow 边（借用前提）**：表达运行时的最小依赖前提。目标节点若要进入 `borrowed` 或 `active`，其所借用的前提节点至少必须具备 `borrowed` 状态，确保基础设施切面运行时必需的底层契约切实可用。
- **加载时环检测与 Fail-Closed**：消融图在加载时必须做强校验。一旦检测到有向环或矛盾约束，必须立即中断（Fail-Closed）并报错拒绝运行，防止系统带着死锁或含混状态侥幸运行并掩盖深层缺陷。

## 配置集与动态覆盖 [004]

- **配置集固化（profiles.json）**：消除每次测试或巡检时繁琐且易错的手工逐项配置，将各主审站标准与生产模式固化为 `resources/ablation/profiles.json` 中的命名配置集，保证消融测试可复现、可审计、可回归。
- **环境变量覆盖受制于图不变量**：允许通过环境变量 `WANXIANGSHU_ABLATION_<node>=ablated|borrowed|active` 进行单点临时覆盖，以支持特定调试场景；但单点覆盖后的全图状态依然必须完整通过 DAG 校验。动态手段绝不能凌驾于系统的根本拓扑不变量之上。

## 违约状态（RED）

1. **包级归属脱节**：消融节点注册或工具映射未严格同步当前合法活跃角色体系（Engineer、DevOps、Manager、Orchestrator、Blogger、Bookkeeper 等），出现孤立注册、陈旧角色残骸或能力变更时的连带误关。
2. **Ablated 状态逃逸**：被标为 `ablated` 的节点仍在运行时改变可见工具、行为或等价副作用。
3. **借用越权（Borrowed 越界）**：处于 `borrowed` 的节点越过明示借用面，触发完整包级下游语义或自主调度机制。
4. **拓扑不变量被打破**：下游节点处于 `active` 而上游前置仍为 `ablated`，或环境变量单点覆盖导致状态破坏 `station-order` 或 `borrow` 约束。
5. **配置异常 Fail-Open**：遇到含环消融图、未定义节点引用、非法状态取值或破损 profile 时静默降级或继续运行。
6. **隐藏分支代替正式消融**：靠注释、条件编译或未文档化代码分支隐藏下游机制，而非走正式的消融开关。
