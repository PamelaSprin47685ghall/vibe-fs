## 检查器的能力边界

- 边界扫描器使用已知模式和部分语法分析；某些注释、字符串及普通字段访问仍可能误报，任意别名或动态构造也可能漏报。文件名含 `domain` 或 `interop` 本身不证明违规。原来仅按文件名、目录名、源码关键词判断合法性的测试已移除。
- 登记检查识别正式标题，正文中的引用不会创建命题；import 按实际调用文件位置解析。编译项目纳入检查仍依赖当前项目文件格式，历史 law 前缀仍按指定所有者及数字编号解析，不能据此认定历史编号已全部规范化。
- `js-contract.mjs` 检查当前值的结构；普通业务字段不因名称碰巧类似编译器字段而被禁止。递归范围是数组元素和纯对象的可枚举自有字符串键值；继承、非枚举属性、访问器行为、跨执行上下文的特殊值及业务语义不属于它的完整证明。对象不是“只要检查器放行就合法”。
- 链接检查覆盖字面相对导入及转导出，模块实际加载补充验证初始化和导出歧义。计算路径、外部包选择和只有调用函数才触发的依赖，仍需对应领域的运行证据。静态检查不推导任意程序的所有未来路径。

这些边界及人工审阅责任记录在 [GAP](../../GAP.md)，不能通过缩小 WHAT 消除。

## 运行

在仓库根目录先执行 `node scripts/build.mjs`，再通过正式运行器执行六个条款文件：

```sh
TESTS_MJS_FILES="$(rg --files requirements/js-semantic-surface/tests | rg '/[0-9]{3}\.test\.mjs$' | sort | paste -sd, -)" node requirements/verification-system/tests/run.mjs
```

正式运行器检查构建新鲜度并披露局部范围；当前两个 TODO 会使验收返回非零。直接 `node --test` 有助于诊断反例，但 Node 将 TODO 排除在普通失败之外，其零退出码不能当成本包已验收。这里没有执行真实 Long Stroke。

夹具写入独立临时目录，并由测试清理。正反例调用生产使用的登记、边界和链接检查器；不会临时污染真实源码或产物。共用表示检查器修改时，还需运行引用它的领域用例。
