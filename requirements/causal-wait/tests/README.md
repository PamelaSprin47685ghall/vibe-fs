# causal-wait 测试范围

行为规范见 [WHAT.md](../WHAT.md)。本目录测试等待的可诊断性与业务权限的隔离：观察等待，但等待的走向由业务事实决定。

| 用例编号 | 验证重点 | 说明 |
|---|---|---|
| **001** | 诊断失败不改变业务 | 诊断目的地写不进去时，业务值与业务失败照常返回。 |
| **002** | 快照四要素可读 | 登记之后的快照给出 Owner、Wait、Producer 与 Termination。 |
| **003** | 诊断不进事实 | 业务侧取不到诊断快照；共享静态分析器对生产树放行、对写入 Journal 编解码的等待词汇报错，词法陷阱（注释与字符串）不误判。 |
| **004** | 读写能力不可互换 | 观察端口与读取端口在类型上不能互换，业务只拿写能力。 |
| **005** | 事件驱动唤醒 | 就绪即刻返回；延迟信号只在材料就绪后放行；分次与上几千次的陈旧信号不替代截止时间，也只构成一个观测。 |
| **006** | 终止与幂等 | 完成、失败、取消都移出活跃集合并记录退出状态；租约释放幂等；晚到标记不复活已结束的等待，有限历史不增长。 |
| **007** | 因果前沿 | 纯图算法报告最小未满足前沿：嵌套分叉、断裂依赖、外部等待、汇合路径不误判成环，循环分量不悬挂。 |
| **008** | 进程内生命周期 | 诊断桥把快照写到 `.Herdchestra/diagnostics/causal-waits.json`（非 Journal、git 排除）；新进程的新注册表为空，不从旧文件恢复等待。 |
| **009** | 契约/运行时/诊断分离 | 静态分析器拒绝业务工作流里的全局观察器与组合根之外的诊断适配器；诊断目标首次绑定后保持稳定。 |

## 运行方式

先执行标准构建：
```sh
node scripts/build.mjs
```

运行测试：
```sh
TESTS_MJS_FILES="$(rg --files requirements/causal-wait/tests | rg '/[0-9]{3}\.test\.mjs$' | sort | paste -sd, -)" node requirements/verification-system/tests/run.mjs
```
