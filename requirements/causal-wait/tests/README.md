# causal-wait 测试范围

本包保留事件驱动、生命周期、权限及因果图的真实局部证明。诊断数据不是业务权威；README 不自行解决 WHAT 008 与诊断文件现状的冲突。

- 001 用实际无法写入的诊断目的地验证业务值与失败仍照常返回，不靠 observer/reader 的存在推断全局非干涉。003/004 继续用实际能力拒绝互换，并检查生产树与同一静态分析器的正反输入。
- 002 从真正登记后的快照读取 Owner、Wait、Producer 和 Termination，不再只断言原始 createWait 对象。最后相关事实尚无专门字段或关联证据，跨边界全覆盖也未证明，留 TODO。
- 005 保留单次异步信号、分次陈旧信号、5000 次立即陈旧唤醒和到期后静止的不同序列；都使用真实等待 helper 与虚拟定时器。单一观测、读次数与实际 Cancel 调用数用于区分轮询和正确唤醒。
- 006 检查完成/失败/取消、租约幂等、晚到标记不能改写退出及有限历史。新增 tryRead/awaitSignal 失败反例，要求记录 WaitFailed、取消未用 deadline 并在随后推进时不复活。默认 256 是当前回归值，不是新业务条款。
- 007 实际纯图算法检查完整环及非循环前缀。同一 owner 的每条等待分支分别追踪，覆盖嵌套分叉、断裂或循环分支旁的外部等待、汇合路径不会误判成环，以及有根工作流旁的独立循环分量；六项反例在旧实现上失败后修复。无等待的生产者与断裂依赖目前缺少可区分信息，不能靠枚举名宣称覆盖。
- 008 子进程 A 真正产生观测及诊断文件，退出后子进程 B 仍看到旧文件，但新注册表为空。这证明注册表不从文件恢复，不证明整个插件重启路径，也不代表禁止任何落盘的原条款已满足。诊断 bridge 写文件的旧用例明确是现状回归。
- 009 保留实际 first-bind 与工程边界检查，移除辅助模型自证；同一 registry 拒绝改绑不等于多个实际插件实例已验证。声明引用也不代替负向编译及消费者真正取得的注入能力。
