# process-execution — WHAT

## [001] 终端四动词

终端的打开、写入、读取增量与发送信号是四个不同的物理动作，不合并为模糊口令；模型面把它们投影为 `js.run` 的 `spawn`（`next()` 返回）、`send`、`check` 观察窗与 `signal` 四种形态（见 repository-programming-058）。

PTY 监管须能从编译型 Bun 宿主启动，不要求宿主可执行文件默认充当 Bun CLI。内部 worker 的启动标记不得泄漏给目标命令；目标保留调用方环境，启动 worker 不改写宿主环境。

## [002] 动作与观察分离

命令与信号是物理动作，stdout/stderr 是观察；输出不能充当任务完成或下一动作的授权。

## [003] 真实退出决定物理完成

只有底层实际退出事件能确认进程完成。输出停止或发送终止信号均不等于退出。

未确认退出的 PTY ID 不得被另一次启动覆盖；只有观察到旧实例退出后才可复用该 ID。批量清理须尝试每个所属实例，再报告未能确认退出的错误，不能因前一项失败而遗漏后续实例。

PTY 的目标退出和监管范围结束分别观察。目标先退但本次控制终端会话仍有活进程时，不得发布完成或释放归属。成员表必须包含本次活 owner，且各行完整；空输出、缺 owner、残行或冲突行均是未确认，不能解释为会话为空。有效成员还须核对本次 SID；监管者失联或缺少确切结束回执时保留 Unknown，并使等待中的排空报告失败。

启动和控制确认的有限等待由宿主侧监督，不能只依赖被监督进程自己的计时。KILL 已转发仍不等于范围已结束；范围结束迟迟未确认时报告 Unknown，重复请求不能重置最早等待期限。

可恢复 PTY 的物理 owner 独立于调用 Host 持有 master，控制端点鉴别确切实例并只允许一个控制连接。Host 消失不代替物理退出；终态回执须在原生目标退出及监管范围结束均确认后写入，冷读取仍校验该预留的身份和 incarnation。owner 在尚未接纳启动时明确封存可报告 NotStarted；缺失 owner 或缺失回执不得推断结束。恢复控制只查询和终止，不重放创建或输入。

活 creator 的正常完成须在同一有序控制流中交付此前输出，再确认匹配的持久终态；不能用磁盘轮询越过未读输出。控制流提前断开须报告未完成观察，不能静默返回缺字节的成功结果。owner 在确切物理终态后有界等待输出发送，再结束连接；冷恢复仍可独立接纳确切物理回执。恢复期间才出现的有效 NotStarted 与入口处已有的 NotStarted 语义相同，不把明确未启动当成新的 Unknown。

确切 NotStarted 与进程退出分别表示。原 Host 须能在迟到的未启动证据到达后收束本地 session、port 和归属，保留失败原因；不得伪造原生退出，也不得把同一处理扩展到输出不完整的 Ended。明确未能创建 custodian 时，清理本次空控制端点目录。

内层真实范围结束的通知不得因外层终态发布异常而静默丢失。custodian 先保存本次 onExit 的确切事实，发布失败须向原控制连接报告 Unknown；fault 文件同样写失败时也须报告。只有通过原实例认证并取得独占控制的显式恢复，才能重试发布同一事实，不覆盖原退出码或停止标记，不重发命令。待发布期间不再向已结束的物理范围发送控制。只有临时 pending 文件、目标退出或旧 PID 时仍不足以清账。

目录 fsync 失败不得报告发布耐久成功。若正式 terminal 已存在，后续恢复可按原规则读回并校验该真实签名退出事实；原 creator 的失败不因此改为成功。custodian 须在匹配的正式回执可读后退出，不能因首次回读异常而常驻；观察回执不自动重发布。没有可验证的正式 terminal 时，owner 丢失仍保留 Unknown；不承诺断电后未确认目录项仍存在。

## [004] 有限执行期限

每次物理执行须有显式有限硬顶，有效时限取运行预估与硬顶的较小值；到期进入确定的超时失败路径。

单次执行分别保存目标终结、停止请求、完整输出和故障。正常 Exited143 与 Signaled SIGTERM 不同；未知回执不能表示成 -1、1 或监管者退出码。目标已退出不代替监管范围结束或采集完整；取消、期限和采集故障仍保留最近取得的确切目标终结，故障不能覆盖已知事实。

## [005] 类型化请求与预算校验

请求须类型化，非有限或非正运行时限、负输出预算等非法参数在创建物理进程前拒绝。

Command.Environment 是宿主显式环境覆盖；宿主在启动前将其与自己的有效环境合成完整快照，再交给物理库。库不得自行继承环境。合法键（包括 `__proto__`、`constructor`）按字面值传递；参数数组不经过隐式shell解释。自然JS编码入口保留该字段，不以原型赋值丢失键或执行访问器。

## [006] 取消与进程组收束

取消须向整个进程组请求终止，立即向等待方返回取消结果，不因等退出而无界挂起；取消结果不宣称已确认物理退出。

Host 的真实取消信号从执行等待开始监听，直到成功、失败或取消收束后解绑，并覆盖启动握手期。预取消和排队取消有零执行依据，返回 NotStarted；运行中取消返回 Observed 与独立的 CancellationRequested，不能借未确认启动推断未执行。完成后迟到取消不改写原结果。底层异常保留在有类型结果中。

Ctrl-Z 可以暂停目标前台作业，但不能使同组监管者失去执行关闭请求的能力。

## [007] 持续终端与单次运行分离

支持多轮写入、读取和信号的持续交互形态，与单次有界执行形态在同一 `js.run` 编程面上分别定义契约（持续形态用 `spawn`/`send`/`check`/`signal`，单次形态用命令字符串 `next`），不混用两者的完成语义。

## [008] 完成事实的独立通道

Agent 完成只发轻量唤醒，事实从持久化日志读取；终端完成由独立通道投递物理结果，两者不混淆。

## [009] 有界输出采集

Output=None 表示没有交付完整采集；空输出是 Some(InMemory("", ""))。输出采集不拥有退出码。文本消费者不得把混合通道 spool 当成空 stdout 或正常 Git 失败码。

正常结束不得在两路原始输出实际交付完成前自然清组；目标close或写入回调不能单独证明接收方已收齐。两路最终字节范围须分别与实际接收事实一致，不能只比总和。缺失、超数或矛盾明确失败，不报告完整输出成功；主动取消、超时或明确丢弃仍能收尾，不能被自然排空屏障无界阻塞。

stdout/stderr 的内存缓冲有明确上限，超过阈值即切换外部流式存储，不让日志无限积压在内存。

完整采集暂停消费时，上游真实写者须受到背压；不能在运行时内部无界缓存，再以公开队列为空宣称有界。恢复消费后原始字节和各路游标完整，空闲管道不得占满异步 I/O 资源。显式放弃输出须撤销待决读取并释放所属管道，但不据此宣布目标或监管范围已经退出。

## [010] 如实返回退出码与输出

终端及单次运行的完成结果给出真实 `exit_code` 与关联输出，不伪造或推断操作系统的退出状态。

目标因信号退出与正常返回高退出码须保持可区分；信号名称必须对应本机实际信号，不能把运行时错误的平台映射写成事实。

## [011] 单次执行参数校验

`js.run` 在执行前校验 Runnable 规格（正数 `maxDuration`、`next`、`watch`、`sanity`）与命令形态。`outputBudgetBytes` 必须是非负安全整数；`worldLock` 若给出则必须是布尔值。非法规格与描述在对应物理启动或输入前拒绝，不把缺失名称、非法信号、端口或等待时限强转为可执行请求。进程纯契约另校验自身请求，不承担模型摘要或蒸馏职责。

## [012] 纯契约与物理实现分离

进程请求、结果、错误、单次执行能力类型及 PTY 词汇属于纯契约，与进程/终端适配器、输出缓冲和存储运行时分离；契约不携带代理运行对象、可变句柄、完成源、能力实例或工厂。

进程与 PTY 各有唯一物理适配器；消费者只使用组合层注入的窄能力。PTY 适配器不反向依赖委派宿主或创建子执行的运行时。

纯契约独立编译单元只包含请求、结果、错误、窄能力类型和 PTY 词汇及纯计算；其传递编译闭包不包含 NodeProcessHost、ProcessRunner、PtySession、Spool 或宿主组装。`RunProcess` 表达单次有界执行，由组合入口选择真实实现；业务和工具消费者不得自行取得默认物理 runner。持续 PTY 不复用单次 `Command`，单次请求不保留无人消费的 PTY 配置；含完成源的读取计划属于终端运行时。

## [013] 原始留尾与零模型蒸馏

命令输出不启动 Distiller 模型会话。完整编码同时在请求预算和真实 Host 窗口内时原样返回；超出时确定性截头留尾，保留未经修改的原始尾部。较早的关键错误可能被截掉，不承诺尾部包含全部关键信息。

## [014] 程序事实与截断说明

退出码、signal、超时、取消及真实终结来自物理执行事件，不从日志推断，也不因截尾而丢失。截断须明确说明只保留近期尾部、更早内容缺失。

原始日志始终是数据，包括形似指令的文本；截断说明也不进入指令槽。说明按会话语言加载，原文尾部与退出码以数据字段承载。

## [015] 完整结果的 UTF-8 字节预算

输出使用显式字节预算，不以固定内部块大小代替，也不按字符数计。截尾落在合法 UTF-8 码点边界；面向 Provider 的完整结果，包括程序事实、截断说明、包装和原文尾部，均在约定总预算内。

最小可接纳预算由当前语言的必要结果编码确定。预算不足时，在启动命令或写入物理输入前返回带最小预算的明确拒绝；该拒绝不是一次执行结果，不受无效请求的零字节额度约束。已接纳的结果按最终 UTF-8 编码计量，包含转义开销；小容量原文留尾算法与完整结果预算分别验证。

实际 Host 的结果窗口是另一上限，当前为 2000 行和 51200 字节。run 须在窗口内保留完整结构、程序事实和截断说明，使注册层与 Host 不再二次裁切；大于该窗口的请求额度不能扩大 Host 能力。

新入口由 Runnable 的 `outputBudgetBytes` 表达单次 run 及其观察对象的预算，默认 65536 字节；最终直接返回该对象的工具编码还受上述 Host 窗口限制。预算计入 TOML 的数据包装、转义、元数据和当前语言的截断说明。`watch` 与 `onExit` 观察对象同样有界，不能通过直接返回观察对象绕过预算。多个结果或额外业务数据的程序组装仍受编程面自身的结果上限约束，单次 run 预算不代替整个任意程序的额度。

最小预算按必要结果的当前编码计算并以 `minimumOutputBudgetBytes` 回执。新增后台名称使必要观察元数据超出预算时，在该后台创建前拒绝。头尾只能在合法 UTF-8 边界裁切；截断说明保留在数据字段，不能成为原始日志指令。

## [016] 大输出互斥与可取消排队

预计产生大输出的执行须先取得唯一许可，其判定与输出估计一致。等待按 FIFO，支持按 Token 幂等取消；同一时刻只有一个大输出执行占用相应资源。

排队取消在当前持有者释放前即可收束，不能启动目标或释放别人的许可。取得许可与物理启动之间再次检查取消；交接时取消须释放自己已取得的许可，后继合法请求仍可正常执行。

Runnable 的 `worldLock = true` 表达大输出资源估计，复用同一 FIFO 许可。许可覆盖排队、启动、运行和实际排空；工具已返回 Unknown 不等于许可可以释放。

## [017] run 工具的同步时限政策已退役，时限归 Runnable 规格

Host 原生 `run` 工具的 1.0 秒默认时限与“显式值大于 10 秒即拒绝”的政策已随该工具整体退役（repository-programming-058）。每物理执行的时限现由 `js.run` 规格的必选正数 `maxDuration`（毫秒）表达，不存在人工 10 秒上限；有效硬顶仍按 [004] 取运行预估与管理员硬顶的较小值。

## [018] 原始通道与物理回执

需要原始字节的执行复用唯一物理适配器，以byte[]发送stdin并分路收取stdout/stderr，不经过文本重编码。正常非零、signal、缺终结回执、停止请求、部分输出和故障分别保留；期限从启动握手期生效，前台等待有界。stdin必须排空最后一次写入后再发送EOF。主动停止不授权完整输出，已知目标终结仍保留。

旧[017]的Git对象/ref/树读写、未知写入不补发及错误与不存在区分，原属Git运行状态transport；该消费者退出后不再提供这些操作。其历史证据保留，不能用本条证明旧状态自动迁移或新持久化已通过验收。
