# distribution — WHAT

## [001] 单一交付物

安装产物同时包含生产编译代码 `dist/**` 和全部运行时语义资源 `resources/**`，作为自足的单一 npm 归档交付，不拆分代码与资源。

## [002] 资源定位

资源路径以执行模块自身的绝对位置（`import.meta.url`）上溯包根目录，再按固定相对路径解析。不依赖调用方的当前工作目录（CWD），不探测候选路径，也不回退至开发工作区源码。

## [003] 生产入口与必需根文件

package.json 的 `main` 与 `exports["."]` 均指向产物内实际存在的 `./dist/OpenCode/Plugin/Plugin.js`。package.json 是归档中的必需根文件：缺失时发布校验立即失败，严禁通过校验器放行。

## [004] 内容白名单与归档成员边界

打包构建与发布校验时，归档成员严格限制在以下三类，此外一律拒绝进入产物：

1. **生产内容（Payload）**：package.json 的 `files` 字段声明的前缀，即 `dist/**` 与 `resources/**`；
2. **包根元数据**：必需根文件 `package.json`（见 [003]），以及允许的可选根文件 `README.md` 与 `LICENSE`（仅在来源树存在时携带）；
3. **显式打包依赖**：`bundleDependencies` 中声明的依赖目录（当前为 `node_modules/wanxiangli/**`）。

除上述三类文件外，任何其他根目录文件（如 `CHANGELOG.md`、`.npmignore`）及非生产路径（`src/`、`tests/`、`scripts/`、`requirements/`、未声明依赖的 `node_modules/`、日志文件等）一律被打包校验器拦截拒绝。校验器严格执行该边界，不自行增设非标豁免。

## [005] 同一份 Production Bytes

`dist` 是唯一生产编译产物。发布打包与日常测试消费相同的增量编译结果；测试直接消费这些编译产物，发布流程直接将同一份产物打包为 tarball，不在打包阶段重复编译或额外复制资源。

## [006] 资源读取与缺失

语义资源读取和 I/O 统一归资源基础设施处理。当请求的资源不存在时，立即报错中断，严禁使用内置 fallback 假数据静默降级；规则目录结构以文件系统实际内容为准，不依赖额外的 catalog 注册索引。

## [007] 发布包完整性检验

发布前执行 `scripts/verify-package.mjs`，包含真实的 `npm pack`、解包以及外部消费者导入测试。校验器严格验证归档成员仅限 [004] 规定的三类文件，校验必需根文件与内容摘要一致性，并在隔离目录下验证脱离仓库依赖时插件可正常加载。

## [008] 资源闭合

所有声明运行时语义资源的模块，其所需的资源目录与多语言文件必须完整包含于发布产物中，确保在纯净安装环境下资源齐全可用。

## [009] 归档校验

解析 tarball 归档流时，严格校验每个成员的路径结构与完整性。路径必须为包根内的安全相对路径，拒绝绝对路径、路径穿越（`..`）及符号链接等非普通文件；`node_modules/**` 仅允许 package.json 中明确声明的 bundle 依赖。

## [011] 独立生命周期依赖的可复现交付

`wanxiangshu` 经 `file:wanxiangli` 依赖 Git submodule 提供的源码，仓库内不跟踪任何 `*.tgz` 归档。源码检出后初始化 submodule，`npm ci` 将 `node_modules/wanxiangli` 链接至源码目录；打包时将其作为 bundled dependency 实体化打入发布归档，确保安装产物能独立加载生命周期逻辑。

## [010] 活跃注册一致

产物中的代码与资源必须与现行活跃角色保持一致，不残留已废止角色的注册代码或死资源。现行工具（如 `todowrite-for-engineer`、`todowrite-for-devops`、`todowrite-for-bookkeeper`）在编译代码与资源清单中保持一致，无孤立注册。

## [012] 语言完整性为发行检查，不进入每次读取

运行时仅加载指定语言文件并进行模板替换，缺失时直接报错，不隐式跨语言回退。全量语言文件的存在性与多语言占位符对齐由发行检查（`scripts/checks/language-parity-gate.mjs`）与分发测试负责，确保在发布前暴露多语言缺项。
