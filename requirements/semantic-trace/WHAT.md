# semantic-trace — WHAT

## [001] XTrace 是 X 的唯一 append-only 原始语义历史

- **记什么**：XTrace 是工作会话唯一的原始语义历史，只能追加。Opening 记录会话初始承诺与交付目标，仅捕获一次且不覆盖；Parts 按游标严格单调追加实际交互部件；每个已完成的 ProviderRun 至多捕获一个绑定确定前沿的 Terminal。
- **怎么定位**：通过会话内单调游标与固定前沿精确切片。相同输入重放幂等，冲突输出直接拒绝。
- **不做什么特权**：XTrace 仅记录原始发生事实，不赋予业务进度、恢复资格或任何特权状态；不绕过权限机制直接触发动作。

## [002] typed capture 边界

- **记什么**：捕获范围严格限于用户任务与续接 prompt、助手正文、推理思路、工具调用与返回结果及必要省略标记；不记录 UI 状态、用量、成本、时间、本地目录或传输层元数据。
- **怎么定位**：幂等与定位凭据使用物理部件、消息与运行身份，不依赖数组下标。`ProviderRetryAttempt` 按 Host 的 typed origin 识别，正文不进入 XTrace 或 prefix digest。
- **不做什么特权**：历史插入必须基于持久化日志，普通 Host 消息身份须全部存在、非空且互异。资格查询与捕获复用 trace 所有者的纯函数裁决，外部调用方无特权改写判断或跳过校验。

## [003] cursor 严格单调、独立于 Host 坐标

- **记什么与怎么定位**：游标独立于 Host 数组下标与轮次计数，在会话生命周期内严格递增；重复或回退的追加一律拒绝。同一会话内的并发捕获必须在分配游标前完成串行化，严禁先分配冲突游标再拒绝一方。
- **不做什么特权**：游标仅表达物理追加顺序，不授予业务进度或恢复特权；Host 端的上下文压缩（compaction）与重锚不得重置已有游标或覆盖既有历史。

## [004] provenance 按 provider run 分段

- **记什么**：溯源信息按 ProviderRun 分段记录，必须包含具体运行标识，不得仅记录模型名。
- **怎么定位**：重锚后启用新的 generation，重编号的 Host 轮次不得与既有历史身份碰撞。
- **不做什么特权**：后续运行无特权修改或覆盖既有 run 分段中的溯源信息。

## [005] semantic parts 与 transport/wire identity 分离

- **记什么**：溯源身份保留在内部数据结构中，不进入面向模型的语义渲染文本。同一语义内容在不同重放环境下渲染出完全相同的文本，不掺杂内部 call_id 或传输层跟踪标识。
- **怎么定位**：投影状态、游标与区间由 trace 所有者严格封装。
- **不做什么特权**：跨所有者只提供复制的纯语义部件、Opening/Terminal 记录及精确查询，不公开内部游标或追加引用，严禁任何特权通道越权读取或篡改内部状态。

## [006] 稳定 frontier / range / cutoff

- **怎么定位**：历史按半开区间 `[start, end)` 精确切片；工作记录的持久覆盖游标允许落在半轮。审查前沿必须由完整 Host 快照与持久化 XTrace 收敛确定，禁止使用未完成的传输切片。按 stable Host identity 定位时，请求集合须全部且恰好出现并构成单一连续区间；缺失、插入额外身份或游标缺口均判定为无匹配记录。
- **不做什么特权**：游标创建、比较、覆盖与区间包含运算由 trace 所有者统一计算，外部消费者不得自定义规则进行特权覆盖。

## [007] XTrace 是语义投影、terminal 与案例来源的单一 source

- **记什么**：Case sourceTrace 与 Terminal 均从 XTrace 派生。规范投影（canonical projection）与其有界切片由 trace 所有者统一物化，不设第二套冲突解析逻辑。
- **怎么定位**：历史截断依据编程面 `view` 声明进行精确物化与截取。
- **不做什么特权**：历史截断不设特权覆盖规则。临时呈现与辅助注入不作为持久 prefix coverage 的依据。捕获返回 typed receipt/error，终结返回 typed completion 记录；装配层只安排执行次序，无权根据内部推测绕过正式事实。

## [008] 未发生材料永不写成历史

- **记什么**：XTrace 只追加真实发生并已确认的 Opening、Part 与 Terminal。
- **不做什么特权**：未确认的投机候选、临时状态和失败探测所尝试的修改严禁作为已发生事实写入历史，任何分支机制无特权预先落盘虚构事实。
- 【程序待改】投机候选拒绝与失败探测回退对持久 XTrace 的防护目前仅有占位测试，需补全针对真实候选与探测反例的端到端校验。

## [009] Host compaction 不得删除 XTrace

- **记什么与怎么定位**：Host compaction 与上下文重锚不得删除、清空或覆盖 XTrace 历史记录。重锚仅更新 prefix epoch，已有的 Parts 与 Opening 完整保留，不另设覆盖游标。
- **不做什么特权**：Host 端的压缩逻辑无特权消除或精简底层原始语义事实。

## [010] Opening 在 trace 内 preserved

- **记什么**：OpeningMaterial 精确对应会话起始至初始边界的 XTrace 区间，完整保留用户的根本承诺与初始交付目标，不作为普通工具材料滤除。
- **怎么定位**：相同材料重放幂等，发生冲突的改写一律拒绝。
- **不做什么特权**：后续对话、系统提示或重试逻辑无特权修改或替换已锁定的 Opening 内容。

## [011] Fission keyed convergence 与多 Present 轨迹归并

- **记什么与怎么定位**：并行分流（Engineer Fission）的各 lane 产生携带键值（keyed）的溯源部件，按确定性规则汇聚，保留归属与因果关系，不按网络或回调的偶然到达顺序拼接。整项工作最终形成统一的终结前沿，供 Casebook 一次性消费。
- **不做什么特权**：各并行分支地位平等，无特权抢占或交叉覆盖，汇聚结果严格由因果键决定。
- 【程序待改】多 lane 汇聚的确定性归并与终结前沿消费接线尚待在生命周期中补全正式用例。

## [012] 独立 Invocation 范围与 Resume 边界

- **怎么定位**：同一物理会话的每次 invocation 具有明确且隔离的 `[InvocationStartCursor..InvocationEndCursor)` 区间。Casebook 仅按该区间取材，不得跨越 resume 边界混合不同阶段的独立工作。
- **不做什么特权**：返回载荷不为此区间另行物化特权副本。
- 【程序待改】跨 Resume 边界的独立 InvocationStartCursor/EndCursor 范围隔离待接入 Casebook 实际调用。

## [013] 交付见证是可重放的语义事实

- **记什么**：交付见证（`TaskDeliveryCommitted`）是「工作已提交」这一已发生事实的可重放记录，不充当自动授权凭据，亦非事后叙述。它由 (session, providerRun, toolCallId) 三元组与完整围栏（任务、逻辑运行、任期、本次调用）共同标识，并连同交付正文、view 声明与物化后的 view 一并留存。
- **怎么定位**：围栏任一字段不同即构成另一条独立事实记录；同一三元组重放幂等，若材料冲突则直接拒绝。
- **不做什么特权**：该事实必须且只能由真实的交付工具调用提交产生；助手散文、view 声明文本与 provider 自然停机仅为伴随材料，本身不构成交付。未包含合法交付事实的终态一律判定为未交付，无权冒充完成，严禁由事后叙述补造。
