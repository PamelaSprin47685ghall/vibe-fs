# time-capability 测试范围

WHAT 保留八条稳定规则；具体工程和测试设施在这里说明，不把当前源码布局写成产品语义。

- 001/005 使用实际虚拟时钟和纯 Deadline，观察实例隔离及同一时间值在不同显式时刻的判断。它们不单独证明所有业务状态转移都遵守时间权限。
- 002 验证当前时刻加预算、精确截止点、等价时区表示、巨大预算和分段等待。2³¹−1 毫秒是当前物理定时器边界的回归值，不是业务统一超时。
- 003 用实际虚拟定时器做截止前/到期、逆序登记、取消、清理、重复推进和多实例隔离。物理 capability 的构造不能推进虚拟时间。事件循环排空只用于观察已完成的 Promise，不用真实睡眠代替业务时间。
- 004 使用实际源码扫描器及同一检查器的正反输入，覆盖全树与精确文件例外。有限 token 扫描不能保证识别所有等价写法；例外文件仍须逐项核对实际物理责任。
- 006 实际等待到期，只得到 WaitTimedOut 并释放活动登记。信号先到、陈旧信号等相邻证明由 causal-wait 005 承接。
- 007 保留真正的会话起点投影和双语 elapsed 渲染。旧 createSessionStartLedger 只是 Surface 内的 Dictionary，未写日志；旧 composeWithElapsed 也只拼接字符串。它们不再冒充首次 prompt、持久化或重启证明，真实链为 TODO。
- 008 读取实际声明工程，验证三类纯契约与适配器、虚拟实现、表示边界分离，以及传递依赖不反向进入实现；用同一断言拒绝植入的反向引用。工程标识只是定位当前所有者，不再锁死所有消费者清单。真实负向编译与 mandatory 注入仍待证，不调用 FCS census。

原 002 中进程时限/预算回归归回 process-execution 004/005/009；普通 Deadline 不拥有一小时默认运行政策或输出容量。APPLIES-TO 清掉不存在的旧测试路径。
