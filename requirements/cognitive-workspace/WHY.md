# cognitive-workspace — WHY

## 领域动力与核心张力

模型的思考天然是非线性的：假设、备选方案、依赖、开放问题、证据关系在调查过程中同时存在，而语言输出只能是线性序列。若不提供一块可持久编辑的中间结构，模型就被迫把聊天记录同时当作记忆和数据结构——每生成一段话就产生一次过早承诺，之后改结构的成本随对话变长而单调上升。

与此并存的第二个张力是：进度声明（还有什么没做）与工作判断（我现在认为结构是什么样）本来就是两件事。把它们塞进同一个私有账本协议，模型就要在「记账规矩」上消耗推理预算，而真正需要判断的结构反而没有地方安放。

`cognitive-workspace` 的核心不变量：

- **单一认知主权**：一个物理 session 一块画板，一次 `assume(update, todos)` 同时钉住结构与声明清单；系统管理的当前画板呈现最多一份。
- **画板即世界**：`update` 是任意 JSON→JSON 变换，没有预定义 schema，没有 CRUD 方言；语义解释由模型负责，工具只负责持久化与表示。
- **声明只是单向投影**：todos 是给宿主 UI 的兼容清单，不反向恢复画板，不构成质量或完成证明。
- **阶段是事实**：阶段边界由 canonical semantic turn 决定，不是 provider 数组下标；冷边界由已提交事实驱动。
- **诚实失败**：jq 失败、形态错误、超大画板都在副作用前被拒绝；已提交的语义状态不回滚。

## 不做什么

- 不判定任务是否完成，不授予角色权限，不推断执行资源是否存活。
- 不做容量预测，不按 token 数量触发任何认知决策。
- 不用 Host UI 反推 canonical 画板，不用 todos 猜测质量结论。
