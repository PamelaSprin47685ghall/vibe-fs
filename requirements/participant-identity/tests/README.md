# participant-identity 测试说明

规则以本包 WHAT 为准。本目录中的表示检查、静态检查、生产状态转换与插件场景提供不同范围的证据，不能相互替代。

- 001 验证目录解析、完整身份恢复、独立字段冲突拒绝及 SessionId 缓存扫描反例。目录的固定列表不证明整个运行期身份不变。
- 002 的持久 fold 用例实际读取每次失败记录之后的 IdentitySeed、完整身份和 exact run/root；它证明失败折叠不改身份，不证明真实 provider 的全部重试调度。其余用例检查原子表示和现有边界扫描器，扫描器对具体文件/词形的依赖尚需继续审阅。
- 003 检查 Persona 和版本拒绝；不单独证明磁盘失败时 root 与身份均不安装。
- 004/005 检查真实派生消费者与 prompt 投影；相同输入的两次投影不能替代真实执行绑定切换的完整验证。
- 007 检查 Bookkeeper 私有身份表示；内部角色、Predictor 和公开调度的完整隔离需先消除规范歧义。
- 008 检查精确 owner/run/root、继承证据与历史往返。部分历史用例同时涉及其他所有者，本轮未全面迁移。
- 009 包含真实插件同容器身份替换、重启与实例隔离，以及生产 fold 的关闭边界场景。
- 010 区分新建身份与历史解码。新反例覆盖 owner 派生旧名字被自动赋成 Engineer，以及伪造继承证据进入 authority；历史 Inspector 仍可按原角色解码且无写权。
- 011 检查当前和历史角色的持久标签，不依赖会话关联等无关前置条件。

当前待决与证据缺口见 GAP-067/068，新基线验证范围见[本批记录](../../../proposals/archive/2026-10-03/35模块PR施工记录-2026-09-28.md)。特别是共享解码入口是否允许历史身份进入全部活跃路径，不能由 010 的两个回归反例推断为已经全面关闭。

节点验证先运行仓库构建，再将本包及受影响的 interaction-authority、dispatch-protocol、session-ontology、managed-session-lifecycle 和 requirement-system 编号测试交给 verification-system 的正式入口。以施工记录中的实际范围和结果为准。
