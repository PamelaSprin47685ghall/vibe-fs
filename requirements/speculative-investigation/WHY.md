# speculative-investigation — WHY

## 不可替代的存在理由

主模型在动手之前，常常要先做一批机械的只读调查：读文件、搜符号、扫路径。这些事不难，却要一轮轮等 provider 返回，把主模型的注意力占满，把时间拖长。

早先的做法是让系统替主模型猜：估计收益、比较成本、积累样本，再决定要不要偷偷先跑一遍。问题在于猜测永远没有实据——系统既不知道主模型已经掌握了什么，也不知道它接下来想验什么，只能拿统计画像代替真实判断，还要额外养护预测器、对照组与一道道闸门。猜错的代价不只是浪费，更是把"该不该做、做几轮"这个最该由主模型决定的问题，悄悄转移给了一套它看不见的机器。

新语义只做一件说得清的事：**把决定权还给主模型，让它在每次工具调用上显式签字**。主模型最清楚自己掌握了什么、怀疑什么、下一步要核对哪里；它给出的整数，就是授权自己的同伴在这批工具跑完后，继续做至多这么多轮只读调查。系统不猜概率，只执行这个已经说出口的授权。

## 为什么预算是主模型给的整数，宿主只执行 max

轮数该多少，取决于主模型此刻的意图，而意图只存在于主模型自己的上下文里。让宿主推算，回来的必然是统计、阈值和两轮档位这类说不清的中间层。整数授权把判断留在最了解局面的人手里，系统只余下机械执行。

同一响应里多个工具调用各填一个整数时，取最大值：任何一个调用说"查 5 轮"，就是一次明确的意愿；0 只表示"这里不用"，不是对整批的否决。取 max 简单、确定、可审计，不要求各调用一致，也不把它们求和、或归咎于最后返回的那个。宿主只执行 max，不做任何经济判断——这是委托与投机的分界。

## 为什么同伴共享同一身份、只读、可以提前结束

同伴不是另雇来的便宜人手，是同一位当事人在此刻换了一副执行形态：participant、Role、Persona 与语言都不动，动的只是执行用途、模型池、可见工具与短期控制权。身份不变，说过的话、担的责才连得起来；审计里的因果链才不会裂成两个人。

只读让授权的边界可以证明：白名单只有 read/glob/grep，schema 与执行门禁同源，写、跑命令、发包一律 fail closed。授权能做什么，契约里写得死，出事后查得到。

可以提前结束，因为信息够了就该交还；凑满预算没有意义，回传一堆没人看的交换只是浪费。不回传推理总结、只回传真实工具调用与结果，主模型才能凭自己看见的表现评价同伴——这既是诚实的边界，也是信任唯一的来源。

## 为什么协作是逐渐了解、建立信任

信任不可能靠系统代管。宿主不建信任分、不自动增减预算，那只会重演一遍"机器替模型判断"的老路。信任来自对话里可见的真实交换：同伴在某类调查里做得好，下次就多托付些；在不擅长的状况显得别扭，就少用或不用。

拿不准时，"距离第一次 edit 还有几步"是一块诚实的起点——它把模糊的直觉落成一个可说的数，供主模型参考和修正。但起点只是起点：它不是最优策略，不替代判断，更不要求最终一定 edit。填 0 收回判断权，同样是正常选择。

## 为什么短记只随原始调用自然可见

`self_note` 是主模型给自己留的一句话，挂在原始调用里。同伴要看见它，既有的一条路已经够了：原始调用记录进冻结镜像，ID 重定位后自然出现在同伴的对话里。不必再搬一次。

另造提示通道的害处是双重的：它制造第二真相源——同一句话两处存放，迟早对不上；它还把"线索"偷偷升级成"指令"——从 system prompt 出现的话，谁还敢不理会？短记只是自省线索，不是事实，不是权限。被常规压缩掉也是可接受的代价：它是便利，不是运行正确性所必需的东西。

## 为什么删除字节上限，保留完整性

大小从来不是只读调查价值的度量。一次完整的大交换往往是同伴真的干了好活；用小前缀和"太大归零"把它切碎，只会把真实证据毁掉，还要为毁尸灭迹再养一套说不清的规则。

要保留的是另一样东西：digest、byteLength 与 payload_refs。它们证明的是"这就是实际发生过的交换"——完整、未被调包、可重放——服务的是完整性、存储与观测，不是给调查估价。工具原有的截断与主模型原有的压缩本来就管着上下文大小，Delegate 不必、也不该再插一手。

## 为什么旧历史只在离线迁移中接纳

只读委托的语义是"主模型签过字"：一条授权的成立，以工具调用上那个整数为依据。旧协议的历史里没有这个签字。若迁移就地补出 `DelegationRequested`，等于宣称主模型做过它从未做过的授权，此后的重放与审计都在引用一句伪造的话——授权语义的诚实性一旦污染，Requested/Bound/Prepared 的先后就再也说不清。

因此旧历史只有一条接纳路径：显式、一次性、离线的迁移（speculative-investigation-015）。运行时永不静默双解析——两套解码在同一进程里并行，没人说得清读到的是哪一套语义；失败还会伪装成"另一套规则刚好不适用"。

反证条件：若将来出现一种机制，能在不声称"主模型签过字"的前提下让旧授权继续有效（例如显式归档、计数归零且永不进入新生命周期），那才是重开接纳路径讨论的信号；在那之前，补一个 Requested 是伪造，不是兼容。

## 核心不变量

1. **显式授权**：没有主模型填写的整数，就没有只读调查；系统不猜概率、不设经济门槛。
2. **配置即启用**：Predictor 模型配置是唯一依据；未配置即无功能基线，预算 0 不等于未配置。
3. **同身份只读**：同伴共享 owner 身份与语言，只碰 read/glob/grep，不能嵌套委托。
4. **一次性授权**：一次授权只被一个执行消费一次；Requested/Bound/Prepared 先落盘，后外发；exact target 的真实消费才配 Promotion。授权身份同理必须内容派生：DecisionId 由映射冻结那一刻的内容确定性决定，而不是按工具调用完成的先后或未来的请求安排生成——同一个授权不能在不同执行轨迹下长出不同身份，否则断点恢复、重试与审计无从对齐；七态生命周期用显式联合类型而非布尔开关，也是为了让"请求过但未绑定"这类真实而互不相容的状态在类型上可辨，不留到运行时互相猜。反证条件：若同一冻结内容必须对应多个并行授权身份，内容派生的前提即被推翻，须先重开授权的身份条款。
5. **只回传事实**：同伴的推理与总结不回流，主模型只依据真实工具结果判断与信任。
6. **机制诚实**：字节大小不参与决策，历史不被涂改，说话的是同伴不是折扣模型。

## 违背边界的破坏形态 (RED)

- **暗箱启动**：宿主用统计画像替主模型决定是否调查、调查几轮。
- **越权执行**：同伴写文件、跑命令、发包，或借第二通道反复委托。
- **重复消费**：同一授权因重试或恢复拿到第二份预算，或断点之后自动补跑。
- **虚置消费**：没有 exact target 的真实输出就 Promotion，把未发生的消费写进历史。
- **通道走私**：短记被搬进 system prompt 或新 hint 事件，线索升格成指令。
- **以大小论价值**：给委托加专属字节上限，把完整交换切碎或整体丢弃。
- **双启用依据**：独立开关、环境变量或消融选项能否决或替代 Predictor 配置。
