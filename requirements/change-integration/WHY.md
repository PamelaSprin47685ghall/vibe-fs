# change-integration — WHY

独立道路可以并行成熟，共享分支却只有一个当前事实。发布需要同时回答两个问题：成果是否达到质量要求，以及它此刻是否仍适用于目标分支。模型评估不能替代 Git 的冲突、快进和当前 head 检查；目标或工作区变化后，旧证据也就失去了授权当前成果的依据。

只锁住共享 ref 的最后一次复核和推进，才能让长调查、评估、rebase 与修复继续并行。持久记录候选与发布认领，再结合外部 head 重证结果，使进程中断后的恢复既不漏记已经完成的发布，也不重复执行尚不确定的动作。

同一道路的工作树和任务身份保持连续，承担评审责任的任次可以轮换。这样冲突不会丢掉既有工作，也不会通过复活旧任次绕过独立评估。多路汇聚创造了新的验证对象，最终结果需要自己的证据。

Clean Gate 保护用户未提交的工作，horizon 则让使用者面对工作结果与未决后果，而无需承担内部发布协调。验证期间的输入一致性由 verification-system 管理，本包负责变化发生后证据和发布资格的失效。
