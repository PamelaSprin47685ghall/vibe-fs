# 演算 — Meditator 类型论基础（M-Calculus）

设计方法：规则先行，F# 是规则的语法化。每个 dsl/*.fs 文件头注释标注它语法化的规则编号。
类型即七巧板拼接口：方法 = 拼板，签名 = 边缘形状，组合子 = 嵌合结构；两块板能否咬合由规则前提决定，不由目录决定。

## 0. 语法范畴（sorts）

```text
c   Claim       命题（scoped proposition）
w   Warrant     证据项（proof term）
P   Proposal    候选（未检查项）
A   Accepted    已检查项
V   Validated   经确定性复核的项（组合子出口）
S   Ledger      上下文（认识账本）
o   Obligation  义务（派生判断）
G   Grade       证据强度向量（乘积偏序）
K   Credit      资源（探索额度）
E   Event       账本的作用量
Env Envelope    事件信封（EventId + 版本 + 负载 + 负载 digest）
eid EventId     事件稳定唯一身份
κ   Authority   验证权柄（EvaluatorAuthority；唯一能签发 witness 与 c! 项的令牌）
Dec ExitDecision 出口决策（终止的完整形态）
M   Meditation  计算（函数，非 AST）
```

## 1. 判断形式

```text
S ⊢ c prop          c 是 S 中的良形命题（含 scope）
S ⊢ w : c[σ]        w 是 c 的极性 σ ∈ {+,−} 证据
S ⊢ P : c?          P 是 c 的候选
S ⊢ A : c!          A 是 c 的已检查证据
S ⊢ o oblig         o 是 S 派生的未完成义务
⊢ S wf              S 是良形账本
S ⊢ v(c) ∈ {0,1}²   极性派生（纯函数）
S; K ⊢ M ⇓ S′; K′   big-step：以资源 K 在 S 上执行 M 得 S′ 与 K′
S ⊢ κ auth          κ 是当前装配持有的验证权柄（不能凭空铸造，只能具名持有）
```

## 2. 结构规则（上下文的行为）

- **S1 weakening**：S ⊆ S′（append-only 扩张）且 S ⊢ J 蕴含 S′ ⊢ J。追加不失效旧判断。
- **S2 事件幂等身份**：`EventId ≡ digest(canonical(payload), schemaVersion, policyVersion, reducerVersion)`——由内容派生，禁止 GUID、进程 hash、当前时间。同 EventId 同 bytes 的重复 append 是 `AlreadyCommitted`（幂等重放合法）；同 EventId 异 bytes 是 `Conflict`（S2 违规，非法状态）。fold 不替 journal 兜底，但 fold 内同 key 异 digest 报 `DuplicateEvent` 错误。
- **S3 无 exchange**：事件顺序是 stream sequence 全序，不可交换；fold 不天然幂等。

## 3. 形成规则

```text
statement : string    scope : Scope    role : Role    src : ProposalSource
──────────────────────────────────────────────────────────────────── (F1)
S ⊢ (statement, scope, role, src) prop      ClaimId ≡ digest(canonical(statement, scope))
```

- F1 侧条件（Leibniz 同一性）：身份由规范化内容的 canonical bytes 决定；禁止 GUID、进程 hash、当前时间。
- F2 scope 兼容：w 参与 c 的判断当且仅当 scope(w) = scope(c)。跨 scope 推广必须经显式推导产生新 warrant。

## 4. Proposal：引入一条，消除只有两条

```text
oracle ⊢ (v, π)    π provenance 完整
────────────────────────────────── (P1 intro-?)
S ⊢ Proposal(v, π) : c?

S ⊢ κ auth    κ ⊢ P ✓ (witness ω 非空, VerifierId(ω) = κ)
────────────────────────────────────────────────────────── (P2 check)
S ⊢ accept(κ, ω, value P) : c!

verifier κ ⊢ P ✗ (reason r)
────────────────────────────── (P3 reject)
S ⊢ Rejected(r)     [不引入任何项]
```

安全性核心：**Proposal 没有第三条消除规则**。业务代码拿不到 P 的值当证据用；只有 check 能把 c? 变成 c!。
P2 的权柄条件：witness 的 `VerifierId` 由权柄 κ 派生，调用方不能书写——"trust-me" 这类伪造在类型上不可表达（`VerifierWitness.issue (EvaluatorAuthority κ) …` 是唯一构造点，`EvaluatorAuthority` 构造私有，只能具名持有 `Verifiers.inference` 等固定常量）。

## 5. Warrant 引入（五条，统一侧条件）

统一侧条件：VerifierWitnesses 非空 ∧ UltimateSourceIds 非空 ∧ scope 兼容。
Warrant 是 opaque record：唯一构造点 `Warrant.create`（检查侧条件）；外部代码无法直接写 record 字面量。
fold 对 `ContributionAccepted` 事件重验侧条件（第二道防线，不信任调用方）。

```text
(W1 Obs)    观测协议 π 确实执行，ω = observation witness
            ─────────────────────────────────────────────
            S ⊢ obs(p, π, ω) : c[σ]

(W2 Src)    来源存在 ∧ 可定位 ∧ digest 匹配，ω = source witness
            ─────────────────────────────────────────────
            S ⊢ src(s, ω) : c[σ]

(W3 Deriv)  S ⊢ wᵢ : cᵢ[σᵢ] (i=1..n)    ρ 推理规则    ρ(c⃗) = c
            ─────────────────────────────────────────────   G(deriv) ⪯ ⊓ᵢ G(wᵢ)
            S ⊢ deriv(ρ, w⃗) : c[σ]

(W4 Stip)   u 是 Authority Root 来源的用户陈述
            ─────────────────────────────────────────────
            S ⊢ stip(u) : c[+]     只证明用户设定，不证明外部现实

(W5 Elicit) 用户明确接受 credence 输入协议
            ─────────────────────────────────────────────
            S ⊢ elicit(u) : c[±]   P0 不消费于数值推断
```

OracleProposal 不出现在任何 W 规则的前提里——oracle 文本永远不是 warrant 的合法原料。

## 6. 极性演算（Belnap 信息序）

```text
v(c) = (1[W⁺(c) ≠ ∅], 1[W⁻(c) ≠ ∅]) ∈ {0,1}²
```

分量序：Unknown ⊥，Contested ⊤，SupportedOnly 与 RefutedOnly 不可比。

- POL-mono：追加事件使知识沿信息序单调：v(S) ⊑ v(S; e)。反证不删除历史 warrant，只抬升 v。
- weak/moderate/strong 是支持强度，不属于此序（与 G 也正交）。

## 7. Grade 代数（乘积 meet-semilattice）

```text
G = D × R × I × Cov × Rep
  D:   Direct > Indirect > Derivational
  R:   Confirmed > Corroborated > Tentative
  I:   Clusters(n)（provenance 依赖簇数量，§41.3）
  Cov: ClosedWorld > OpenWorld
  Rep: Replayed > NotYetReplayed
```

- G-meet：逐维取弱；meetAll = fold meet。
- G-deriv（W3 侧条件）：G(deriv) ⪯ ⊓ᵢ G(wᵢ)——推导不创造强度。
- 禁止：加权平均、单一总分、跨分量比较、把 Probabilistic 当 grade 值。

## 8. 资源片段（linear）

```text
(R1)   Σᵢ credit(childᵢ) ≤ credit(parent) − c,  c ≥ 1
(R2)   allocate 失败是非法状态（Error），不是可修输入（不 clamp）
(R3)   consume 超额（amount > Remaining）、负数分量、非正 consume → 非法状态（Error）
```

势函数 Φ(S) = Σ credit(open obligations)
每次展开 Φ 严格下降；子义务数有界 ∧ digest 幂等 ∧ attempt key 去重 ∧ sweep 不动点即停
⇒ 调度有限（良基）。

Credit 与概率质量无转换（§9.3）：不同类型，不同守恒对象。

## 9. 计算规则与事件模型

```text
(C1 β-fold)   fold S (append e) ≡ R(S, e)
(T5 确定性)   同事件 bytes ∧ 同 reducer version ∧ 同 policy version
              ⇒ 同 S′（外延等价：digest 相等）
```

oracle 非确定性由三件套冻结：Answer = F(question, oracleTranscript, evidenceSnapshot, policyVersion)。同 invocationKey 只许一个 accepted transcript——T5 的侧条件，journal 执行。

### 9.1 事件信封（Envelope）

```text
Env = { EventId          : 由负载与版本派生（S2）
        SchemaVersion    : 事件 schema 版本
        PolicyVersion    : 控制/验证策略版本
        ReducerVersion   : fold 实现版本
        Payload          : MeditationEvent
        PayloadDigest    : canonical(payload) 的摘要 }
```

- journal 只见信封的 canonical 行（NDJSON），零领域知识；编解码是 Ledger 边界的契约面。
- 重放：`Replay` 读全部行 → 版本校验（schema/policy/reducer 与当前装配不一致 → fail closed，不猜测迁移）→ fold 恢复 ledger。
- `AppendOutcome = Committed | AlreadyCommitted | Conflict | CommitUnknown`；`CommitUnknown` 走 `Reconcile` 确认，仍未知 → fail closed。

### 9.2 账本字段 ↔ 事件（每个字段必有事件可抵达；每个事件必有幂等身份）

```text
Claims            ← ClaimFramed
Warrants          ← ContributionAccepted（fold 重验 §5 统一侧条件）
Hypotheses        ← HypothesisRecorded（同 key 异 digest = DuplicateEvent）
Concepts          ← ConceptRecorded（同上）
Relations         ← RelationRecorded（同上）
Counterexamples   ← CounterexampleRecorded（同上）
Evidence          ← EvidenceObserved（同 key 异 digest = DuplicateEvent）
UnknownRegions    ← UnknownRegionUpdated（非降级：Coverage 只能沿等级序上升）
MethodEpisodes    ← EpisodeRecorded（同 key 异 digest = DuplicateEvent）
Rejections        ← OracleAnswerRejected（append，不覆盖）
ResourceUsage     ← OracleInvocationAccepted / CreditsConsumed / SweepCompleted
SearchAttempts    ← SearchAttempted（append；"连续 N 轮 NoHit"的判据输入）
Attempts          ← AttemptRecorded（进展保证，见 §11）
Stalls            ← NoProgress（连续无进展计数）
生命周期          ← MeditationRequested / MeditationCompleted / MeditationFailed
```

### 9.3 canonical codec（唯一 owner）

- 事件编码、EventId 派生、semanticDigest 共用同一个 canonical renderer（Ledger.EventCodec，长度前缀编码 `tag:len:bytes`，无分隔符歧义、无转义问题）。
- 禁止调用方注入 `encode : MeditationEvent -> string`——编码是 Ledger 边界的私有实现。
- semanticDigest 覆盖账本全部字段（含 Scope/Source/Strength/Origin/VerifierWitnesses/DependencyWarrantIds/UltimateSourceIds/Description 等），任何认识意义的差异都改变 digest。

## 10. 高阶规则（组合子 = 前提完备性）

每条规则的前提是函数参数；缺一前提则规则不可用——**词法化即前提完备性**。
组合子行使确定性复核权：witness 经权柄 κ 签发（§4 P2），组合子签名显式携带 κ。

```text
(H-relax)   κ  f: h→Mr  g: r→Ma  p: a→Mh  v: κ → h→M(witness list)
            ─────────────────────────────────────────────────────
            relax κ f g p v : h → M(Result<Validated h, h>)

(H-sample)  κ  seed count sample summarize verifyDeterministically: κ → … → M(witness list)
            ─────────────────────────────────────────────────────
            sampleThenVerify … : M(Result<Validated r, r>)
            无确定性复核函数即规则不可用

(H-exist)   κ  materials  build: m→Mo  witness: o→M(witness list)
            ─────────────────────────────────────────────────────
            construct κ m build witness : M(Result<Constructed o, o>)
            ∃-intro：无 witness 的"构造完成"无法表示

(H-simplify) κ  source reduce provePreserved auditLoss: κ → … → M(loss list)
            ─────────────────────────────────────────────────────
            simplify … : M(Result<SafelySimplified b, LossAudit>)
            auditLoss 有否决权：losses 非空即停在候选，witness 不豁免

(H-prune)   bound(b) = Some witness 才可剪；None → 保留
(H-memo)    normalize 相同 ⇒ 共享结果（子问题规范化幂等）；并发安全，同 key 同结果
(H-par)     mapBounded：并发有界；结果按输入位置排列；完成顺序不进入领域值
```

## 11. 义务派生与终止出口（meta 层，不是推理规则）

- obligations : Request × S → o list，纯函数；同 S 必同 o（§6.4）。
- 出口是 ExitDecision，不是 option：

```text
Dec = Continue
    | ContractSatisfied of ContractSatisfactionProof
    | OpenWorldReportReady of StopProof
    | TargetRefuted of RefutationProof
    | Blocked of RequiredInput list
    | Inconsistent of Contradiction list
    | Inconclusive of UnresolvedProblem list
```

- 出口顺序（顺序即语义）：
  tryProveInconsistency → tryProveTargetRefuted → tryProveFullContract → tryProveUsefulOpenWorldReport → tryProveBlocked → returnInconclusive。
- 进展保证：attempt key = (obligationId, ledgerDigest, policyVersion)。同 key 已执行（Attempts 含之）→ 不得再次调用 Oracle；义务列表须先滤除已 attempt 项。事件折叠后 digest 无变化 → 追加 NoProgress。连续无进展（Stalls ≥ N）→ 停止执行义务，只允许 OpenWorld 或 Inconclusive 出口——ContractSatisfied 在义务未解除时结构上不可证明。
- O-cov 侧条件：SearchAttempted(NoHit) 只能支撑 OpenWorld 出口，永远不能产生 VerifiedFinite certificate。
- 矛盾升级判据：仅当同一 scoped proposition 的冲突位于当前义务成功谓词路径上才走 Inconsistent；否则 Contested 照常推进（§10.1）。
- 报告是证明的渲染：CanonicalReport 与 StopProof 同源（compileCanonical 以 proof 填充），conclude 只读 canonical 一个权威来源；出口类型与 StopReason 一一对应。

## 12. 元定理（陈述；证明义务分配给测试与门禁）

|定理|陈述|证明义务|违反意味着|
|---|---|---|---|
|T1 提交权分离|任何 c! 项的推导树必含 verifier 叶；witness 的 VerifierId 由权柄 κ 派生|门禁（裸 Accepted( 出界 + 无 κ 的 Witness( 出界）+ 第 1 层行为测试|LLM 输出成为证据；"trust-me" 伪造|
|T2 权力上限|方法可构造项集 ⊂ 其返回类型|§17.2 最小反例测试（abduction_cannot_conclude 等）|Analogy 冒充 Falsification|
|T3 单调性|fold 后 v(c) 沿信息序不下降|属性测试|反证删除历史|
|T4 终止|Φ 严格下降 ∧ attempt key 去重 ⇒ seek 有限|属性测试（守恒 + 势函数 + 同 key 不重执行）|预算耗尽冒充成功；空转重复执行|
|T5 确定性|外延等价（digest）|同三件套重放测试|reducer 含时钟/随机/完成序|
|T6 重放一致性|同事件序列 + 同版本 ⇒ 同 ledger digest；幂等重放不改变 digest|崩溃注入 + 双倍重放测试|append 后 fold 结果漂移|

## 13. 非法状态 = 无推导规则（§40.2 的演算翻译）

|非法状态|演算判词|
|---|---|
|无 AnswerContract 进 SYNTHESIS|obligations 定义域不含此 S；无规则可派生|
|无资格进 NUMERIC_COMPILATION|P0 无数值规则；Credence 与 ControlScore 无转换函数|
|有未决硬义务返回 ANSWERED|conclude 的前提 ContractSatisfactionProof 不可构造|
|open-world 残余宣称穷尽|O-cov 侧条件拒绝 certificate|
|subagent 原文直接成 factor|oracle 文本不是任何 W 规则前提；P0 无 factor 范畴|
|同 key 两个 accepted transcript|S2 journal 侧条件拒绝|
|无 κ 构造 witness / c! 项|P2 权柄条件；EvaluatorAuthority 构造私有|
|同 key 已 attempt 仍调用 oracle|§11 attempt key；Attempts 过滤义务|
|NoProgress 后走 ContractSatisfied|§11 连续无进展只导向 OpenWorld / Inconclusive|
|Coverage 降级（ClosedWorld → Open）|§9.2 UnknownRegionUpdated 非降级约束|
|旧 schema/policy/reducer 版本重放|§9.1 版本校验 fail closed，不猜测迁移|
